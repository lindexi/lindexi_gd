# 渲染器与工具行为

语法以 `slideml-spec.md`（官方规范）为准。本文件记录**当前构建的实测结论**：哪些写法能直接依赖、哪些规范支持但本构建没实现、哪些写法会让整页渲染失败。

制作课件时直接采用本文件中已验证的写法。只有实际渲染与预期不符时，才针对出现异常的写法做最小复现。

## 1 工具语义

| 工具 | 要点 |
| --- | --- |
| `ListOpenCourseware` | 列出当前打开的课件和可用的目标 ID |
| `BindCoursewareTarget` | 用 `targetId` 绑定或切换本会话的课件操作区 |
| `GetCurrentCoursewareInfo` | 查看课件标题、页数和页面尺寸 |
| `GetSlideInfo` | 页面元素树 + 文本细节。用它找零散文本框、画布外残留元素、原图片资源 ID |
| `RenderSlideML` | 传入完整页面 XML，返回回填后的 XML、`warnings`、`errors`。课件须处于备课（编辑）模式 |
| `GetSlideScreenshot` | 唯一可信的最终判据。有疑问先截图，不要靠推算 |
| `Register_SlideML_Resource` | 本地图片先注册，拿返回 ID 填 `Source` |
| `ExportCoursewareMarkdown` | 导出全课件，拿到每页 `slideId`、尺寸、截图。适合批量盘点或改动前留底 |

`RenderSlideML` 的 `slideId` 语义：

- `null`／空串／纯空白 → **新建**一页。
- 有效页面 ID → **清空并复用**该页，渲染后切换到该页。
- 无效 ID → 调用失败，且**不会**新建页面。

注意：`"null"`（带引号的字面字符串）会被当成无效 ID，不是"新建"。要新建就传真正的 `null` 或空串。

`errors` 与 `warnings` 要分开读：`errors` 是真问题（如 `FontSize` 非法），`warnings` 有相当比例是估算噪音，判据见第 5 节。

## 2 可直接依赖

| 项 | 实测结论 |
| --- | --- |
| 坐标相对直接父容器 | 子元素跑位、盖住别的东西，基本都是误用了画布坐标 |
| Z 序按文档顺序 | 后写的在上层；想让底块在最下，就写在最前 |
| `TextElement` 的 `Width` | 不写＝单行不换行；写了＝在该宽度内自动换行 |
| 渐变 `<Fill><LinearGradient>` | **可用**，`Rect` 与 `Panel` 都生效，水平／垂直／对角均可；与 `Stroke` 可共存 |
| 纯色 `Fill`／`Stroke`／`StrokeThickness` | 可用 |
| `StrokeDashArray` | 可用，虚线正常 |
| `Padding` | 可用，子元素起点＝父容器原点 + Padding |
| `IsBold`、`Foreground`、`FontName`（`SimSun`／`Microsoft YaHei` 均生效） | 可用 |
| 流式布局 `Layout=Horizontal/Vertical`、`Gap`、`Margin` | 可用，规则见第 5 节 |
| `TextAlignment`（`Left`／`Center`／`Right`） | 生效，但含固定内缩偏差，见第 5 节 |
| 默认值 | 省略 `FontSize` 为 `16`；省略 `FontName` 为 `Microsoft YaHei` |
| 渲染失败不污染页面 | 报错的调用不会改掉目标页已有内容；新建页失败也不会留空页 |

## 3 规范支持但本构建未生效

这些写法**不会报错，只会静默失效**，最容易被误当成"生效了"。用之前必须截图确认。

| 项 | 实测表现 | 替代做法 |
| --- | --- | --- |
| 字号等级 `L1`~`L5` | `errors` 报「FontSize 值 "L3" 不是有效的数值」，元素回退默认 16px（`L1`/`L3`/`L5` 实测渲染高度完全相同） | **一律用绝对 px**，不要用等级 |
| `Shadow` 属性 `Shadow="0 12 24 #00000080"` | 半透明黑阴影叠在浅底上一像素都看不到，等于未应用 | 不要靠阴影分层，用底色差异 |
| `<Shadow>` 子元素 | 同上 | 同上 |
| `HorizontalAlignment` | 指定 `Width` 时无效，文字一律贴左（不写 `X` 时的行为未验证） | 用 `TextAlignment` 或直接算 `X` |
| `VerticalAlignment` | 无效，文字始终贴元素顶部 | 用 `Y` 手工居中：`Y = 容器Y + (容器高 - 行高) / 2` |
| `Span` 富文本 | **子元素顺序被反转**，且多数样式丢失：输入「A(红加粗) B C(下划线蓝) D」，渲染成「D C(无样式) B A(红加粗)」 | 拆成多个 `TextElement`，各自定位，靠 `Y` 对齐基线 |
| 不存在的图片资源 ID | 元素被**静默丢弃**，不报错、不留占位框 | 提交前核对 `Source` 都是真实 ID；缺图会表现为"那一块空白" |

## 4 会让整页渲染失败的写法

| 写法 | 现象 |
| --- | --- |
| `CornerRadius` 写 2 值（`"8,60"`）或 4 值 | 抛 `System.ArgumentNullException`「ElementSaveInfo 的 Id 不能为空」，堆栈落在 `RectElementCreator.CreateCustomRoundedRectElement`。**整页渲染失败** |
| 文本含 `▶` 等图形字符 | 抛负宽度异常（`Width` 被算成 `-4`），整页渲染失败 |
| `FontSize` 写非数值（如 `L3`） | 不崩，元素按默认 16px 渲染（见第 3 节），但 `errors` 里会留记录 |

`CornerRadius` 只写单值。**单值也无法做到直角**，见下一节。

## 5 排版硬规则

### 5.1 行高公式（避免 `ActualLineCount` 警告的唯一可靠办法）

实测：单行文本框的渲染高度严格等于 `1.32 × FontSize + 20`。

| FontSize | 渲染高度 |
| --- | --- |
| 12 | 35.84 |
| 14 | 38.48 |
| 16 | 41.12 |
| 18 | 43.76 |
| 20 | 46.40 |

所以：`Height ≥ 行数 × (1.32 × FontSize + 20)` 才不会触发警告。18px 文字塞进 `Height=40` 会被判成"仅容纳 0 行"。

两条补充：

- **文字超出 `Height` 时不会被裁剪**，仍完整绘制。警告只是提示"设定高度不够"，不是画面缺陷。
- 因此警告的真实含义是"你的 `Height` 与内容不匹配"。要么加高 `Height` 消除警告，要么确知画面无裁字后当噪音忽略。汇报时不要笼统称其为"误报"。

### 5.2 直角与圆角

| 结论 | 证据 |
| --- | --- |
| `Rect` **恒有圆角**，`CornerRadius="0"` 无效，最小圆角目测约 16px | 同尺寸 `CR=0`／不写 `CR` 渲染完全一致；`CR=1`、`CR=4` 视觉几乎无差 |
| `CornerRadius` 取值有明显量化：1／4 一档，12 明显更大，24 再大一档 | 同尺寸 140×100 四格对照 |
| **只有 `Panel` 的背景是直角** | 同为 `#E8EEF7`，`Panel` 背景四角为直角，`Rect` 为圆角 |

要做"教材式直角细线框"，用 `Panel` 承载背景／底色，**不要用 `Rect` 假装直角**。

### 5.3 `Panel` 当纯色底块的前提

- `Panel` **没有子元素**时，`Width`／`Height` 被忽略，按内部默认尺寸渲染（实测给 400×36，实际画成约 150×84，三个叠成一条竖块）。
- `Panel` **有子元素**时，尺寸正确，背景为直角。

结论：纯色底块要么给 `Panel` 至少塞一个子元素（哪怕是一个 1px 的占位 `Rect` 或一行文字），要么接受 `Rect` 的圆角。

### 5.4 对齐属性的实际精度

`TextAlignment` 生效，但基于"测量宽度"而非墨迹宽度，测量值比实际墨迹宽约 20px，导致：

- `Right`：文字末端距元素右边界约 20px，不贴边。
- `Center`：文字中心比元素中心偏左约 10px。
- `Left`：偏移很小，可视为贴边。

实践含义：**多行数值用同一个 `TextAlignment="Right"`、同字号时，彼此仍然严格对齐**（偏差恒定），做数值列是安全的；但别指望贴到边线上，需要贴边就另行补偿 `X`。

### 5.5 流式布局

- 间距 = `max(Gap, 前一个元素的 right Margin + 后一个元素的 left Margin)`，**不是相加**。实测 `Gap=8`、`Margin` 取 0／40／10，得间距 40 与 50（即 `max(8, 0+40)`、`max(8, 40+10)`）。
- 交叉轴默认 **Top** 对齐，子元素不会垂直居中，需要居中就自己写坐标或给 `Y`。
- 排列轴上写了 `X`／`Y` 的元素脱离流式、用绝对坐标、不占流位置。
- 无 Wrap。一组超过 4 个先算总宽 `n × Width + (n-1) × Gap`。
- 交叉轴上的 `Padding` 生效。
- 见过「流式布局内容高度 280 超出 Panel 高度 80」这类警告，而子元素实际只有 56 高——交叉轴测高存在放大误报，判据同 5.1。

### 5.6 `GetSlideInfo` 的已知失真

带子元素的 `Panel` 会被报成「组合」，且其 `Location` 不可信（实测报 `(80,708)`，实际渲染在 `(40,354)`）。用元素树核对坐标时，以渲染截图为准。

## 6 排错：二分定位

1. 保留 `Page` 与背景，删掉全部子元素，渲染一次。能过 → 问题在内容元素。
2. 恢复大约一半元素，渲染。报错就继续砍一半，不报错就补回另一半。
3. 锁定到单个元素后，按第 3、4 节逐条对：多值 `CornerRadius`、图形字符、非法 `FontSize`、未注册资源 ID、0 或负 `Width`。
4. 修好后**重新渲染并截图**，确认没引入新的错位。

## 7 提交前核对清单

- [ ] 没有元素互相遮挡，也没有元素跑出画布
- [ ] 每行文字完整，既没折行也没被裁掉下半截（每行 `Height` 按 `1.32 × 字号 + 20` 给）
- [ ] 同类元素对齐在同一条基准线
- [ ] 字体设置生效（截图里确实变了），标题与页眉有字体对比
- [ ] 没有用到第 3 节列出的失效能力：字号等级、`Shadow`、`HorizontalAlignment`、`VerticalAlignment`、`Span`
- [ ] 需要直角的框用的是 `Panel`（且带子元素），不是 `Rect`
- [ ] `CornerRadius` 只写单值
- [ ] 强调色只用在一到两处，铺满页面的彩色块已去掉
- [ ] 所有数值、单位、符号与底稿逐字一致
- [ ] 图片全部正常显示，`Source` 都是真实存在的 ID
- [ ] 页面没有残留上一版元素（整页替换时应已清空）

## 8 汇报口径

- 硬伤与噪音分开说：影响观感或内容的问题列前面，估算类警告注明"截图无异常"。
- 渲染失败就直说失败和报错内容，不把失败的调用描述成成功。
- 规范支持而本构建未生效的，说"当前渲染器未生效"，不要说"规范不支持"。
- 明确列出"哪些内容一字未动"，尤其是数值和物理符号。
- 主动说明删掉了什么（残留元素、背景图、装饰形状），让别人知道改了版面而不是丢了内容。
- 交付后给一句下一步建议，但不要擅自扩大改动范围。
