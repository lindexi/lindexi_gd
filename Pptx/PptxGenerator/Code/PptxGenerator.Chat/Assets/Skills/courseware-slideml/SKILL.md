# 课件 SlideML

用 SlideML 描述课件页面并写入课件。新建页面、重排版面、美化、整套风格统一、渲染排错，都属于本技能范围。

## 开工前先查什么

| 任务 | 先读 |
| --- | --- |
| 写 XML：标签、属性、坐标、流式布局、渐变、转义 | [references/slideml-spec.md](references/slideml-spec.md) |
| 渲染结果不对、警告看不懂、元素错位或消失 | [references/renderer-behavior.md](references/renderer-behavior.md) |
| 选版面骨架，要现成的栅格尺寸 | [references/layout-recipes.md](references/layout-recipes.md) |
| 定字体字号配色、用户嫌"AI 味重"、要统一风格 | [references/style-guide.md](references/style-guide.md) |
| 要看一份完整可用的整页 XML | [references/worked-example.md](references/worked-example.md) |

`slideml-spec.md` 是**官方规范**，语法与属性以它为准。另外四份是本技能的经验与审美判断。

**关键分歧**：官方规范描述了若干能力（字号等级 `L1`~`L5`、`Shadow`、`HorizontalAlignment`、`Span` 富文本），当前构建**实测不生效**。以 `renderer-behavior.md` 第 3 节为准——那里列出的能力一律别用，直到重新验证通过。

动手写 XML 前必须看过 `slideml-spec.md`；提交前必须核对 `renderer-behavior.md` 的验证清单。

## 核心工作流

首次操作课件或需要切换课件时，如果提供了操作区工具，先调用 `ListOpenCourseware`，再用返回的目标 ID 作为 `targetId` 调用 `BindCoursewareTarget`。绑定成功后再操作课件；继续处理同一份课件时，直接使用当前绑定。

1. **盘点现状**：调 `GetSlideInfo` 看目标页。记下画布尺寸、页面类型（封面／提问讨论／知识点／图示／小结）、零散文本框数量、画布外残留元素、可复用的原图片资源 ID。把原文的数值、单位、符号、题干逐字抄成底稿，后面用来核对。
2. **定风格**：用户已指定就照做；说"按你的审美"才自行决定，并在交付时说明理由；都没说时给两三个候选（见 `style-guide.md` 预设），让对方一句话就能定。风格一旦定了，整套课件沿用——单页另行花式会显得割裂。
3. **选骨架、定网格**：从 `layout-recipes.md` 挑骨架，先定左右边距、标题带高度、行高、间距，再往里填内容。同类元素对齐到同一条基准线，不要逐个"看着摆"。
4. **写整页 XML**：输出完整 `<Page>`，不是补丁，不是 XAML／HTML 片段，不加 Markdown 代码围栏。改现有页时，用户没要求动的部分原样保留。
5. **渲染**：调 `RenderSlideML`。新建页传 `slideId=null`；改现有页传已确认的页面 ID——不能因为拿不准 ID 就传 null，否则会凭空多出一页。
6. **截图核对**：调 `GetSlideScreenshot` 看真实渲染。逐项过：遮挡、折行、裁切、越界、字体是否生效、颜色是否符合预期、数值是否与底稿一致。
7. **修到对为止再汇报**：坐标错就重算；警告要分清哪些是硬伤、哪些是噪音。汇报写明改了什么、删了什么、哪些内容一字未动、哪些属于渲染器限制。

多页任务一页一页来：渲染确认当页后再动下一页，不要一次提交十几页等最后一起看。

## 硬性护栏

- **内容不改语义**：数值、单位、物理符号（`Δv`、`v₀`、`vₜ`、`m/s²`）、题干文字照抄。美化只动呈现，不动结论。
- **提问页保留提问性**：原本是讨论／讲评页的，保留"先遮挡后揭示"的余地，别把问句和答案揉成一句陈述，除非用户明确要合并。
- **不编造**：`Image` 只能用注册工具返回的或页面里已存在的资源 ID；不写 `RenderSize`、`ActualLineCount` 之类引擎回填属性；不造标签和属性。
- **整页提交**：每次给完整页面。
- **没截图不下结论**：没看到截图就说"已完成"是错的。渲染失败就如实说失败原因，别把报错的调用描述成成功。

## 设计判断速查

- 层级靠字号、字重、留白，不靠堆颜色。一页一个强调色足够。
- 同类元素对齐到同一条基准线；三行同类内容用同一套网格复制三份。
- 字体对比最像人排的：衬线标题配无衬线小字页眉、大字号数值配小字号注释。全页一个字体反而像模板。
- 装饰要克制：圆角大卡片、投影、彩色侧色条、装饰圆、标签徽章叠在一起，就是通常说的"AI 风"，一页里留一到两样即可。
- 宁可减少元素数量，也不要把字号压到 14px 以下去塞满页面。
- **字号一律用绝对 px**：当前构建不支持 `L1`~`L5`，写了会报 Error 并回退 16px。
- 想要直角用 `Panel`（需带子元素），`Rect` 永远是圆角，`CornerRadius="0"` 也消不掉。

反模式对照、色值见 `style-guide.md`。

## 常见症状与原因

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 整页 / 某块变成默认亮蓝 | 渐变子标签写错，常见是把 `<Fill>` 写成 `<Rect.Fill>`／`<Panel.Fill>`，被当未知标签忽略，元素回退主题填充 | 改成规范要求的 `<Fill><LinearGradient><Stop>`。渐变本身**是可用的**，别误判成不支持 |
| 某元素盖住别的元素 | 子元素误用了画布绝对坐标，实际应为父容器相对坐标 | 按父容器左上角重新换算 |
| 渲染报错、宽度算成负数 | 文本里含图形字符（实测 `▶`） | 去掉可疑字符二分定位，改用形状拼图标 |
| 渲染报错、`Id 不能为空` | `CornerRadius` 写了 2 值或 4 值（如 `"8,60"`），走了自定义圆角分支并崩溃 | 只写单值 |
| 文字折行或下半截被裁 | 容器宽度不够，或 `Height` 小于 `1.32 × 字号 + 20` | 加宽容器；按行高公式给足 `Height` |
| 文字超出框但没被裁 | 本构建不按 `Height` 裁剪，只是照常绘制 | 这是正常现象；把 `Height` 调到公式值即可消除警告 |
| 流式布局里元素位置诡异 | 排列轴上写了 `X`／`Y`，该元素已脱离流式布局 | 排列轴上删掉坐标；跨轴方向才用坐标 |
| `Panel` 尺寸不对、被压成一条 | `Panel` 没有子元素时会忽略 `Width`／`Height` | 给它塞至少一个子元素 |
| 文字右对齐不贴边 | `TextAlignment` 含约 20px 固定内缩；`HorizontalAlignment` 完全无效 | 接受恒定偏差做列对齐，或手算 `X` 补偿 |
| 富文本顺序错乱 | `Span` 在此构建中顺序被反转、样式丢失 | 拆成多个 `TextElement` |
| 阴影没出现 | `Shadow` 属性与 `<Shadow>` 子元素均未实现 | 放弃阴影，用底色差异分层 |
| 字号明显不对、报非法数值 | `FontSize` 写了 `L1`~`L5` | 改成绝对 px |
| 用户说"太 AI 风" | 圆角卡片 + 投影 + 多色彩条 + 装饰圆叠用 | 收敛为白底、细线分隔、灰阶 + 单强调色 |
| 某块图片位置空白 | `Source` 用了不存在的 ID，元素被静默丢弃 | 换成注册工具返回的 ID |
