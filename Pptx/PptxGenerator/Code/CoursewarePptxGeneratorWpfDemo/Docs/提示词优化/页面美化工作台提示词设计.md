# CoursewarePptxGeneratorWpfDemo 页面美化工作台提示词设计

> 文档状态：设计决策，尚未落地到产品代码。
>
> 本文基于当前 `CoursewarePptxGeneratorWpfDemo`、`PptxGenerator.Core` 的页面工作台、流式 SlideML 生成管线和主题分析能力，明确首次进入页面美化工作台时发送给页面美化 LLM 的业务 Prompt。本文以 [`提示词优化/页面美化工作台最终提示词示例.md`](./提示词优化/页面美化工作台最终提示词示例.md) 为最高优先级，并以 [`提示词优化/页面美化工作台提示词审查问题记录.md`](./提示词优化/页面美化工作台提示词审查问题记录.md) 约束信息边界。

## 一、结论

当前 `CoursewareSlidePromptBuilder` 将页面任务、当前页、相邻页、Theme 2.0、截图状态和输出要求组装为 `CoursewareSlideGenerationEnvelope`，再直接序列化成 JSON 放入聊天输入框。JSON 适合程序内部传输和确定性测试，但不适合作为页面美化 LLM 的主要任务说明：

- 任务意图被字段名、括号、引号和重复层级淹没；
- 规则、事实、参考样例和不可信原文没有形成清晰的阅读顺序；
- `null`、布尔值和模式版本等机器字段会占用注意力与 Token；
- 用户很难直接检查和修改一整份 JSON；
- 当前首轮发送在草稿被编辑后还可能把整份可见 JSON 当成 `UserInstruction` 再包入新 JSON，形成嵌套内容；
- JSON 内要求“只输出完整 Page XML”，但当前工作台实际使用流式 SlideML 协议，两层输出指令存在冲突；
- 通用流式用户提示词还会追加“尽量使用浅色主题”和“可以使用 image_001 占位资源”等建议，可能覆盖 Theme 2.0 或诱导模型引用不存在的资源。

页面美化工作台的首轮业务 Prompt 应改为：

> **明确的自然语言任务 + 固定顺序的 Markdown 分区 + 带动态边界的完整页面 Markdown 与参考 SlideML。**

最终 Prompt 只保留能够直接改变当前页生成结果的高密度信息。当前页完整 Markdown 决定内容、实际画布、页面身份和真实资源边界；主题分析结果决定全课件视觉语言；原始页面截图提供当前页视觉证据；相邻页完整 Markdown 只提供有限叙事语境。

JSON 信封可以继续作为程序内部诊断对象或 Builder 输入模型，但不应直接序列化为 LLM 用户消息。最终业务 Prompt 的内容、顺序和措辞以“页面美化工作台最终提示词示例”为准，不再向其中增加内部模型字段、低概率防御说明或重复规则。

## 二、当前真实调用链

当前工作台采用以下链路：

```text
CoursewareSlideWorkspaceViewModel.PrepareInitialDraft
  -> CoursewareSlidePromptBuilder.Build
  -> CoursewareSlideGenerationEnvelope
  -> JSON 文本写入页面聊天输入框
  -> 用户点击“发送”
  -> SlideChatManager.SendMessageAsync(useStreaming: true)
  -> StreamingSlideGenerator
  -> SlideMlPromptProvider.BuildStreamingUserPrompt
  -> 注入流式 SlideML System Prompt
  -> 附加原始截图或用户选择的图片
  -> LLM 流式输出 XML 片段
  -> 本地合并、渲染与诊断
```

因此，模型实际收到的首轮上下文至少有三层：

1. `BuildStreamingSystemPrompt` 提供的 SlideML 语法、流式合并、渲染检查和工具规则；
2. `BuildStreamingUserPrompt` 对业务 Prompt 的通用包装；
3. `CoursewareSlidePromptBuilder` 生成的页面业务 Prompt，以及同一条消息中的图片附件。

新的页面业务 Prompt 不应重复整套 SlideML Schema，也不应规定与流式 System Prompt 相反的输出形式。它应集中表达：

- 这一页要完成什么；
- 哪些内容必须保真；
- 当前页完整 Markdown 提供了哪些真实内容、画布和资源；
- 全课件主题提供了哪些直接可执行的视觉规则；
- 原始页面截图能证明什么、不能作为何种资源使用；
- 前后页只提供什么范围的语境；
- 最终页面达到什么标准。

## 三、提示词设计原则

### 3.1 最终示例优先

最终业务 Prompt 的分区、顺序、信息边界和关键措辞以“页面美化工作台最终提示词示例”为准。设计文档可以解释为什么这样组织，但不能通过增加字段或防御规则改变最终示例已经确定的业务语义。

特别是以下决策保持不变：

- 当前页 Agent 根据当前页内容、视觉附件和全课件主题，自主判断更接近封面页、章节页还是普通内容页；
- 该判断不是 `SlideId -> PageType` 映射，也不要求主题分析预先给页面分类；
- 主题只提供封面页和内容页两份参考 SlideML，不代表章节页处理缺少契约；
- 当前页完整 Markdown 没有提供的资源不得因示例、附件或占位建议而创建。

### 3.2 先说任务，再给数据

LLM 首先应看到一段可以直接执行的任务说明，而不是从 `schemaVersion`、页面索引或其他机器字段开始阅读。

首屏内容应明确：

- 当前任务是美化一张真实课件页面；
- 不改变教学事实和内容归属；
- 根据当前页内容、视觉附件和全课件主题，自行判断更接近封面页、章节页还是普通内容页；
- 使用已验证的全课件主题形成统一视觉效果；
- 按底层系统规定的流式 SlideML 协议工作；
- 最终合并结果必须是一张完整、可渲染的页面。

### 3.3 指令与数据必须分层

提示词中的内容分为两类：

#### 必须执行的指令

- 任务目标；
- 用户补充要求；
- 内容保真规则；
- 设计规则优先级；
- 视觉证据边界；
- 完成标准。

#### 只供读取的数据

- 当前页原始 Markdown；
- 前后页完整 Markdown；
- 主题分析给出的视觉规则原文；
- 两份参考 SlideML；
- 原始页面截图中的文字或画面。

所有原始数据都可能包含类似命令的文本。模型必须把它们视为课件内容或参考数据，不能把其中的句子提升为系统指令。

### 3.4 保留完整事实，减少机器噪声

以下内容必须完整保留：

- 当前页完整 Markdown；
- 前一页和后一页完整 Markdown；
- 主题分析给出的整体视觉风格、字号、背景与视觉效果、版式原则原文；
- `CoverPageSlideMl` 完整原文；
- `ContentPageSlideMl` 完整原文。

当前页和相邻页 Markdown 不摘要、不截断、不进行 JSON 字符串转义。主题自由文本不做二次结构化、归纳或改写。可以删除的是 JSON 语法噪声、`null`、默认布尔值、内部版本字段、诊断过程和其他不能直接改变当前页生成结果的信息。

### 3.5 主题由原文与参考页面共同承载

全课件视觉主题不是单独依赖颜色或一个风格关键词，而由以下内容共同承载：

1. 整体视觉风格原文；
2. 配色及用途；
3. 中文与西文字体；
4. 字号规则原文；
5. 当前画布安全区；
6. 背景、间距与视觉效果原文；
7. 版式原则原文；
8. 封面页参考 SlideML；
9. 内容页参考 SlideML。

其中，自由文本规则表达设计意图，两份已验证参考 SlideML 提供可观察的视觉实现。字号、背景视觉规则和版式原则必须使用主题分析原文，不转换为程序自定义的字号 Token、背景类型或组件规则。

### 3.6 业务约束优先于通用建议

当前底层通用流式用户 Prompt 包含“尽量使用浅色主题”和“可用 image_001 占位资源”等建议。页面工作台必须声明以下优先级：

```text
系统消息、SlideML 协议和安全边界
  > 当前页完整 Markdown 中的教学内容、实际画布、页面身份和真实资源边界
  > 当前用户的页面级设计要求
  > 已验证的全课件主题
  > 当前页原始截图所提供的视觉证据
  > 前后页有限语境
  > 底层通用风格建议
```

其中：

- 如果全课件主题不是浅色主题，不得为了通用“浅色”建议改写主题；
- 如果当前页完整 Markdown 没有提供 `image_001`，不得因为通用示例而虚构该资源；
- 用户要求可以调整当前页的表现重点，但不能要求模型遗漏原始教学内容、泄露路径或违反 SlideML 协议。

后续实现时，更推荐为课件页面提供专用的流式用户 Prompt 包装，移除“浅色主题”和占位资源等带业务倾向的通用建议。

### 3.7 不进入业务 Prompt 的内容

以下内容不进入页面美化业务 Prompt：

- Theme Schema 版本；
- 当前页面 ID、页码、索引、逻辑尺寸、Warning 和画布诊断等独立元数据分区；
- 独立的当前页资源清单及“存在：是/否”等程序状态；
- 用户手工图片附件状态和通用图片裁剪、圆角、多图排列、缺图退化策略；
- `SlideId -> PageType` 映射或独立章节页分类契约；
- 主题分析输入统计、Schema、推理过程、工具调用、校验日志和中间候选；
- 重复的最小字号、行高、字符数、对比度等通用可读性规则；
- 多画布模板变体、横竖版适配和极端比例防御说明。

这些信息或者已经由当前页完整 Markdown、实际画布、系统 Prompt 和渲染检查能力覆盖，或者只服务程序内部处理，加入业务 Prompt 会降低信息密度并改变最终示例的边界。

## 四、首轮提示词的推荐结构

推荐严格按以下顺序组织：

```text
1. 任务
2. 规则优先级
3. 用户补充要求
4. 内容处理要求
5. 原始页面截图
6. 相邻页面语境
7. 全课件主题
8. 封面页参考 SlideML
9. 内容页参考 SlideML
10. 完成标准
11. 当前页完整 Markdown
```

其中“任务”是标题后的首屏说明，其余内容对应最终 Prompt 中的十个编号分区。

这个顺序的考虑是：

- 先建立任务和约束，避免模型先被大段原文带偏；
- 在主题之前提供用户要求、内容处理边界、截图边界和相邻页语境；
- 将两份参考 SlideML 放在主题规则之后，明确它们是样例而不是当前页答案；
- 将最长的当前页 Markdown 放在最后，并用明显边界包裹；
- 完成标准放在原文之前，避免长数据块稀释结束条件。

## 五、各分区应包含的内容

### 5.1 任务

任务段应使用自然语言直接说明：

- 为当前真实课件页重新设计排版和视觉表现；
- 保留本页教学语义、事实、题目、选项、答案关系、引用资源和内容归属；
- 结合当前页内容、原始页面截图和全课件主题生成页面；
- 自主判断当前页更接近封面页、章节页还是普通内容页；
- 不要求机械复刻原截图，也不允许脱离主题任意重做；
- 最终得到一张完整可渲染页面。

### 5.2 规则优先级

显式写出冲突处理顺序，尤其解决通用流式包装与全课件主题的冲突：

1. 系统消息、SlideML 协议、安全与数据边界；
2. 当前页完整 Markdown 中的教学内容、实际画布、页面身份和真实资源边界；
3. 当前消息中的用户页面级设计要求；
4. 已验证的全课件主题；
5. 当前消息实际附带的原始页面截图；
6. 相邻页语境；
7. 通用生成建议。

用户补充要求不能越过安全与数据边界，也不能要求删除原始内容。当前页完整 Markdown 没有提供的资源不得因示例或占位建议而创建。

### 5.3 用户补充要求

用户要求应作为独立自然语言段落，不应嵌入 JSON 字符串。

首次默认要求建议为：

> 请根据当前页完整内容、可用视觉附件和全课件主题完成页面美化，保持教学语义准确、信息完整、层级清晰，并确保所有内容适合当前画布。

如果用户修改了这一段，应把修改后的文字作为实际用户补充要求。**发送时不得再把整份可见 Prompt 当作 `UserInstruction` 重新构建另一份 Prompt。**

可选的 UI 设计有两种：

- 整份首轮 Prompt 可见、可编辑，发送时原样发送，不再调用 Builder；
- 固定上下文只读展示，用户只编辑“用户要求”，发送时由 Builder 组装一次最终 Prompt。

不能同时采用“整份 Prompt 可编辑”和“发送前再次把编辑文本作为用户要求重建”两种策略。

### 5.4 内容处理要求

该段应明确：

- 当前页完整 Markdown 是本页内容事实源；
- 不遗漏非空文本、题干、选项、结论、步骤、表格信息和资源引用；
- 不把前后页内容直接复制到当前页；
- 可以重新分组、调整层级、改变视觉顺序和去除纯装饰性旧布局信息；
- 不擅自改写知识事实、答案关系、专有名词、数字或符号；
- 原页内容过多时优先压缩视觉表达、重组层级和优化布局，本次任务仍只生成当前单页，不擅自拆出新页；
- 原页内容较少时可以通过留白、图文关系和层级设计增强表现，但不能编造新的教学事实。

Markdown 同时包含原始位置、尺寸、字号和字体。这些旧视觉参数只作为理解原页面结构的参考，不应机械继承；全课件主题才是新页面的视觉规范。

### 5.5 原始页面截图

首轮消息随附当前页原始页面截图。Prompt 只需要明确：

- 截图用于理解原页面的内容分组、重点、图文关系和视觉问题；
- 不要求复刻旧版式；
- 截图只提供视觉证据，不是可直接写入 SlideML 的课件资源；
- 不得把截图的附件文件名或路径写入 SlideML；
- 不得自动把截图当作 `Image Source`；
- 可用资源及其引用信息以当前页完整 Markdown 为准。

Prompt 不增加用户手工图片分支、附件数量、附件文件状态或通用图片处理策略。

### 5.6 相邻页面语境

前一页和后一页都使用完整 Markdown，而不是标题与摘要。它们分别使用动态长度围栏包裹，并明确：

- 相邻页只用于理解当前页在课件叙事中的位置和跨页节奏；
- 相邻页不是当前页内容来源；
- 不得把相邻页内容直接排入当前页；
- 没有前页或后页时，对应位置写“无”，不输出 `null`。

### 5.7 全课件主题

主题分区只包含能够直接改变当前页视觉结果的信息：

1. 整体视觉风格原文；
2. 配色及用途；
3. 中文与西文字体；
4. 字号规则原文；
5. 当前画布安全区的比例和像素值；
6. 背景、间距与视觉效果原文；
7. 版式原则原文。

主题 Schema 版本不进入 Prompt。主题分析输入、Schema、分析过程、推理文本、工具调用、校验日志和中间候选也不进入 Prompt。

#### 5.7.1 整体视觉风格

使用主题分析给出的整体视觉风格原文，不归纳为少量风格关键词，不与配色合并。

#### 5.7.2 配色及用途

颜色按已有确定字段逐项输出名称、颜色值和用途。例如：

```text
- 纸白：#FFFFFF；用途：页面背景
- 墨色：#0F172A；用途：正文
- 强调蓝：#2563EB；用途：重点强调
```

#### 5.7.3 字体与字号

中文与西文字体按确定字段输出。字号使用主题分析给出的字号规则原文，不转换为程序定义的标题级别、字号 Token、最小字号或额外可读性规则。

#### 5.7.4 当前画布安全区

安全区同时给出主题比例和按当前页实际渲染画布确定性计算的像素值：

```text
左：5%（64 px）
上：5%（36 px）
右：5%（64 px）
下：5%（36 px）
```

像素值服务于当前页执行，比例值保留主题原意。关键内容必须位于安全区内；纯背景和非关键信息装饰可以延伸到安全区外，但不能造成裁剪或阅读干扰。

#### 5.7.5 背景、间距与视觉效果

使用主题分析给出的背景、间距、圆角、阴影、描边、装饰及其他视觉效果规则原文。程序不拆成背景类型、容器 Token 或组件样式。

#### 5.7.6 版式原则

使用主题分析给出的版式原则原文，不二次归纳为程序定义的页面骨架。

### 5.8 两份参考 SlideML

`CoverPageSlideMl` 与 `ContentPageSlideMl` 都是已经通过完整 XML、Schema 和真实渲染校验的参考页面，但它们不是当前页分类结论。

必须明确：

- 两份参考都不是当前页答案，也不代表当前页已经被分类；
- 当前页 Agent 根据当前页内容、视觉附件和主题自主判断页面角色；
- 两份参考页在主题分析时使用第一页画布完成校验；若当前页画布不同，只能借鉴其比例、层级和视觉语言，不得直接照搬坐标或尺寸；
- 参考 SlideML 用于学习颜色、字体、留白、区域关系和组件风格，不要求逐元素复制；
- 不得把参考页中的示例文字误当成当前页内容；
- 不得使用当前页完整 Markdown 没有提供的资源 ID；
- 如果参考结构无法容纳当前内容，应保持主题语言并重新组织布局，而不是压缩到不可读或裁剪。

两份原文应分别放在 `xml` 代码块中，不能转义成 JSON 字符串。

### 5.9 完成标准

业务 Prompt 应要求最终结果满足：

- 最终合并状态是一张完整、可渲染的 `Page`；
- 当前页全部教学内容已被表达；
- 使用真实画布尺寸和安全区；

## 七、运行时生成规则

### 7.1 用户补充要求

`UserInstructionOrDefault` 使用用户实际输入的页面级设计要求。用户没有修改时，使用以下默认要求：

> 请根据当前页完整内容、可用视觉附件和全课件主题完成页面美化，保持教学语义准确、信息完整、层级清晰，并确保所有内容适合当前画布。

用户要求只替换模板中的“用户补充要求”分区，不得把整份可见 Prompt 再次作为 `UserInstruction` 嵌套进新 Prompt。

### 7.2 主题内容透传

主题分析结果按以下规则写入 Prompt：

- `ThemeVisualStyle` 使用整体视觉风格原文；
- `ColorSuggestions` 按颜色名称、颜色值和用途逐项输出；
- `ChineseFont` 与 `WesternFont` 使用主题中的确定字段；
- `FontSizeRules` 使用字号规则原文；
- `BackgroundSpacingAndVisualEffects` 使用背景、间距、圆角、阴影、描边、装饰及其他视觉效果规则原文；
- `LayoutPrinciples` 使用版式原则原文；
- `CoverPageSlideMl` 与 `ContentPageSlideMl` 使用完整 XML 原文。

除颜色、字体和安全区等已有确定字段外，主题自由文本不进行二次结构化、归纳或改写。Theme Schema 版本和主题分析过程信息不写入 Prompt。

### 7.3 安全区像素换算

根据当前页实际渲染画布分别换算：

```text
LeftPixels   = round(CanvasWidth  × LeftRatio)
RightPixels  = round(CanvasWidth  × RightRatio)
TopPixels    = round(CanvasHeight × TopRatio)
BottomPixels = round(CanvasHeight × BottomRatio)
```

Prompt 同时输出安全区百分比与像素值。像素值服务于当前页执行，比例值保留主题分析原意。

### 7.4 当前页与相邻页 Markdown

当前页 Markdown 逐字保留，不摘要、不截断、不进行 JSON 字符串转义。

前一页和后一页也使用完整 Markdown，不转换成标题与摘要。没有前页或后页时，对应位置直接写“无”，不输出 `null`，也不输出空代码块。

三份 Markdown 分别扫描自身最长连续反引号，并各自使用至少多一个反引号的外层围栏。例如原文最长为三个反引号，则外层使用四个反引号。围栏不添加语言标记。

### 7.5 参考 SlideML

两份参考 SlideML 使用完整 XML 原文，并分别放入 `xml` 代码块，不经过 JSON 字符串转义。Builder 不从参考页推导当前页类型映射，也不生成独立章节页模板。

### 7.6 原始页面截图

当前页原始页面截图作为首轮消息的视觉附件独立发送，不在 Prompt 中写入附件文件名或路径。业务 Prompt 与截图附件应基于同一发送快照，确保文本中“当前消息随附”与实际消息一致。

### 7.7 资源边界

Builder 不再生成独立资源清单。当前页完整 Markdown 是资源 ID 及其引用关系的事实源，模板通过规则优先级、截图说明和完成标准共同约束模型只能引用其中提供的真实资源。

不得为了方便模型而追加 `image_001`、`img_1` 或其他占位资源，也不增加通用图片处理策略。

### 7.8 上下文预算

Token 估算应基于最终实际发送的业务 Prompt、流式包装和视觉附件。上下文不足时不得静默截断当前页 Markdown、相邻页 Markdown、主题规则或参考 SlideML；应明确阻断，并提示选择更大上下文模型。

## 八、系统 Prompt 与业务 Prompt 的职责边界

### 8.1 应继续放在流式 System Prompt 的内容

- SlideML 可用标签、属性和父子层级；
- 流式片段格式；
- `Id`、`StyleId`、`StyleFrom` 与合并规则；
- XML 转义；
- 渲染与错误重试；
- 页面状态与预览检查能力的使用方式；
- 禁止写入引擎回填属性；
- 工具和输出通道约束。

这些规则不复制到每一页业务 Prompt，避免增加 Token 并产生两份规范漂移的风险。

### 8.2 应放在页面业务 Prompt 的内容

- 当前页任务与规则优先级；
- 用户页面级设计要求；
- 内容保真与处理边界；
- 原始页面截图的视觉证据边界；
- 前后页完整 Markdown 提供的有限语境；
- 全课件主题的最终规则；
- 两份已验证参考 SlideML；
- 页面级完成标准；
- 当前页完整 Markdown。

### 8.3 只保留在程序内部的内容

- Theme Schema 版本和序列化兼容信息；
- 当前页面 ID、索引、Warning 和画布诊断；
- 主题分析输入统计、推理过程、工具调用和校验日志；
- 资源存在性检查、路径和导出文件名；
- 上下文预算估算明细与内部信封结构。

这些信息可以参与程序校验、日志和错误提示，但不进入发送给页面美化 LLM 的业务 Prompt。

### 8.4 课件专用流式用户包装

课件场景的流式用户包装不再追加以下通用建议：

- `尽量使用浅色主题`；
- `若需图片可用占位资源 ID，如 image_001`；
- 固定的标题 L2、正文 L3、辅助 L4 建议；
- 与全课件主题或当前页 Markdown 资源边界重复、冲突的风格要求。

课件专用包装只负责说明应按系统消息规定的流式 SlideML 协议执行页面任务，并原样附加 Builder 生成的业务 Prompt。

## 九、状态与异常处理

### 9.1 原始页面截图未能随消息发送

最终模板明确声明当前消息随附原始页面截图。因此业务 Prompt 与截图必须作为同一发送快照原子构建。若截图无法附带，不应继续发送一份与实际附件状态不一致的 Prompt；应阻断首轮发送并向用户显示可处理的错误。

### 9.2 用户修改首轮草稿

必须选择单一事实源：

- 若整份 Prompt 可编辑，则发送用户当前可见的完整草稿，不再调用 Builder 重建；
- 若固定上下文只读、用户只编辑“用户补充要求”，则发送前由结构化源构建一次最终 Prompt。

不能把整份已编辑 Prompt 嵌入 `UserInstruction`。

### 9.3 没有前页或后页

对应位置写“无”，不输出 `null` 或空对象，也不创建虚构相邻页摘要。

### 9.4 全课件主题与用户要求冲突

用户可以调整当前页表现重点和页面气质，但不能要求遗漏内容、改变事实、越过实际画布与资源边界、泄露路径或违反系统协议。页面工作台定位为全课件统一美化，因此全课件主题仍是页面视觉边界。

### 9.5 当前页没有资源或参考页含不可用资源

不生成独立资源清单，也不创建占位资源。模型只能使用当前页完整 Markdown 中提供的真实资源 ID；参考 SlideML 中出现但当前页 Markdown 未提供的资源只能作为视觉参考，不能复用。

### 9.6 上下文预算不足

不得静默截断当前页 Markdown、相邻页 Markdown、主题规则或两份参考 SlideML。可通过移除 JSON 语法、重复包装和不进入 Prompt 的内部信息节省上下文；仍超预算时应明确阻断。

- 模型最终形成完整可渲染页面，并主动修正裁剪、溢出和标题换行问题。

## 十二、最终建议

页面美化 LLM 需要的不是一份“更漂亮的 JSON”，而是一份阅读顺序明确、职责边界清楚、信息密度足够高的页面设计任务书。

最终应坚持以下三个事实源：

1. **当前页完整 Markdown 决定内容、实际画布、页面身份和真实资源边界；**
2. **主题分析原文与两份已验证参考 SlideML 共同决定全课件视觉语言；**
3. **当前消息随附的原始页面截图提供视觉证据，相邻页完整 Markdown 只提供有限叙事语境。**

后续实现只加入能够直接改变当前页生成结果的信息，不为内部数据结构、低概率防御或重复规则消耗 LLM 上下文。
