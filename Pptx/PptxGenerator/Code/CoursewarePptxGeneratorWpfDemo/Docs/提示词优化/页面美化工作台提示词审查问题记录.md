# CoursewarePptxGeneratorWpfDemo 页面美化工作台提示词审查问题记录

> 文档状态：审查结论。
>
> 本文记录对 [`页面美化工作台最终提示词示例.md`](./页面美化工作台最终提示词示例.md) 与当前主题分析能力进行对照时发现的问题，并明确后续页面美化 Prompt 的信息边界。

## 一、核心原则

LLM 上下文是页面生成链路中的宝贵资源。页面美化 Prompt 只应保留对当前页最终生成结果有直接帮助的高密度信息，不应为了说明数据结构、覆盖边界或防御低概率情况而增加无关内容。

主题分析提供的自由文本规则应直接进入 Prompt：主题分析给出什么，页面美化 Agent 就读取什么。程序不应为了展示方便再次拆分、归纳或改写这些规则，以免丢失语义、引入偏差并浪费上下文。

## 二、本次确认需要修正的问题

### 2.1 缺少字号规则

当前主题分析输入包含整份课件的字号分布，字号规则会直接影响标题、正文、辅助文字和页面信息密度，是页面生成需要执行的视觉信息。

最终提示词示例应提供独立的“字号”位置，但只透传主题分析给出的字号规则原文，不将其转换为程序定义的标题级别、字号 Token 或额外可读性规则。

### 2.2 背景与视觉规则表达不够明确

原示例只有“间距与视觉效果”，不能清楚表达页面背景、容器表面和整体视觉处理也属于主题分析结果。

最终提示词示例应使用“背景、间距与视觉效果”，并直接放入主题分析给出的相关原文。程序不对背景类型、圆角、阴影、描边或装饰规则做二次结构化。

### 2.3 “整体风格”对真正视觉风格的指向不够明确

真正视觉风格不是单独依赖配色，也不是由页面 Agent 临时猜测。它在 Prompt 中由以下内容共同承载：

1. “整体视觉风格”中的主题分析原文；
2. 配色及用途；
3. 字体与字号；
4. 背景、间距与视觉效果；
5. 版式原则；
6. 已通过校验的封面页和内容页参考 SlideML。

其中，自由文本规则表达设计意图，参考 SlideML 提供可观察的视觉实现。最终提示词示例将“整体风格”改为“整体视觉风格”，避免把它理解成泛化描述或仅有风格关键词。

## 三、当前提示词中不存在页面类型映射

最终提示词中的以下要求是当前页 Agent 的自主判断任务：

> 请结合当前页内容、视觉附件和全课件主题，自行判断本页更接近封面页、章节页还是普通内容页。

这不是主题分析预先生成的页面类型映射，也没有给当前 `SlideId` 指定固定分类。它只要求页面 Agent 根据当前页真实内容选择更合适的参考方式。

因此：

- 当前示例不需要删除这段内容；
- 不应把这段内容描述成页面类型映射；
- 不应因为主题只提供封面页和内容页参考 SlideML，就推导出章节页实现错误；
- 页面角色判断与参考 SlideML 的数量不是同一个契约。

当前提示词状态作为页面角色判断的设计基准保持不变。

## 四、明确不进入页面美化 Prompt 的内容

### 4.1 主题版本

主题 Schema 版本用于程序校验、序列化和兼容性判断，对当前页面的视觉生成没有直接帮助，不进入 LLM Prompt。

### 4.2 图片处理策略

不增加通用图片裁剪、圆角、多图排列或缺图退化策略。当前页图片资源边界、原始 Markdown 和视觉附件已经提供实际任务所需事实，额外通用策略信息密度低且可能干扰页面 Agent 按真实内容设计。

### 4.3 页面类型映射

主题分析不需要在页面 Prompt 中提供 `SlideId -> PageType` 映射。当前页 Agent 按当前页内容自主判断页面角色。

### 4.4 额外可读性规则

不重复增加最小字号、行高、字符数、对比度或其他通用可读性规定。字号规则已经由主题分析原文提供，页面最终状态还会通过 SlideML 渲染与检查能力核对裁剪、溢出和越界。

### 4.5 多画布防御说明

不增加多画布模板变体、横竖版适配和极端比例策略。当前提示词已经提供实际画布、安全区，并要求页面适合当前画布；继续扩展属于低收益的过度防御。

### 4.6 主题分析过程信息

不发送主题分析输入统计、Schema、分析过程、推理文本、工具调用、校验日志或中间候选结果。页面 Agent 只消费最终主题规则和已验证参考 SlideML。

## 五、主题信息的最终承载方式

页面美化 Prompt 中的主题部分保持以下高密度结构：

1. 整体视觉风格原文；
2. 配色及用途；
3. 中文与西文字体；
4. 字号规则原文；
5. 当前画布安全区；
6. 背景、间距与视觉效果原文；
7. 版式原则原文；
8. 封面页参考 SlideML；
9. 内容页参考 SlideML。

除颜色、字体和安全区等当前已有确定字段外，字号、背景视觉规则和版式原则均按主题分析原文透传，不由页面 Prompt Builder 二次结构化。

## 六、本次审查中的错误判断

本次审查曾提出以下不恰当建议，后续不应据此修改 Prompt：

- 建议加入 Theme Schema 版本；
- 建议加入通用图片处理策略；
- 将当前页面角色自主判断误解为页面类型映射；
- 因没有独立章节页参考 SlideML 而推断当前章节页处理错误；
- 建议重复加入最小字号、对比度等可读性规定；
- 建议增加多画布适配防御说明；
- 建议把主题自由文本进一步拆成程序定义的结构化规则。

这些建议的问题不是实现成本，而是会占用上下文、重复已有信息、降低信息密度，或者改变当前提示词已经确定的业务语义。

## 七、最终结论

当前主题分析对页面美化的主要真实缺口，是最终提示词示例没有明确承载字号规则，以及“整体视觉风格”和“背景、间距与视觉效果”的表达不够准确。

修正后，主题信息应以原文和参考 SlideML 共同进入页面 Prompt。后续设计应继续遵守：只加入能够直接改变当前页生成结果的信息，不为内部数据结构、低概率防御或重复规则消耗 LLM 上下文。
