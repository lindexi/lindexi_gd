# CoursewarePptxGeneratorWpfDemo 页面美化工作台提示词重构实施方案

> 文档状态：待审批，尚未实施。
>
> 本文给出当前 `CoursewarePptxGeneratorWpfDemo` 的具体改造决定、目标形态、文件级实施步骤、测试矩阵和验收标准。实施语义以 [`页面美化工作台提示词设计.md`](../提示词优化/页面美化工作台提示词设计.md) 和 [`页面美化工作台最终提示词示例.md`](../提示词优化/页面美化工作台最终提示词示例.md) 为准。

## 一、决定要怎么改

本次改造直接采用以下方案，不继续保留多套可选路径。

### 1.1 首轮页面美化 Prompt 改为自然语言 Markdown

`CoursewareSlidePromptBuilder` 不再把 `CoursewareSlideGenerationEnvelope` 序列化为 JSON。新的首轮 Prompt 严格按设计文档确定的阅读顺序输出：

1. 单页课件美化任务；
2. 规则优先级；
3. 用户补充要求；
4. 内容处理要求；
5. 原始页面截图边界；
6. 前后页完整 Markdown；
7. 全课件主题；
8. 封面页参考 SlideML；
9. 内容页参考 SlideML；
10. 完成标准；
11. 当前页完整 Markdown。

Prompt 中不再出现 JSON 信封、Theme Schema 版本、页面索引、Warning、画布诊断、独立资源清单、附件文件名或内部布尔状态。

### 1.2 输入框和附件区成为下一次发送的唯一事实源

页面首次被访问时，程序完成一次本地准备：

```text
当前主题 + 当前页及相邻页 Markdown + 当前页实际画布
  -> 构建完整自然语言首轮 Prompt
  -> 写入当前页输入框
  -> 将当前页原始截图加入可见附件集合
```

用户点击“发送”后，发送逻辑只做以下事情：

```text
读取当前输入框文本快照
  + 读取当前可见附件快照
  + 校验首轮原始截图仍然存在
  + 首轮执行上下文预算检查
  + 预加载并验证本次全部视觉附件
  + 原样发送快照
```

发送阶段不得再次调用 `CoursewareSlidePromptBuilder`，也不得把整份可见 Prompt 当成 `UserInstruction` 嵌套到另一份 Prompt 中。

### 1.3 整份首轮 Prompt 保持可编辑

本次选择“整份 Prompt 可见、可编辑、原样发送”的交互，不新增另一套只编辑“用户补充要求”的结构化表单。

这样可以继续复用当前 `InputText`、`DraftRevision` 和发送快照机制，并保证用户看到的内容与模型实际接收的业务文本完全一致。

### 1.4 首轮原始截图改为必需附件

最终提示词明确声明“当前消息随附当前页的原始页面截图”。因此首轮请求必须实际包含 `SourceScreenshot` 附件。

具体规则如下：

- 页面首次准备草稿时，原始截图存在才构建可发送的首轮 Prompt；
- 原始截图附件在首轮成功前不可由用户移除；
- 原始截图文件缺失、在发送前被删除或加载失败时，阻断首轮发送；
- 阻断时保留当前草稿和其他附件，不创建或推进页面会话；
- 首轮成功后移除已发送的原始截图，后续追问不再自动重复附带；
- 用户手工添加的图片继续作为补充视觉附件，但不能替代必需的原始页面截图。

这会替换当前“没有截图也继续生成”的行为和对应测试。

### 1.5 Theme 契约新增独立字号规则原文

设计文档要求页面 Prompt 直接透传主题分析给出的字号规则原文，但当前 `CoursewareTheme` 没有字号字段。程序不得根据参考 SlideML、课件字号统计或固定 Token 临时推导字号规则。

因此在主题契约中新增必填字段：

```text
FontSizeRules: string
```

该字段只保存主题分析 Agent 给出的字号层级和字号使用规则原文，不拆成标题、正文、辅助文字等程序自定义 Token。

由于这是持久化契约的破坏性变化，实施时同步执行以下版本升级：

- `CoursewareTheme.CurrentSchemaVersion`：`2.0` 升级为 `2.1`；
- 主题 Agent、提交工具、校验错误和相关文档统一改称 Theme 2.1；
- `CoursewareThemeAnalysisSnapshotManifest.CurrentSchemaVersion`：`2` 升级为 `3`；
- 快照 v1 继续拒绝；当前受支持的 v2 在升级后改为明确拒绝；不增加默认字号、不静默迁移、不兼容加载。

页面 Prompt 不输出 `2.1` 版本号。版本只服务程序校验和快照兼容性。

### 1.6 删除页面 JSON 信封，而不是保留第二事实源

仓库内 `CoursewareSlideGenerationEnvelope`、`CoursewareSlideGenerationJsonSerializerContext` 和 `CoursewareSlidePromptBuildResult.Envelope` 只被当前 Builder 与测试使用，没有独立业务消费者。

本次决定删除：

- `Models/CoursewareSlideGenerationEnvelope.cs`；
- `Models/CoursewareSlideGenerationJsonSerializerContext.cs`；
- `CoursewareSlidePromptBuildResult` 及其 `EstimatedTokenCount`。

`CoursewareSlidePromptSource` 继续保留，用来持有当前 `CoursewareInputPackage` 和已验证主题。上下文预算继续以最终发送文本为准，由 `CoursewareSlideContextBudgetValidator` 统一估算，不再维护 Builder 自己的近似 Token 数。

### 1.7 课件运行时使用无风格偏置的流式用户包装

不修改 `PptxGenerator.Core` 中通用 `SlideMlPromptProvider` 的默认行为，避免影响其他 Demo 和通用 SlideML 场景。

`SlideChatManagerFactory` 在创建课件页面运行时时，继续实例化具体的 `SlideMlPromptProvider`，但将其流式用户模板配置为原样透传：

```text
{USER_INPUT}
```

由此达到以下效果：

- 继续复用通用流式 System Prompt、SlideML Schema、合并规则和工具规则；
- 不再追加“尽量使用浅色主题”；
- 不再追加固定 L2/L3/L4 字号建议；
- 不再追加 `image_001` 占位资源建议；
- 不新增装饰器类型，不改动共享 Prompt 接口。

当前课件页面工作台没有暴露提示词自动迭代入口。本次不把 `PromptIterationPipeline` 接入课件工作台，也不承诺课件专用流式模板在该实验管线的 `ResetToDefault()` 后保持。后续如要接入提示词迭代，必须单独扩展核心 Provider 的“产品基线模板”和“临时优化覆盖”层次，并让迭代使用流式协议；不能直接复用当前会清除全部覆盖值的实现。

### 1.8 保留底层首轮协议，不把它暴露回 UI

以下机制继续保留：

- `CoursewareSlideMessageSnapshot.IsFirstMessage`；
- `SlideChatManager.SendMessageAsync(... isFirstMessage ...)`；
- 首轮重置流式页面状态；
- 首轮发送前重置最近渲染快照，确保成功判断只消费本次请求结果；
- 首轮按需要创建新聊天会话；
- 后续追问直接发送用户自然语言；
- 每页独立运行时、会话、画布、取消和结果状态。

`isFirstMessage` 只作为管线内部协议参数，不再决定发送时是否构建隐藏 Prompt。

## 二、改造完成后是什么样

### 2.1 用户首次进入一页

用户选中页面后，右侧工作台应直接显示：

- 一份以“单页课件美化任务”开头的完整自然语言 Prompt；
- 当前页原始页面截图的可见附件缩略图；
- 当前页模型和运行时状态；
- 唯一的“发送”按钮。

用户能够在发送前检查或编辑整份 Prompt。输入框中不再出现 JSON 大括号、转义后的 XML 或 `courseware-slide-generation/v1`。

### 2.2 用户点击发送

若当前输入框未被修改，模型接收的业务文本必须与输入框内容逐字一致。

若当前输入框已被修改，模型接收修改后的完整文本，不重建、不嵌套、不恢复默认段落。

首轮消息同时附带：

- 当前页原始页面截图；
- 用户当前可见且仍存在的其他图片附件；
- 用户勾选后可选附带的当前渲染预览。

发送快照中的所有文件附件都属于本次传输的必需附件。工作台在发送前使用 WPF 图片解码器验证后构造内存 `DataContent`，任何一张图片读取或解码失败，本次请求整体失败；程序不得静默跳过部分附件后继续发送。可选的“当前渲染预览”也在同一步捕获为 `DataContent`；用户勾选但当前没有可用预览时明确阻断。全部视觉内容准备完成后，程序才允许清理失败会话、重置最近渲染结果并开始首轮请求。

### 2.3 首轮成功后继续追问

首轮生成出有效 SlideML 后：

- 页面会话标记为已建立；
- 已成功发送且仍匹配快照的首轮草稿被清空；
- 原始截图从下一次待发附件中移除；
- 用户输入“把标题改得更简洁”等普通追问；
- 后续消息不再重复主题、相邻页、参考 SlideML 或当前页完整 Markdown；
- 底层继续在同一页面会话和流式合并状态上修改页面。

### 2.4 首轮失败或取消

首轮失败、取消、预算超限、截图丢失或模型没有形成有效页面时：

- `HasStartedGenerationConversation` 保持 `false`；
- 当前输入框文本保持不变；
- 当前附件保持不变；
- 页面可以在问题修复后直接重试；
- 若失败请求已经产生聊天历史，重试前继续使用当前已有的新会话清理逻辑；
- 每次首轮尝试在发送前清空最近渲染结果；只有本次请求重新产生非空 SlideML 才能判定成功；
- 不把失败首轮误当成续轮。

### 2.5 主题重新分析

新的 Theme 2.1 发布后，页面按状态处理：

| 页面状态 | 处理方式 |
| --- | --- |
| 尚未准备首轮草稿 | 首次访问时使用新主题构建 |
| 已准备、尚未开始会话、用户未编辑 | 立即使用新主题重建可见首轮 Prompt |
| 已准备、尚未开始会话、用户已编辑 | 保留用户草稿，标记“当前草稿基于旧主题” |
| 已建立会话 | 保持当前会话和页面结果，不静默切换主题 |

不新增主题指纹或运行 ID。使用现有页面生命周期和一个明确的 `IsInitialPromptThemeOutdated` 状态即可表达是否需要用户关注。

已编辑且过期的草稿显示明确警告和“按最新主题重建草稿”按钮。按钮只在尚未建立会话时可用，点击后明确覆盖当前编辑内容，重新使用最新主题构建首轮 Prompt，并清除过期标记。“重新进入当前页”不会绕过 dirty 状态自动重建。

## 三、审批时需要确认的行为变化

本次方案包含以下明确的破坏性变化，审批通过后按新规则修改测试，不保留旧行为兼容分支。

1. Theme Schema 从 `2.0` 升级到 `2.1`。
2. 主题分析快照从 v2 升级到 v3，旧 v2 快照不再加载。
3. 首轮页面 Prompt 从 JSON 改为 Markdown 自然语言。
4. 页面 JSON 信封和对应源生成上下文删除。
5. 首轮发送时不再调用 Prompt Builder。
6. 原始页面截图由“存在时发送”改为“首轮必需”。
7. 通用流式用户包装中的浅色、固定字号层级和占位资源建议不再作用于课件页面。
8. 相邻页由标题摘要改为完整 Markdown。
9. Builder 不再输出独立资源清单，资源边界由当前页完整 Markdown 表达。
10. 发送快照中的全部图片文件改为本次请求必需附件，任何一项传输失败都会阻断发送。
11. 每次首轮尝试都会清空旧渲染结果，旧预览如需附带必须先捕获为本次请求图片数据。
12. 课件页面运行时不再注入 `IPromptOptimizer`，从技术上禁用共享提示词迭代入口。

### 3.1 快照升级兼容影响

| 场景 | 结果 |
| --- | --- |
| 新程序打开快照 v2 | 拒绝加载，不自动回退为普通课件目录 |
| 旧程序打开快照 v3 | 拒绝加载 |
| 只有 v2 快照、原始课件仍存在 | 使用原始课件重新分析后生成 v3 |
| 只有 v2 快照、原始课件已经丢失 | 本次方案没有恢复路径 |
| 代码整体回退到旧版本 | 已生成的 v3 不会自动转换为 v2 |

发布和回退前应保留原始课件目录，必要时备份旧快照。审批通过即表示接受 v2 与 v3 双向不兼容且不提供迁移器。

## 五、当前实现中需要解决的真实问题

### 5.1 首轮发送会再次构建 Prompt

当前 `CoursewareSlideWorkspaceViewModel.SendPageMessageAsync` 在 `snapshot.IsFirstMessage` 为 `true` 时再次调用 `_promptBuilder.Build(...)`。

当用户没有编辑初始草稿时，代码用默认要求重建一次；当用户编辑了初始草稿时，代码把 `snapshot.Message` 当作 `userInstruction` 填进新信封。后一种情况会形成“完整可见 Prompt 包入另一份 Prompt”的递归结构。

改造后，`SendPageMessageAsync` 的首轮分支只负责：

- 校验快照；
- 预算检查；
- 预加载并验证全部视觉附件；
- 在所有预检成功后清理旧失败会话和旧渲染结果；
- 设置发送状态；
- 原样调用 `SendStreamingMessageWithResultAsync`；
- 只根据 `SlideStreamingGenerationResult` 提交成功状态。

### 5.2 当前 Prompt 与实际流式协议冲突

当前 JSON 信封要求“只输出完整 Page XML”，但流式 System Prompt 要求模型连续输出 XML 片段并使用合并能力。模型同时收到两套不同输出要求。

新的业务 Prompt 只要求按系统消息规定的流式 SlideML 协议工作，并要求最终合并状态是一张完整页面。具体片段格式、首片段、Id、合并、Remove 和检查工具仍由 System Prompt 负责。

### 5.3 通用用户包装覆盖课件主题

当前 `SlideMlPromptProvider.BuildDefaultStreamingUserPrompt` 追加浅色主题、L2/L3/L4 和 `image_001`。这些内容会覆盖或污染课件主题与真实资源边界。

本次不改通用 Provider，而是在课件页面工厂中配置流式用户模板为原样透传。

### 5.4 Theme 缺少字号字段

当前主题分析输入已经汇总字号分布，设计也要求页面 Prompt 透传字号规则，但 `CoursewareTheme` 无法保存该结论。若只改页面 Builder，只能编造或丢失字号语义。

因此 Theme 契约升级必须先于页面 Prompt Builder 落地。

### 5.5 当前相邻页只有摘要

当前 Builder 使用 `CoursewareSlideSummaryService` 构建前后页标题和有限摘要。新设计要求前后页完整 Markdown 作为有限叙事语境，且明确禁止复制到当前页。

Builder 将直接从 `CoursewareInputPackage.Slides` 读取相邻页 `MarkdownText`，不再通过摘要服务构建页面生成上下文。摘要服务仍保留给缩略图和页面标题展示。

### 5.6 当前首轮截图可以被移除或缺失

当前页面准备后，原始截图和 Prompt 都可见，但用户可以通过统一的关闭按钮移除截图；发送逻辑也允许没有截图的页面继续生成。这会让 Prompt 中的截图声明与真实附件不一致。

改造后，首轮原始截图附件不可移除，并在创建快照后再次检查文件存在性。

## 六、目标调用链

### 6.1 页面首次访问

```text
CoursewareSlideWorkspaceViewModel.InitializeSlideAsync
  -> PrepareInitialDraft
  -> CoursewareSlideItemViewModel.EnsureSourceScreenshotAttachment
  -> CoursewareSlidePromptBuilder.BuildInitialPrompt
       -> 当前页完整 Markdown
       -> 前后页完整 Markdown
       -> Theme 2.1 原文与颜色/字体/安全区
       -> 当前页实际画布安全区像素
       -> 两份完整参考 SlideML
       -> 动态代码围栏
  -> CoursewareSlideItemViewModel.ApplyInitialPrompt
  -> CoursewareSlideItemViewModel.EnsureRuntimeAsync
```

Prompt 准备是纯本地、确定性操作，不依赖模型运行时创建成功。

### 6.2 首轮统一发送

```text
SendMessageCommand
  -> CoursewareSlideItemViewModel.CreateMessageSnapshot
  -> ValidateInitialSnapshot
       -> 文本非空
       -> 存在 SourceScreenshot
       -> 必需截图文件仍存在
       -> 其他附件文件仍存在
  -> EnsureRuntimeAsync
  -> CoursewareSlideContextBudgetValidator.ValidateIfConfigured
       -> 课件专用 PromptProvider.BuildStreamingUserPrompt
       -> 实际流式 System Prompt
       -> 查询工具 Schema
       -> 输出预留与安全余量
  -> CoursewareImageAttachmentLoader.LoadAsync
       -> 读取 snapshot 中全部图片文件
       -> 使用 BitmapDecoder 验证至少存在一帧
       -> 按扩展名映射 image/png、image/jpeg、image/bmp、image/gif、image/webp
       -> 构造内存 DataContent
  -> 若勾选当前渲染预览，将现有预览捕获为 image/png DataContent；不存在则阻断
  -> 清理失败首轮遗留会话（如有）
  -> SlideMlRenderTool.ResetLatestResultAsync
  -> SlideChatManager.SendStreamingMessageWithResultAsync
       userMessage = snapshot.Message
       isFirstMessage = true
       attachedImageContents = 发送前已预加载的全部视觉内容
       attachPreview = false
  -> 仅当 SlideStreamingGenerationResult.IsSuccess 为 true 时提交页面成功状态
```

在 `SlideChatManager` 和 `SlideGenerationPipeline` 增加专用 `SendStreamingMessageWithResultAsync`，并在 `StreamingSlideGenerator.GenerateAsync` 增加预加载图片内容参数和明确结果返回。流式生成器只把这些内容加入首次用户消息；错误修复轮不会向新的修复消息重复追加，但会继续使用同一会话历史，因此模型仍可看到最初消息中的附件。现有 `SendMessageAsync`、文件路径附件参数和非流式分支保持不变；课件工作台改用新入口，不再把附件路径交给底层流式加载，也不继续依赖 `attachPreview = true` 在重置后读取预览。

`SlideStreamingGenerationResult` 至少包含 `IsSuccess`、`AttemptCount`、`AcceptedFragmentCount`、`FinalAttemptAcceptedFragmentCount`、`FinalSlideXml` 和 `ErrorMessage`。只有最终成功尝试至少接受一个新片段、该尝试无解析或渲染错误、流结束处理成功且最终合并 XML 非空时，`IsSuccess` 才为 `true`。重试耗尽、最终仍有错误、最终尝试没有接受新片段或没有形成最终页面时返回失败；即使合并器从前序尝试或续轮会话保留了非空 XML，也不得标记成功。外部取消继续抛出 `OperationCanceledException`。

### 6.4 明确的流式生成结果

新增 `Models/SlideStreamingGenerationResult.cs`，由共享流式生成器返回：

| 字段 | 含义 |
| --- | --- |
| `IsSuccess` | 最终一轮是否无错误并形成非空完整页面 |
| `AttemptCount` | 实际模型尝试次数 |
| `AcceptedFragmentCount` | 本次 `GenerateAsync` 调用成功合并的新片段总数 |
| `FinalAttemptAcceptedFragmentCount` | 最终一次模型尝试成功合并的新片段数 |
| `FinalSlideXml` | 最终成功页面；失败时为空字符串 |
| `ErrorMessage` | 重试耗尽、无输出或最终错误的可读摘要；成功时为 `null` |

`RunStreamingLoopAsync` 为每次模型尝试统计成功片段数，并将该计数与错误状态一起返回给 `GenerateAsync`。为保证计数语义准确，`SlideStreamingPipeline` 将 `FragmentReceived` 事件移动到合并错误检查之后：失败并回滚的片段不计数，成功合并后即使随后出现渲染错误也计入“本次产生过中间内容”，但该尝试仍失败。调用级总数用于诊断，最终尝试计数用于成功判定。

`RunStreamingLoopAsync` 继续收集每轮错误，但 `GenerateAsync` 在最大重试次数到达时必须返回失败结果，不能再静默 `break`。最终尝试没有新输出时，无论前序尝试或续轮会话是否已有成功片段、合并页面是否非空，都返回失败。课件工作台以该结果为唯一成功判据，`CurrentSlideXml` 只用于展示和编辑。

共享入口固定为：

```text
SlideChatManager.SendStreamingMessageWithResultAsync(
    string userMessage,
    bool isFirstMessage,
    IReadOnlyList<DataContent>? attachedImageContents = null,
    bool createNewSession = false,
    bool skipAutoEvaluation = false,
    CancellationToken cancellationToken = default)
    -> Task<SlideStreamingGenerationResult>
```

`SlideGenerationPipeline` 提供同名入口并与现有流式状态初始化代码复用同一个私有核心方法。现有 `SendMessageAsync` 签名、返回类型和行为保持兼容：当 `useStreaming = true` 时调用同一核心方法但忽略返回结果；当 `useStreaming = false` 时完全不接收、不处理新的预加载图片参数。

`StreamingSlideGenerator.GenerateAsync` 改为返回 `Task<SlideStreamingGenerationResult>`，并新增 `IReadOnlyList<DataContent>? attachedImageContents` 参数。`attachedImageFiles` 和 `requiredAttachedImageFiles` 继续服务旧调用方；同一次底层调用中如果预加载内容与文件路径同时非空，则按“预加载内容在前、文件内容在后”的顺序合并。课件工作台只传预加载内容，不混用两种来源。

## 八、自然语言页面 Prompt Builder

### 8.1 接口形态

`ICoursewareSlidePromptBuilder` 保留 `PrepareSource`，将 `Build` 重命名为 `BuildInitialPrompt`。方法签名固定表达以下输入：

- `CoursewareSlidePromptSource source`；
- `int slideIndex`；
- `CoursewareSlideCanvas canvas`；
- `string userInstruction`；
- `CancellationToken cancellationToken`。

返回值直接使用 `string`。不再返回 Envelope 或 Builder 自己估算的 Token 数。

调用前置条件是当前页原始截图已经进入可见附件集合。Builder 本身不接收路径，也不检查文件。

### 8.2 Prompt 文本来源

Builder 只从以下来源读取内容：

| Prompt 分区 | 数据来源 |
| --- | --- |
| 用户补充要求 | 方法参数 `userInstruction` |
| 前一页 | `source.InputPackage.Slides[slideIndex - 1].MarkdownText` |
| 后一页 | `source.InputPackage.Slides[slideIndex + 1].MarkdownText` |
| 配色 | `source.Theme.ColorSuggestions` |
| 字体 | `source.Theme.Fonts` |
| 字号 | `source.Theme.FontSizeRules` |
| 整体视觉风格 | `source.Theme.Style` |
| 安全区比例 | `source.Theme.SafeArea` |
| 安全区像素 | 方法参数 `canvas` 与安全区比例 |
| 背景、间距与视觉效果 | `source.Theme.SpacingAndVisualEffects` |
| 版式原则 | `source.Theme.LayoutPrinciples` |
| 两份参考页 | `CoverPageSlideMl`、`ContentPageSlideMl` |
| 当前页 | `source.InputPackage.Slides[slideIndex].MarkdownText` |

不得读取或输出本地文件路径、附件显示名、运行时状态、页面 Warning 或独立资源列表。

### 8.3 文本模板

模板正文以最终提示词示例为基线，关键措辞和分区顺序保持稳定。实现时使用 `StringBuilder` 分段追加，避免通过 `string.Format` 或复杂占位符转义大段 Markdown 和 XML。

模板中的固定文本应集中在 Builder 内部的私有常量或私有追加方法中。它属于模型协议文本，不进入 UI 本地化资源；错误信息和界面状态仍进入资源文件。

### 8.4 完整 Markdown 与动态围栏

当前页、前一页和后一页 Markdown 必须逐字追加：

- 不调用 `Trim`、`TrimEnd`；
- 不替换换行；
- 不 JSON 转义；
- 不摘要；
- 不截断；
- 不删除看似命令的文本。

每份 Markdown 分别计算最长连续反引号。外层围栏长度使用：

```text
max(4, 当前内容最长连续反引号数量 + 1)
```

三份 Markdown 独立计算，不能共用当前页围栏。

无前页或无后页时，在对应分区写“无”，不输出空代码块、`null` 或虚构摘要。

### 8.5 参考 SlideML

两份参考 SlideML 使用完整原文：

- 不 JSON 转义；
- 不解析后重新序列化；
- 不删除 XML 声明；
- 不做坐标缩放；
- 不从参考页推导当前页固定类型；
- 代码块带 `xml` 语言标记。

为了防止参考 XML 的文本节点中出现反引号破坏边界，可以复用围栏计算助手，但语言标记仍为 `xml`。

### 8.6 安全区像素

使用页面 `CoursewareSlideCanvas.DocumentContext` 中已经统一取整后的像素画布，按以下规则计算：

```text
LeftPixels   = round(CanvasWidth  × LeftRatio)
RightPixels  = round(CanvasWidth  × RightRatio)
TopPixels    = round(CanvasHeight × TopRatio)
BottomPixels = round(CanvasHeight × BottomRatio)
```

舍入方式与 `CoursewareCanvasAdapter` 保持一致，使用 `MidpointRounding.AwayFromZero`。

Prompt 同时输出：

- 比例格式：百分比，最多保留两位小数；
- 像素格式：整数 `px`。

比例格式使用 `CultureInfo.InvariantCulture` 和稳定的 `0.##` 数字格式，再显式追加 `%`。不重新从 Markdown 中解析画布尺寸，也不使用原始 `double` 逻辑尺寸重复换算。

### 8.7 颜色输出

颜色按 Theme 中的稳定顺序逐项输出：

```text
- 名称：#RRGGBB；用途：用途原文
```

不排序、不合并、不改写颜色用途。

### 8.8 不再生成的内容

- `CoursewareSlideGenerationTask`；
- `CoursewareSlideGenerationPage`；
- `CoursewareSlideNeighborSummary`；
- `CoursewareSlideVisualInput`；
- `CoursewareSlideOutputRequirements`；

## 九、工作台草稿与发送改造

### 9.1 首轮草稿准备

`PrepareInitialDraft` 调整为以下顺序：

1. 若页面已建立会话，直接返回；
2. 若草稿已被用户编辑，直接返回；
3. 若草稿已准备且不要求刷新，直接返回；
4. 调用 `EnsureSourceScreenshotAttachment`；
5. 截图不存在时设置明确错误和截图状态，不构建声称已附截图的 Prompt；
6. 使用当前 `_promptSource`、页面索引、页面 `Canvas` 和默认用户要求构建自然语言 Prompt；
7. 调用 `ApplyInitialPrompt`；
8. 清除主题过期标记。

默认用户要求改为最终示例中的文本：

> 请根据当前页完整内容、可用视觉附件和全课件主题完成页面美化，保持教学语义准确、信息完整、层级清晰，并确保所有内容适合当前画布。

### 9.2 首轮发送不再构建 Prompt

删除 `SendPageMessageAsync` 中以下逻辑：

- 根据 `IsInitialPromptDirty` 选择默认要求或 `snapshot.Message`；
- 调用 `_promptBuilder.Build(...)`；
- `ApplyInitialPrompt`；
- 重新创建发送快照。

发送方法从创建快照开始，全程只使用该快照。

### 9.3 首轮快照校验

新增私有校验边界，首轮至少检查：

- `snapshot.Message` 非空白；
- `snapshot.Attachments` 中存在一个 `SourceScreenshot`；
- 该附件 `IsAvailable` 为 `true`；
- 其余附件也都存在；
- 页面没有未重新渲染的手工 SlideML 修改。

若首轮缺少原始截图，不调用 `EnsureRuntimeAsync`、预算校验或模型发送。

预检只能改善错误反馈，真正的发送快照由预加载结果确定。新增 `CoursewareImageAttachmentLoader`，首轮和续轮都按 `snapshot.Attachments` 顺序执行：

1. 使用 `FileStream` 异步读取完整字节；
2. 在 WPF STA 调度器上通过 `BitmapDecoder.Create(..., BitmapCacheOption.OnLoad)` 解码；
3. 要求 `Frames.Count > 0`；
4. 优先读取 `decoder.CodecInfo.MimeTypes` 取得实际图片媒体类型；标准解码器无法提供媒体类型时，再按已允许扩展名映射；
5. 使用原始字节和确认后的 `image/*` 媒体类型创建 `DataContent`；
6. 任一步失败即停止准备请求，不清理会话、不重置渲染、不调用模型。

允许的扩展名与文件选择器一致：`.png`、`.jpg`、`.jpeg`、`.bmp`、`.gif`、`.webp`。实际支持能力以当前 Windows WIC 解码器为准；例如系统不能解码 WebP 时，显示该附件不可解码并阻断发送。错误只显示附件 `DisplayName`，不得回显绝对路径。

### 9.4 原始截图不可移除

在 `CoursewareChatImageAttachmentViewModel` 增加只读属性，例如 `CanRemove`，当附件类型是 `SourceScreenshot` 时为 `false`。

`CoursewareSlideItemViewModel.RemoveAttachedImageFile` 也要进行服务端式保护：即使 UI 错误调用，也不得在首轮成功前删除原始截图。不能只依赖按钮禁用。

`CopilotPanel.xaml` 中原始截图的关闭按钮使用 `CanRemove` 绑定折叠；用户选择的图片保持可移除。

### 9.5 主题草稿过期状态

`CoursewareSlideItemViewModel` 新增：

- `bool IsInitialPromptThemeOutdated`；
- `ResetInitialPromptToLatestThemeCommand`；
- 对应用户可见状态文本和按钮可见性。

`UpdateThemeAnalysisResult` 在替换 `_promptSource` 后遍历页面：

- 未开始且已准备、未编辑：立即强制重建；
- 未开始且已编辑：设置过期标记；
- 未准备：等待首次访问；
- 已开始：不改草稿和会话。

重建使用页面当前 `Canvas` 和仍可见的原始截图。若截图在主题更新期间已经丢失，页面进入不可发送状态，不生成错误声明。

用户点击 `ResetInitialPromptToLatestThemeCommand` 时，使用最新 `_promptSource` 强制调用 `BuildInitialPrompt`，覆盖当前首轮草稿、更新草稿修订号并清除 dirty 与过期标记。该命令在页面忙碌、会话已建立或原始截图不可用时禁用。

### 9.6 成功清理规则

继续复用 `DraftRevision` 防止发送期间的新输入被成功回调清除。

`ApplySuccessfulSend` 保持以下语义：

- 只有当前文本仍与快照匹配时清空输入；
- 移除快照中的已发送附件；
- 首轮成功后设置 `HasStartedGenerationConversation = true`；
- 清除首轮 dirty 和主题过期标记。

首轮成功后将 `ScreenshotAttachmentState` 设为新增的 `Sent`，界面显示“原始截图已随首轮发送”。不得继续显示“截图已附带”却同时从附件集合移除截图。

如果用户在发送期间添加了新附件，新附件不属于快照，成功回调不得移除。

### 9.7 首轮请求结果新鲜度

每次首轮发送在进入模型请求前执行以下顺序：

1. 将发送快照中的全部文件附件通过 `CoursewareImageAttachmentLoader` 验证并预加载为 `DataContent`；
2. 从现有渲染快照捕获用户勾选的“当前渲染预览”；
3. 调用 `SlideMlRenderTool.ResetLatestResultAsync()` 清空 `LatestSlideXml`、`LatestRenderedXml`、Warning 和预览；
4. 以新会话或已清理的失败会话开始流式请求，并附加已经捕获的图片内容；
5. 根据 `SlideStreamingGenerationResult` 判断最终成功；失败时不调用 `ApplySuccessfulSend`。

该机制解决第一次请求生成过页面后取消或失败、第二次请求没有新输出却误用旧 XML 的问题。对已建立会话的普通追问不清空当前页面结果。

### 9.8 输入区域可用性

首轮自然语言 Prompt 显著长于普通追问。`CopilotPanel.xaml` 应通过样式或触发器让首轮编辑区具有更大的可视高度；首轮成功后恢复普通追问高度。

该改动只调整编辑体验，不引入新的 Prompt 查看器或第二份只读文本。

## 十、课件专用流式 Prompt 配置

### 10.1 工厂改造

`SlideChatManagerFactory` 创建页面运行时时：

1. 使用页面实际 `SlideDocumentContext` 创建 `SlideMlPromptProvider`；
2. 通过 `UpdatePrompts` 只覆盖 `streamingUserPromptTemplate`；
3. 模板值为 `{USER_INPUT}`；
4. 将该 Provider 显式传给 `SlideChatManager`；
5. fallback manager 使用同样配置。

正常运行时和 fallback 必须使用同一 Prompt 行为，避免模型恢复后出现不同首轮包装。

课件工作台继续不暴露 `PromptIterationPipeline`。`SlideChatManagerFactory` 不再创建或传入 `AiPromptOptimizer`，因此页面运行时 `CanRunIteration` 为 `false`，公开的 `RunPromptIterationAsync` 直接返回 `null`，形成技术边界。保留 `AiSlideEvaluator` 和 `AiPromptEvaluator`。后续若接入迭代，先实现不可被临时重置覆盖的课件基线模板，再恢复 Optimizer 注入并增加流式集成测试。

### 10.2 不修改的通用能力

以下内容保持在 `PptxGenerator.Core`：

- `BuildDefaultStreamingSystemPrompt`；
- 完整 SlideML 标签和属性规范；
- 流式片段与合并规则；
- `get_slide_state`、`get_slide_preview`；
- 渲染错误反馈和重试；
- 通用 Demo 的默认流式用户建议。

本次不修改 `ISlideMlPromptProvider` 接口。

### 10.3 上下文预算

`CoursewareSlideContextBudgetValidator` 继续调用页面运行时的实际 `PromptProvider`：

- System Prompt Token 使用实际课件页面 System Prompt；
- User Prompt Token 使用原样流式包装后的自然语言 Prompt；
- 工具 Schema、输出预留和 5% 安全余量保持现状；
- 超预算时不截断当前页、相邻页、主题规则或参考 SlideML。

`CoursewareSlidePromptBuildResult.EstimatedTokenCount` 删除后，预算校验成为唯一权威来源。

当前模型配置没有公开可靠的图片 Token 换算规则，因此不编造固定图片 Token。图片在发送前全部预加载为同一请求的内存内容，模型服务端仍负责最终多模态上下文限制。

自动测试通过后，选择以下真实页面各执行至少一次首轮生成：

- 封面页；
- 章节页；
- 普通内容页；
- 练习题页；
- 图文页；
- 内容密集页；
- 内容较少页。

逐页确认：

1. 模型直接执行页面任务，不解释 JSON 或复述 Prompt。
2. 模型能区分当前页、相邻页和参考页。
3. 模型不把相邻页文本复制到当前页。
4. 模型不把参考 SlideML 的示例文字当成当前页内容。
5. 模型不虚构 `image_001` 或 Markdown 未提供的资源 ID。
6. 模型不因通用包装强制生成浅色主题。
7. 模型保留题目、选项、答案关系、专有名词、数字和符号。
8. 模型根据实际画布和安全区组织页面。
9. 模型使用 `get_slide_state` 检查实际尺寸、位置、行数和警告。
10. 最终合并状态是一张完整可渲染的 `Page`。

若模型仍出现稳定的误解，优先修正页面业务 Prompt 的固定措辞或 Theme 原文质量；不要在业务 Prompt 中复制整套 SlideML Schema。

## 十五、错误处理与用户提示

### 15.1 原始截图缺失

用户提示应明确表达：当前页缺少首轮页面美化所需的原始截图，不能发送声称包含截图的任务。页面仍可查看 Markdown、编辑已有 SlideML 或使用本地重新渲染能力。

### 15.2 原始截图在发送前丢失

保持草稿，不清空附件集合。发送前发现文件不存在时设为 `FileMissing`；文件存在但截图自身加载或加入请求失败时设为 `SendFailed`。用户修复文件后可重试。

### 15.3 截图状态与错误归因

| 事件 | 截图状态 |
| --- | --- |
| 尚未准备 | `NotPrepared` |
| 已进入待发附件且文件可用 | `Attached` |
| 文件不存在 | `FileMissing` |
| 截图自身加载或加入请求失败 | `SendFailed` |
| 首轮成功 | `Sent` |
| 上下文超预算 | 保持 `Attached` |
| 用户补充附件失败 | 保持 `Attached` |
| 模型请求失败或取消 | 保持 `Attached` |

只有截图自身失败才设置 `SendFailed`。不能把所有首轮异常统一归因到截图。

### 15.4 上下文超预算

错误继续包含模型名、上下文窗口、System Prompt、User Prompt、工具 Schema、输出预留和安全余量。提示用户切换更大上下文模型；不建议删除当前页、相邻页、Theme 或参考 SlideML 的部分内容后静默发送。

### 15.5 主题草稿过期

已编辑首轮草稿不自动覆盖。界面提示当前草稿基于旧主题；用户可以继续发送当前草稿，或点击“按最新主题重建草稿”显式覆盖当前编辑内容。页面已建立会话后不提供重建操作。

### 15.6 模型不可用

保持现有 fallback：AI 发送禁用，但同画布本地重新渲染仍可使用。Prompt 草稿准备不依赖模型初始化成功。
