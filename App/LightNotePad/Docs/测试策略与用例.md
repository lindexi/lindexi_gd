## 二、测试目标与范围

### 2.1 测试目标

验证 LightNotePad v1.1 的 **16 项功能需求（F01-F15 + F15.5 触屏交互增强）** 全部按预期实现，确保：

1. **功能完整性**：所有 P0/P1/P2 功能均符合需求文档规格
2. **稳定性**：异常路径不崩溃、不丢数据
3. **对标一致性**：关键行为与 Windows 记事本保持一致
4. **性能达标**：冷启动、文件打开、编辑响应、内存占用满足基线要求
5. **触屏体验**：单/双指滚动、选择柄、气泡菜单、放大镜符合触屏交互预期

### 2.2 测试范围

## 五、关键决策速查（D01-D07）

> 以下决策贯穿全部测试用例，测试时必须以此为准。

| 编号 | 决策 | 详细说明 |
|------|------|----------|
| **D01** | 保存编码 = UTF-8 无 BOM | 用 `new UTF8Encoding(false)` 验证写入文件的前 3 字节不是 BOM（`EF BB BF`） |
| **D02** | 状态栏行列号 = **逻辑行** | Tab 算 1 字符，CJK（中文/日文/韩文）算 1 字符；自动换行时视觉折行不改变行号 |
| **D03** | 默认换行 = 自动换行 | 应用启动后自动换行为开启状态 |
| **D04** | 对标 = Windows 记事本 | 行为不一致时优先对齐 Windows 记事本 |
| **D05** | 不做：拖拽选中文本 | — |
| **D06** | 不做：超大文件特殊处理 | — |
| **D07** | 不做：Ctrl+滚轮缩放 | 字体大小只能通过设置界面修改 |

## 十、边界提示与后续建议

### 10.1 测试优先级策略

| 阶段 | 优先级 | 覆盖用例数 | 目标 |
|------|--------|-----------|------|
| M1 验收 | P0 | ~45 条 | 核心闭环 100% 通过 |
| M2 验收 | P0+P1 | ~73 条 | 全功能 ≥ 98% 通过 |
| M3 验收 | P0+P1+P2 | ~84 条 | 全量 ≥ 95% 通过 + 性能基线达标 |

### 10.2 风险提示

1. **编码 fallback 风险**：GBK/ANSI 无 BOM 文件，.NET `StreamReader` 默认 fallback 到 UTF-8 可能导致乱码（TC-F11-06），建议在 M2 阶段评估是否需要引入编码探测库（如 `UtfUnknown`）
2. **大文件风险**：D01（100MB+）不在首版范围但需确认不崩溃，至少应做一次冒烟
3. **撤销栈深度**：LightTextEditorPlus 底层栈深度未在需求中明确，测试时需观察实际极限
4. **多文件拖拽行为**：TC-F07-07 需与产品确认最终策略（打开第一个 / 全部打开 / 忽略）

### 10.3 后续版本建议

- 增加自动化 UI 测试覆盖（如 Avalonia UI Test）
- 建立性能基准 CI 流水线
- 引入模糊测试（Fuzzing）覆盖文件打开路径
- 增加无障碍（Accessibility）测试
