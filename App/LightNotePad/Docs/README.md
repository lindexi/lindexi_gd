## 🚀 开发阶段文档引用指南

### 编程助手开发顺序

```
Step 1 → 读需求分析 v1.0（明确做什么）
   ↓
Step 2 → 读产品规划（明确任务编号 T01-T56）
   ↓
Step 3 → 读代码审查基线（明确怎么写）
   ↓
Step 4 → 读测试策略与用例（明确测试要求）
   ↓
Step 5 → 读决策记录（明确为什么这么做）
```

### 测试工程师测试顺序

```
Step 1 → 读需求分析 v1.0（明确 AC01-AC15）
   ↓
Step 2 → 读产品规划（明确里程碑 M1/M2/M3）
   ↓
Step 3 → 读测试策略与用例（执行用例）
   ↓
Step 4 → 对照代码审查基线（验收代码质量）
```

### 代码审查员审查顺序

```
Step 1 → 读代码审查基线（明确审查标准）
   ↓

   ↓
Step 3 → 读决策记录（理解设计取舍）
   ↓
Step 4 → 按 checklist 逐项审查代码
```

## 🔄 文档维护规则

### 版本管理
- 需求变更 → 更新 `需求分析文档_v1.0.md`，版本升至 v1.1/v2.0
- 任务调整 → 更新 `产品规划文档.md`，记录任务变更原因
- 新增功能 → 在 `需求分析文档` 增加 F16+，同步更新 `产品规划` 和 `测试策略`

### 文档同步要求
- 需求变更必须同步更新：产品规划 + 测试用例 + AC 映射
- 决策变更必须同步更新：决策记录 + 对应测试用例
- 代码实现必须可追溯：T 编号 → F 编号 → AC 编号
