# LightNotePad 需求分析文档 v1.0（定稿）

> **版本历史**：
> - v0.1：初稿，基于用户第一轮需求对齐
> - v0.2：确认"默认自动换行"，新增 AC15
> - **v1.0：定稿**——确认默认保存编码 UTF-8 无 BOM；明确状态栏行列号为逻辑行语义（Tab/CJK 各算 1 字符）

---

## 一、需求概述

### 1.1 需求背景
当前项目已有基于 Avalonia 12.0 + .NET 10.0 的桌面应用框架，以及功能完备的 LightTextEditorPlus 文本编辑器核心库。需要在此基础上构建一款面向普通用户的极简记事本软件。

### 1.2 落地目标
打造一个对标 **Windows 自带记事本** 的纯文本阅读/编辑工具——阅读优先、编辑够用、零学习成本。

### 1.3 业务价值
- 为普通用户提供一个轻量、快速、无干扰的纯文本查看和编辑工具
- 作为 LightTextEditorPlus 库的落地应用，验证核心库能力

## 四、核心功能需求

### 4.1 文本阅读与渲染（F01）
- **规则**：使用 LightTextEditorPlus 渲染纯文本内容
- **体验原则**：阅读优先，渲染清晰、响应快速
- **自动换行**：默认开启自动换行，文本自动折行显示

### 4.2 文本编辑（F02）
- **触发条件**：用户点击文本区域开始输入
- **操作流程**：直接在光标位置输入/删除文字
- **规则**：纯文本输入，无格式化工具栏

### 4.3 撤销/重做（F03）
- **触发**：Ctrl+Z 撤销，Ctrl+Y 重做
- **规则**：由 LightTextEditorPlus 底层提供，应用层直接调用
- **边界**：撤销栈深度由底层库决定，不做额外限制

### 4.4 复制/粘贴/剪切（F04）
- **触发方式**：
  - 快捷键：Ctrl+C 复制、Ctrl+V 粘贴、Ctrl+X 剪切
  - 右键菜单：提供复制、粘贴、剪切选项
- **规则**：与系统剪贴板交互，粘贴时只保留纯文本
- **异常处理**：剪贴板为空时粘贴操作无效（不报错）

### 4.5 全选（F05）
- **触发**：Ctrl+A
- **规则**：选中全部文本内容

### 4.6 查找/替换（F06）
- **触发**：Ctrl+F 打开查找、Ctrl+H 打开替换
- **查找功能**：
  - 输入关键词，高亮所有匹配项
  - 支持 F3 / Shift+F3 跳到下一个/上一个匹配
  - 查找框关闭后高亮消失
- **替换功能**：
  - 支持「替换」单个 和「全部替换」
  - 替换后自动跳到下一个匹配项

### 4.7 文件打开（F07）
- **方式一：菜单打开**
  - 文件 → 打开 → 系统文件对话框
  - 文件类型过滤器：`所有文件 (*.*)`，不限制扩展名
- **方式二：拖拽打开**
  - 从系统文件管理器拖拽任意文件到窗口 → 打开该文件
- **编码规则**：使用 .NET 自带编码能力（StreamReader 默认检测 BOM，无 BOM 则 UTF-8）

### 4.8 保存/另存为（F08）
- **保存（Ctrl+S）**：
  - 文件已有路径 → 直接覆盖保存
  - 新建文件无路径 → 弹出另存为对话框
- **另存为**：
  - 菜单触发 → 系统保存对话框
  - 支持选择目标路径和文件名
- **编码**：**UTF-8 无 BOM**（`new UTF8Encoding(false)`）

### 4.9 关闭未保存提示（F09）
- **触发条件**：文档有修改且未保存，用户关闭窗口
- **交互流程**：
  1. 弹出对话框："是否将更改保存到 {文件名}？"
  2. 三个按钮：保存 / 不保存 / 取消
  3. 保存 → 执行保存后关闭
  4. 不保存 → 直接关闭，丢弃修改
  5. 取消 → 回到编辑界面

### 4.10 窗口标题（F10）
- **规则**：
  - 有文件路径：`{文件名} - LightNotePad`
  - 新建未保存：`未命名 - LightNotePad`
- **更新时机**：文件打开/保存/另存为后立即更新
- **修改标记**：有未保存修改时标题前加 `*`（如 `*test.txt - LightNotePad`）

### 4.11 状态栏（F13）
- **位置**：窗口底部
- **显示内容**：
  - 行号（Ln）：当前光标所在**逻辑行**（源文件行），从 1 开始
  - 列号（Col）：当前逻辑行内的**字符位置**，从 1 开始
- **行列号计算规则**：
  - Tab 字符算 **1 个字符**
  - CJK 字符（中文/日文/韩文）算 **1 个字符**
  - 与 Windows 记事本行为一致
- **自动换行场景**：即使视觉折成多行，行号始终为逻辑行号（不按视觉行变化）
- **更新时机**：光标移动时实时更新

### 4.12 字体设置（F14）
- **位置**：设置界面（菜单 → 设置 或 工具 → 选项）
- **可配置项**：
  - 字体名称（从系统字体列表选择）
  - 字体大小（数值输入）
- **默认值**：系统等宽字体，如 Consolas 或微软雅黑，字号 12pt
- **生效**：确认后立即生效，设置持久化保存

### 4.13 触摸滚动（F15）
- **触发**：触摸屏单指滑动
- **规则**：垂直和水平滚动文本内容
- **兼容**：也支持鼠标滚轮和触控板滚动

## 五、非功能需求

### 5.1 性能

| 指标 | 要求 |
|------|------|
| 启动时间 | 冷启动 < 2 秒 |
| 文件打开 | 常规大小（<1MB）文件打开 < 500ms |
| 编辑响应 | 键盘输入到屏幕显示 < 50ms（无感知延迟） |
| 内存占用 | 空载 < 50MB，打开 1MB 文件 < 100MB |

### 5.2 兼容性

| 维度 | 要求 |
|------|------|
| 操作系统 | Windows 10 1809+ / Windows 11 |
| 架构 | x64 优先 |
| .NET 版本 | .NET 10.0 |

### 5.3 安全性
- 不联网，无网络权限需求
- 文件读写仅限用户主动操作触发的路径
- 粘贴内容过滤：仅接受纯文本，拒绝富文本/二进制/脚本注入

### 5.4 易用性
- 菜单栏结构清晰，符合 Windows 记事本习惯
- 常用操作均提供快捷键
- 状态栏信息直观

## 八、决策记录

> 本章节记录需求分析过程中的关键决策及其理由，供后续维护参考。

| 编号 | 决策点 | 选定方案 | 备选方案 | 决策理由 |
|------|--------|----------|----------|----------|
| D01 | 默认保存编码 | UTF-8 无 BOM | UTF-8 with BOM / 系统 ANSI | 现代标准，跨平台友好，避免乱码 |
| D02 | 状态栏行列号语义 | 逻辑行 | 视觉行 | 与 Windows 记事本一致；与查找替换、撤销栈的"行"概念统一 |
| D02a | Tab 字符列号 | 算 1 字符 | 展开为 4/8 字符位 | Windows 记事本做法，实现简单 |
| D02b | CJK 字符列号 | 算 1 字符 | 算 2 显示宽度位 | Windows 记事本做法，杜绝歧义 |
| D03 | 默认换行行为 | 自动换行 | 不自动换行（横向滚动） | 用户拍板确认；LightTextEditorPlus 已实现，零成本 |
| D04 | 对标产品 | Windows 记事本 | Notepad++ / VS Code 简化版 | 用户明确要求极简纯文本 |
| D05 | 拖拽选中文本 | 不做 | — | 用户明确不要 |
| D06 | 字体缩放方式 | 设置界面统一设置 | Ctrl+滚轮实时缩放 | 用户明确不要快捷键缩放 |
| D07 | 超大文件 | 不做特殊处理 | 分块加载/懒加载 | 用户明确不管，让文本库自己加载 |
