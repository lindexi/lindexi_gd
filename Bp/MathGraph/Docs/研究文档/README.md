# 研究文档写作约束

本目录面向研讨会与后续论文写作。`研究文档.md` 是主文档，存放背景、导入与各研究方向的摘要。以下约束对主文档及本目录下所有独立方向文档同时生效。

## 与过程文档完全隔离

本目录是完整的研究文档，自成体系，与仓库内的探索过程文档互不隶属。

- 过程文档指编号的过程记录、实验记录、实现状态记录等，它们随研究推进增删改写。
- 本目录内的文档不引用、不链接、不复述、不合并任何过程文档。
- 过程文档的改写、重命名、删除，不得造成本目录任何文字需要同步修改。
- 两边不存在“上游/下游”关系，也不建立任何目录层级或索引上的关联。

## 只写已知，不写待办

研究文档是对外输出物，承载的是**当前已经知道的内容和已经做过的工作**。

- 已经确认的结论、已经验证的规则、已经得到的计数，写进来。
- 尚未确认的判断、待验证的方向、下一步计划、TODO、“还没试过”“留待以后”“这里先不展开”这类表述，一律不进研究文档，放进过程文档。
- 不声明没有做的事。不写“未验证”“没有实例”“管不到”“尚未尝试”这类句子：论文只陈述做了什么、得到什么，不列举缺口。
- 结论附带的成立条件必须与结论同句说完，用途是把话说准，不是预告别处还有什么。
- 不设“遗留问题”“待办”“后续工作”一类章节。研究文档里出现的每一句，都应当是现在就能站住的陈述。
- 读者读到的应当是确定的知识，不是作者的工作笔记。不确定的东西留在自己那边，确认之后再进来。

## 读者与定位

- 主文档写给外部读者，是研讨会的导读材料，承担“背景 + 分岔清单”。
- 语气介于正式与非正式之间。背景与导入章节必须平铺、可读，不追求学术腔，不因术语堆砌降低可读性。
- 后续方向章节可以逐步收紧；最终整理成论文时再切换到严格表述，论文不复用主文档的口语。

## 只写对外内容

- 不写聊天记录、讨论过程、修改说明、写作约束等元信息。
- 不写“本文档是什么”“怎么读这份文档”这类说明书式段落。
- 不出现“当前工作区”“本次改动”“首版”“最小验证”这类内部或把研究封口的措辞。
- 不使用“常被忽略”“被人忽视”这类抬高自身说法的方式引出论点。

## 论证顺序

- 先陈述现象、想法与已有工作，再谈局限与定位。
- 自我定位、等价性说明、局限声明放在正文之后，不在开头就下负面结论，避免读者在接触到任何观点前先得到否定判断。
- 可以承认等价性与学术边界，但表述为事实陈述，不写成自我否定。

## 便于持续追加

主文档会不断追加内容，结构必须支持“只加不改”。

- 研究内容一律条目式：新增一项，追加一行或一节，不需要回头修改任何已有句子。
- 不写“投入最多的部分”“N 项工作”“N 个方案”“目前只有几种”这类会随追加而失效的数量或排序表述。
- 不写具体项目名、目录名、分支名作为进度依据；进度变化不应造成主文档返工。用于代码定位的仓库链接不受此限。
- 章节标题不带“一、二、三”等序号，避免插入新章节时连带改号。

## 分工与拆分

- 背景、导入：叙事为主，允许第一人称，按事件顺序推进。
- 研究内容：先说明问题，再列方向与已掌握的结论，最后列剩余分岔。
- 某个方向会长期研究时，独立成篇，主文档只保留一句话摘要与链接，细节不进主文档。
- 已确认的结论写进对应章节；未确认的写明不确定在哪里，不假装已经解决。

## 代码引用

研究文档里的结论必须有代码支撑，引用方式统一为固定 commit 的仓库链接。

- 统一格式：`https://github.com/lindexi/lindexi_gd/tree/{CommitId}/Bp/MathGraph/<相对路径>`
- `{CommitId}` 指该文档所依据代码的提交号，各篇文档可以不同，不与某一篇绑定。
- `<相对路径>` 以仓库中的 `MathGraph/MathGraph/` 为基准。例如 `Code/MathTest/MathGraph.ReversibleFractal.Wpf`。
- 链接内写具体提交号，不用分支名或 `latest`，保证任何时刻点开都对应文档所述内容。
- 代码链接放在文末或靠后的位置，一处即可；正文不贴代码细节。读者具备基础，链接足以自证。
- 同一份文档引用多处代码时，可按章节重复出现，但格式保持一致。

## 事实核对

- 引用外部研究时给出链接；数字以可查来源为准。
- 与来源存在出入但不影响论述的细节，按来源稳妥表述，不在正文中争论。
