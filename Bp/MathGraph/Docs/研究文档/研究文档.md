# 研究文档

## 背景

### 一个 2015 年的下午

2015 年，我的老师让子凯师兄去探索一个方向。听老师说，那是他的老师交给他的课题。具体细节我记不清，大意是这个方向研究的人很少。

我那时只是好奇，旁听了一部分。听完脑子里冒出一些想法，画了下来，拿去给师兄看。他说看懂了。

我总觉得他没完全看懂。

这个感觉没有证据，也没影响什么，就是一直留着——连同当时我没能讲清楚的几个问题。后来我管这些叫“乌云”。

写这篇文档的时候已经是 2026 年了。十一年过去，这几朵乌云我还在想。这份文档讲的是其中一朵。

### 图是固定的，还是可以变的

现在的神经网络，绝大部分都是固定图；也有从一开始就走全连接图的。

这两种在规模上其实是一回事。全连接图只要让某些节点传入 0 参数，就等于把连接断开，最终仍然得到一个任意形状的连接图。反过来说，任何能承受的图规模，都能塞进一张全连接图里表示。

那么，“一张会变化的图”和“一张早就固定好的图”，差别在哪里？

在计算量和内存不受限制的前提下，两者是等价的——一张会变的图，总能被展开成一张同规模、甚至更大规模的全连接图。

所以真正值得追问的不是“能不能表示”，而是“为什么要让它变”。这个问题我放到后面再说。

### 那朵乌云：图能有多大

我脑子里一直在转神经网络里的“图”这件事，转到一个地方卡住了：**一张图能有多大？**

如果认真问下去，答案可以是“无限”。

真正把我推过去的不是数学书，是一段 C# 代码。

### 一个 C# 里的无限集合

C# 有 `yield return`。方法体里写一个 `while (true)`，它就返回一个无限集合：

```csharp
IEnumerable<int> AllNaturalNumbers()
{
    var i = 0;
    while (true)
    {
        yield return i++;
    }
}
```

这段代码可以跑在一个内存以 KB 计的进程里，但集合是无限大的。

它没骗人。你要一个，它才算一个；你不要，它就停在原地。时间成了它的维度。

我看到这段代码的时候被激了一下：**集合能这么写，图能不能也这么画？**

### 超点

于是一张图能有多大？

它可以是任意规模，甚至无限。你看到的那几个点，只是露在水面上的那一层。

先拿一个最小的例子把机制说清楚：一张图上画几个点，你觉得它就这么大。

不是。它是无限大的。画出来的每个点都是**超点**：一个点，里面装着另一张图；那张图里的点，还是超点。一直往里看，永远看不到底。

所以如果有人问，只统计最终叶子节点有多少个——答案是无穷。

这里要说明一件事：**画面上放几个点，只是为了让机制看得见，不是说这套东西只能这么小。** 规模本来就可以任意大，一个点也可以展开成十几、几十个子点，模板也不必只有一种。之所以画面上只留很少几个，是因为再多，图就变成一团线，除了机器没人愿意看第二眼。分形的性质不依赖规模大小，小规模就能把“点里面有图，图里还有图”这件事展示清楚。

到这儿，其实什么都还没做。它只是个设定，一种“图可以无限”的表示法。

真正的问题从下一句开始：**无穷的东西没法一次性展开。**

叶子有无穷多个，内存放不下，你只能一点一点取出来。于是“什么时候取、取哪一个”成了绕不开的第一道题。

### 一条旁证：果蝇的连接图

光有拓扑，说话的底气还不够。

2026 年 9 月，谷歌和 HHMI Janelia 等合作发布了一张完整的雄性果蝇大脑与中枢神经系统连接图——超过 16.6 万个神经元、1.25 亿个突触连接，发表在 Cell 上。链接在这里：

<https://research.google/blog/a-connectomics-milestone-mapping-the-complete-male-fruit-fly-brain/>

这件事对我的意义不在神经科学本身，而在于它说明：**“谁和谁连”这件事本身携带信息。** 一只果蝇能飞、能找路、能记住东西，而它被完整描述出来的时候，描述的主体就是一张连接图。

但它同时提醒我另一半：那张图里，每个神经元自己也是要干活的。所以第二个问题也跑不掉——**超点里装什么。**

## 研究内容

### 分形是怎么分的

一次展开，一个点变成什么？这条线上已经成形的两套规则如下，各自独立成篇。

**五点分形与 I/O 适配点**：核心固定五个点，被替换的叶如果入度或出度对不上，就额外插入真实的 I、O 适配点，把单路拆成双路。这样任何签名的点都能展开，代价是 1 入 2 出的点要多带两个点。详见 [五点分形与IO适配点.md](五点分形与IO适配点.md)。

**可逆五点分形**：发现把六条内部边整体反向，2 入 1 出就变成 1 入 2 出，两套模板互为正反。于是按签名选方向就能直接展开，不需要适配点，每个模板严格五个真实点。详见 [可逆五点分形.md](可逆五点分形.md)。

两套方案共用的部分：端口有序，模块边界递归解析到真实叶端口，不按路径或编号排序；展开和收起都是实时的拓扑修改，先构建候选状态，成功后再整体提交。

围绕这套规则，已经展开的工作如下，每一条独立成篇：

- 端口算子的定义，以及它的前向与反向传播
- 展开前后两个图的函数关系：能不能保持，在什么条件下能保持
- 展开后新增支路能不能拿到梯度、会不会学得动
- 展开位置的选择：随机、按信号、还是按某种规则

（新增的研究直接往下加一条，不影响上面任何内容。）

### 什么时候、对哪个点进化

这是主线问题，至少分三层，层与层之间是组合关系，不是单选。

**什么时候展开**

- 训练前定死：一次展开到指定深度，之后不动
- 训练中定时：每隔固定步数展开一批
- 训练中按信号：损失停滞、梯度饱和，或者某个点的输入已经复杂到单个算子吃不下
- 纯随机

**展开哪个点**

- 随机挑一个合法叶
- 按路径轮转，保证覆盖
- 按梯度大小排序
- 按该点对误差的贡献排序
- 按不确定性排序

**长了以后留不留**

- 看验证集门槛
- 看等算力对齐下谁更划算

第二层看起来像结构搜索的老问题，但分形给它加了一层特殊结构：因为规则是递归同构的，要决定的不是“连哪条边”，而是“在哪条路径上再长一层”。搜索空间天然是一棵树。

### 算子怎么放

**全图统一一套算子**——这条可以放下。激活函数混用并不会给反向传播添麻烦，统一也就没有必要。只做记录，不深入。

**各点各用算子**——这才是分岔的起点，往下还有几支：

- **用什么算子**：候选池有多大？要不要引入现成的算子集当原子候选？
- **算子内部是什么**：真的只是一个原子运算？还是它自己也是一张图？如果超点里的点也是超点，那“算子”和“图”其实是同一件东西的两层，最底层才是原子算子。
- **怎么分配**：固定模板按角色分？按入出度分？按深度分？还是干脆随机，让训练自己去挑？

关于算子我有个判断：**算子选择重要，但它不是这个结构的关键点。** 结构的关键在“何时、何处生长”；算子更像填充物，填充物的好坏会影响结果，但它不决定这条路能不能成立。所以这个方向要投入，但不必当主战场。

## 关于这套东西的定位

写到这里，可以回头看开头那个问题了：一张会变化的图，和一张固定好的图，在算力和内存不受限时是等价的。既然如此，这件事的意义在哪？

从纯学术角度讲，这份文档记录的东西谈不上突破。它没有给出一个“固定图做不到、只有变化图能做到”的能力。

我觉得它有价值的地方只有两处：这条路线上的想法，以及做过的一些工作，能给后来的人当参考。

至于参考价值有多大，我不下结论。
