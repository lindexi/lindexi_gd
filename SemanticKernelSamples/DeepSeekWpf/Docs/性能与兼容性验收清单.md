# DeepSeek Workspace 性能与兼容性验收清单

> 状态：**待人工实测**。本文定义可重复步骤、目标和记录表，不表示任何项目已经通过。执行者必须填写环境、原始结果和结论；未执行项保持“待测”。

## 1. 测试原则

- 使用正式 Release、win-x64、framework-dependent 发布包。
- 首次测试前记录应用版本、提交/构建标识、Windows 版本、.NET Runtime、CPU、内存、磁盘、DPI、主题和网络。
- 性能项目至少执行 3 次；冷启动每次测试前结束进程并等待磁盘活动稳定。
- 首 token 测量必须使用同一模型、同一提示词、同一网络条件，并单独记录服务端波动。
- 内存记录使用相同工具和采样时点，建议记录工作集与专用字节。
- 发现失败时保留脱敏日志、诊断摘要和可复现数据规模，但不要保存或分享 Key、聊天正文。

## 3. 冷启动

### 步骤

1. 使用默认或明确记录的数据目录准备测试数据。
2. 退出应用，在任务管理器确认进程结束。
3. 等待 10 秒，确保没有发布目录扫描或会话复制任务。
4. 从启动 `DeepSeekWpf.exe` 开始计时。
5. 到主窗口可见、会话列表完成加载且可执行新建/搜索时停止计时。
6. 重复 3 次，分别记录无会话、典型会话和大量会话数据集。

### 目标

- 启动期间界面不出现长时间“未响应”。
- 单个损坏会话不阻止主界面加载。
- 目标时间由发布负责人在目标硬件上确认；本清单不预先宣称达标。

## 4. 首 token 时间

### 步骤

1. 使用有效真实账号、固定模型和稳定网络。
2. 新建空会话，使用固定短提示词。
3. 从触发发送开始计时。
4. reasoning 或 text 的第一个可见增量出现时停止计时。
5. 重复至少 5 次，记录认证、限流、网络和服务端异常。

### 目标

- 发送后立即显示生成状态。
- 首增量出现前 UI 可操作，停止按钮可用。

## 5. 长回复期间 UI 与滚动

### 步骤

1. 请求足够长、包含 Markdown 和代码块的回复。
2. 观察流式 reasoning/text 是否持续增量显示。
3. 在生成中滚动到历史消息中部，确认界面不强制拉回底部。
4. 回到底部，确认自动跟随恢复。
5. 操作窗口移动、缩放、设置导航和会话列表滚动。
6. 点击停止，记录从点击到增量停止的时间。

### 目标

- UI 不长时间冻结或持续高频闪烁。
- 用户向上阅读时保持阅读位置。
- Markdown/代码布局无明显重复重排错误。
- 停止后不再追加内容，并完成最终保存。

## 6. 典型与大量会话内存

### 数据集建议

- 典型：50 个会话，每个 20 条消息。
- 大量：500 个会话，每个 50 条消息；如目标用户画像不同，记录调整后的规模。

### 步骤

1. 启动后等待会话加载和日志写入稳定 30 秒。
2. 记录空闲内存基线。
3. 搜索、切换和滚动 20 个会话。
4. 打开含长 Markdown/代码的会话并等待 30 秒。
5. 执行一次刷新，记录峰值和稳定值。
6. 关闭应用，确认进程退出。

### 目标

- 数据规模增加时内存增长可解释且无持续无界增长。
- 多次搜索、切换和刷新后稳定值不持续攀升。
- 大量会话下 UI 仍可操作；具体容量目标由发布负责人基于目标硬件确认。

## 12. 关闭与取消

### 步骤

1. 在长回复生成中点击停止，确认状态变为停止且不再追加内容。
2. 重新生成长回复，在生成中关闭窗口。
3. 等待进程退出，记录耗时。
4. 重启应用，检查最后会话、部分回复和文件 JSON 是否可读。
5. 在网络断开、日志目录不可写和数据目录不可写条件下分别验证关闭提示。

### 目标

- 关闭会取消活动请求并等待必要保存。
- 不留下半截 JSON 或持续后台进程。
- 保存失败给出明确提示，不假装成功。
