# DeepSeek Workspace 支持与排障

## 1. 隐私提醒

在任何支持渠道中：

- 不要分享 API Key、Authorization Header 或完整 `AgentConfiguration.json`。
- 不要分享聊天正文、导出的完整会话或包含敏感内容的数据目录。
- 日志默认不记录聊天正文，但路径可能包含 Windows 用户名；分享前必须检查和脱敏。
- 应用不会自动上传诊断数据。所有复制、压缩和发送操作均由用户主动完成。

## 2. 默认文件与目录

| 内容 | 默认位置 |
|---|---|
| Agent 端点配置 | `%LocalAppData%\DeepSeekWpf\AgentConfiguration.json` |
| 应用设置 | `%LocalAppData%\DeepSeekWpf\settings.json` |
| 缓存目录 | `%LocalAppData%\DeepSeekWpf\Cache` |
| 数据目录 | `%LocalAppData%\DeepSeekWpf\Data` |
| 会话文件 | `%LocalAppData%\DeepSeekWpf\Data\Sessions\*.json` |
| 日志目录 | `%LocalAppData%\DeepSeekWpf\Logs` |
| 日志文件 | `%LocalAppData%\DeepSeekWpf\Logs\app-YYYYMMDD.log` |

如果设置页修改过缓存、数据或日志目录，以当前设置和诊断摘要显示的路径为准。

若环境变量 `DEEPSEEKWPF_AGENT_CONFIG` 非空，Agent 配置使用该变量指定的完整路径，而不是默认位置。

## 3. 通用诊断流程

1. 记录错误发生时间、正在执行的操作和界面提示。
2. 打开设置页，确认 Agent 配置文件路径和所选模型。
3. 点击“重新加载配置”，再执行“测试连接”。
4. 点击“复制诊断摘要”，保存到文本文件。
5. 打开日志目录，找到错误时间附近的 `app-YYYYMMDD.log`。
6. 检查数据和日志目录是否存在、可写、磁盘空间是否充足。
7. 如问题涉及会话，先备份整个 `Sessions` 目录，再尝试移走单个可疑 JSON。
8. 仅在脱敏后整理最小诊断包；不要附加 Agent 配置和聊天正文。

## 4. 常见问题

### 4.1 认证失败（401/403）

现象：界面提示“模型服务认证失败，请检查凭据”。

处理：

1. 确认正在编辑诊断摘要显示的 Agent 配置路径。
2. 检查 Key 是否过期、被撤销、复制了空格或属于错误账号/区域。
3. 检查 `EndPoint` 与 Key 是否属于同一服务。
4. 确认所选模型在该账号中可用。
5. 保存外部配置后，在设置页重新加载并测试连接。

不要把 Key 粘贴到问题单、日志或截图中。

### 4.2 请求过多（429）

现象：界面提示请求过于频繁；应用可能在尚未开始输出时有限自动重试。

处理：

1. 等待服务端限流窗口结束。
2. 避免短时间连续发送或反复测试连接。
3. 检查账号配额、并发限制和计费状态。
4. 若重试仍失败，记录时间和关联错误上下文，稍后再试。

已经开始流式输出后，应用不会自动重放请求，以免产生重复内容。

### 4.3 网络、超时或服务端错误

现象：提示网络异常、请求超时或服务暂时不可用。

处理：

1. 检查网络、代理、VPN、防火墙和 DNS。
2. 在浏览器或受控工具中确认端点域名可访问，但不要暴露 Key。
3. 检查设置页的请求超时，允许范围为 10–3600 秒。
4. 重新加载配置并测试连接。
5. 对临时故障使用界面的“重试”；持续失败时查看日志中的错误类别和时间。

### 4.4 模型返回空响应

现象：提示“模型未返回内容，请重试”。

处理：

1. 重试一次，确认是否为服务临时问题。
2. 检查模型定义、模型 ID 和端点是否匹配。
3. 确认所选模型支持当前请求和流式协议。
4. 使用其他已注册模型测试，判断问题属于模型还是通用配置。
5. 提供脱敏日志和模型标识，不提供聊天正文。

### 4.5 会话损坏或无法加载

现象：部分会话缺失，界面或日志提示某个文件加载失败。

处理：

1. 退出应用并备份整个数据目录。
2. 在 `Sessions` 目录按日志文件名定位问题 JSON。
3. 将该文件移到目录外，再启动或刷新会话。
4. 其他会话应继续加载；原文件不会被应用自动删除。
5. 如需修复，仅在副本上检查 JSON 结构和 `SchemaVersion`。

不要用旧版本应用直接覆盖唯一的 SchemaVersion 2 数据副本。

### 4.6 数据、缓存或日志目录不可写

现象：启动、保存、生成工具调用或关闭时提示目录权限问题。

处理：

1. 不要把数据目录设置到需要管理员权限、只读、离线或受控文件夹。
2. 确认当前 Windows 用户有创建、写入、替换和删除临时文件权限。
3. 检查磁盘空间、杀毒软件隔离、企业策略和同步软件锁定。
4. 在设置页选择本地可写目录并保存。
5. 修改数据目录不会自动迁移旧会话；需要时先备份并手工复制。

### 4.7 启动失败

现象：应用显示启动失败对话框或启动后立即退出。

处理：

1. 确认安装 .NET 10 Desktop Runtime x64。
2. 检查 `AgentConfiguration.json` 是否为合法 JSON；标准 JSON 不允许 `//` 注释。
3. 临时移走损坏的 `settings.json`，让应用重建默认设置；先保留备份。
4. 检查 LocalAppData 目录和自定义路径权限。
5. 查看最新日志；若日志目录尚未初始化，记录启动错误对话框全文。
6. 确认发布文件完整，必要时重新解压到新目录。

### 4.8 停止或关闭后仍在等待

处理：

1. 点击“停止”后等待当前取消和最终保存完成。
2. 关闭窗口时应用会取消活动请求并等待保存，不应强制结束进程。
3. 若长期无响应，记录等待时长、模型、网络状态和日志时间点。
4. 强制结束前先确认数据目录没有持续写入；下次启动检查会话完整性。

## 5. 清理日志

推荐方式：打开设置页，点击“清理日志”。

手工方式：

1. 正常退出应用。
2. 打开当前日志目录。
3. 删除 `app-*.log`。
4. 重新启动应用。

日志默认按日生成、保留 14 天，并限制总磁盘占用。清理日志不会删除设置、会话或 Agent 配置。

## 6. 诊断摘要内容

诊断摘要包含：

- 生成时间
- 应用版本
- .NET 运行时
- 操作系统
- 设置文件路径
- Agent 配置文件路径
- 缓存、数据和日志路径
- 已选模型标识
- 已注册模型数量
- 设置加载和日志写入错误摘要

诊断摘要不包含 Key 和聊天正文，但路径可能包含用户名。

## 7. 最小诊断包

仅在需要支持时手工整理：

1. 问题标题和影响范围。
2. 应用版本、Windows 版本和 .NET Runtime 版本。
3. 可重复的最短操作步骤。
4. 预期结果与实际结果。
5. 错误发生的本地时间和时区。
6. 设置页复制的诊断摘要，路径已按需脱敏。
7. 错误时间前后最小范围的日志片段，已检查不含敏感内容。
8. 涉及性能或兼容性时，附 `性能与兼容性验收清单.md` 中的环境与记录表。

不要包含：Key、完整 Agent 配置、Authorization Header、聊天正文、完整会话文件、无关日志或整个数据目录。
