# WPF MVVM 可复用工程实践

## 1. 用 Generic Host 管理应用生命周期

- 将依赖注入、日志、配置和服务生命周期统一放入 Generic Host，而不是在窗口或页面中手工拼装依赖。
- 启动顺序应显式可等待：加载设置、初始化日志、启动 Host、加载外部资源、恢复业务状态、显示主窗口。
- 关闭顺序同样应受控：停止新操作、取消活动任务、等待必要保存、刷新日志、停止并释放 Host。
- Singleton 适合单窗口共享状态；多窗口或多工作区需要先定义所有权，再使用作用域服务，避免把可变状态误做全局单例。

## 2. 严格限制 `async void` 边界

- `async void` 只用于 WPF 生命周期和事件处理器等框架要求的入口。
- 入口内部应立即调用返回 `Task` 的方法，并在边界统一捕获、记录和展示异常。
- 命令使用可等待的异步命令实现，避免丢弃任务；并发、禁用状态和异常传播由命令统一管理。
- 服务层不依赖 UI 同步上下文；需要更新 WPF 状态时，由 ViewModel 或 Dispatcher 明确切回 UI 线程。

## 3. 异步仓储采用原子写入和有序保存

- 文件读取和写入使用异步 API，并传递 `CancellationToken`。
- 写入先序列化到同目录临时文件，刷新后再替换目标文件，避免进程中断留下半截 JSON。
- 同一业务实体的保存、删除应串行化，并使用操作版本或队列丢弃过时写入，防止旧快照覆盖新状态。
- 读取多个独立文件时隔离单文件故障；返回成功数据和问题清单，而不是因一个损坏文件放弃全部数据。
- 持久化使用带版本的 DTO；UI 状态和第三方 SDK 对象不要直接成为磁盘契约。

## 4. 流式输出需要分层节流

- 网络层保持真实增量，不为 UI 合并而破坏取消和错误语义。
- ViewModel 可即时更新必要状态，但磁盘保存、Markdown 转换和布局刷新应按时间窗口节流。
- 流结束、停止、失败和关闭时执行最终保存，不能只依赖周期保存。
- 已开始向用户展示内容后不要自动重放整个请求，否则可能产生重复文本；此时应交给用户显式重试。

## 5. 智能自动滚动要尊重阅读位置

- 记录用户是否位于滚动区域底部附近，而不是每次消息变化都强制滚到底。
- 用户主动向上阅读时暂停自动跟随；切换会话、主动发送或用户回到底部时可恢复。
- 合并短时间内的多次增量滚动请求，降低布局和虚拟化压力。
- 视图代码隐藏只承担滚动、焦点、键盘等纯 UI 行为，不承载会话或网络业务规则。

## 6. 外部凭据与应用设置分离

- 端点和凭据由独立外部配置或安全凭据源维护，应用设置只保存无敏感性的选择和行为偏好。
- 设置页不回显完整 Key，也不把 Key 复制到 ViewModel、日志、会话或诊断摘要。
- 配置路径可由环境变量覆盖，默认路径应稳定且可发现；优先级必须在文档和诊断中一致。
- 示例配置必须是合法 JSON，使用明显占位值，不能复制包含注释的模板作为可直接运行示例。

## 7. 诊断信息遵循最小化原则

- 日志记录操作类型、关联标识、错误类别、异常类型和必要路径，不默认记录聊天正文或请求体。
- 诊断摘要只收集版本、运行时、操作系统、配置位置和错误摘要等排障必需信息。
- 本地诊断不等于匿名；路径可能包含用户名，分享前仍需人工检查。
- 诊断数据默认不上传，清理和导出都应由用户主动触发。

## 8. 用 `FakeChatClient` 测试 AI 流程

- 使用 Agent SDK 或共享库提供的 `FakeChatClient` 构造确定性的流式 text、reasoning、工具调用、空响应和异常。
- 单元测试不得依赖真实 Key、真实服务或网络时序。
- 通过可注入延迟函数验证退避和取消，避免测试真实等待。
- 除服务适配器外，还要测试 ViewModel 对停止、重试、命令状态和部分回复的处理。

## 9. 可测试的交互与导出边界

- 确认框、文件选择、剪贴板和打开目录通过交互服务封装，ViewModel 测试使用 Fake 实现。
- 导出使用独立服务，将会话模型转换为目标格式；导出失败不得改变原会话。
- 删除确认、撤销、编辑截断等产品语义应在 ViewModel 流程中测试，而不是只测试按钮是否存在。

## 10. 可访问性与人工验收

- 为控件提供自动化名称、帮助文本、合理焦点顺序和完整键盘路径。
- 设置最小窗口尺寸不代表布局已通过；仍需在目标 DPI、高对比度和 Windows 版本上人工检查。
- 自动化测试和 Release 构建不能替代冷启动、首 token、长回复交互和内存占用的重复人工测量。
