# DeepSeek Workspace 需求分析

## 1. 产品定位

DeepSeek Workspace 是面向个人开发者的 Windows 桌面 AI 工作区。产品以本地会话管理、真实多轮流式对话、Agent 工作区工具和可诊断的本地运行体验为核心，不把模型凭据写入应用设置、会话或诊断摘要。

产品使用 AgentLib 注册的全部语言模型提供者。应用不限定单一厂商；可用端点、Key、模型定义及能力由外部 `AgentConfiguration.json` 管理，设置页只从已注册模型中选择当前模型，不编辑或回显端点与 Key。

## 2. 目标用户与场景

### 2.1 目标用户

- 需要在 Windows 桌面持续进行代码、方案和技术问题对话的个人开发者。
- 需要使用本地 Agent 工作区工具，并保留可搜索、可导出会话记录的高级用户。
- 需要在不上传诊断数据的前提下自行排查配置、网络、存储和模型错误的用户。

### 2.2 核心场景

1. 首次运行时配置外部 Agent 端点文件，重新加载并选择已注册模型。
2. 发起真实多轮对话，增量查看 reasoning 与最终 text。
3. 允许模型调用以数据目录为工作区的 AgentLib 工作区工具。
4. 在生成中停止；在可恢复故障后重试失败轮次。
5. 搜索、重命名和删除会话；删除前确认，并可撤销最近一次删除。
6. 编辑历史消息；保存编辑后截断该消息之后的内容，避免旧上下文与新内容混用。
7. 阅读 Markdown 与代码内容，并将当前会话导出为 Markdown 文件。
8. 复制不含凭据和聊天正文的诊断摘要，打开或清理本地日志。

## 3. 功能需求

### 3.1 模型配置与选择

- 默认从 `%LocalAppData%\DeepSeekWpf\AgentConfiguration.json` 读取 AgentLib 配置。
- 环境变量 `DEEPSEEKWPF_AGENT_CONFIG` 非空时，以其指定的文件路径为最高优先级。
- 配置文件管理端点地址、Key、模型定义和主模型；必须是合法 JSON。
- 加载 AgentLib 已注册提供者所暴露的全部可用模型，不在 WPF 项目内维护平行提供者列表。
- 设置页展示配置文件路径、已注册模型、重新加载配置、打开配置和测试连接能力。
- 设置页只持久化模型选择，不读取、编辑或回显 Key 和端点地址。
- 没有可用模型时，主界面明确提示配置文件位置并阻止发送。

### 3.2 真实聊天与 Agent 能力

- 使用所选模型完成包含历史上下文的真实多轮对话。
- 通过流式响应分别展示 reasoning 和 text；空响应视为可诊断错误。
- 每次请求使用本地数据目录作为 Agent 工作区，提供 AgentLib 默认工作区工具。
- 支持用户取消、请求超时、有限自动重试和显式重试。
- 自动重试仅用于可恢复错误，最多三次；已经开始输出内容后不自动重放，避免重复写入。
- 认证、限流、网络、超时、服务端、协议、空响应、存储、配置、取消和未知错误必须分类处理。

### 3.3 会话管理

- 新建、选择和刷新会话，默认按更新时间倒序展示。
- 按会话标题或消息正文进行本地搜索。
- 支持会话标题重命名，标题非空且最长 80 个字符。
- 删除会话前要求用户确认；删除成功后允许撤销最近一次删除。
- 会话按独立 JSON 文件保存在数据目录下，单个损坏文件不得阻止其他会话加载。
- 会话格式使用 `SchemaVersion = 2`；旧 v1 数据自动迁移到当前模型。
- 用户消息入队、流式生成过程、生成完成、停止、编辑、重命名、删除恢复和关闭时应可靠保存。

### 3.4 消息编辑、显示与导出

- 消息卡片支持内联编辑正文及 reasoning。
- 保存历史消息编辑时，删除该消息之后的消息并持久化，形成明确的“编辑后截断”语义。
- Markdown 内容转换为 WPF 文档显示，支持段落、列表、链接和代码块等常用内容。
- 代码块使用等宽样式展示；链接通过用户可感知的交互打开。
- 当前会话可导出为 Markdown，不修改原会话数据。

### 3.5 交互与状态

- 提供空会话、无模型、加载、生成、停止、失败、重试和保存等明确状态。
- 默认 Enter 发送、Shift+Enter 换行；用户可切换为 Ctrl+Enter 发送。
- 新消息和流式输出时仅在用户位于底部附近时自动滚动；用户向上阅读时不得强制拉回底部。
- 对流式保存、显示与滚动进行节流，避免每个增量都触发昂贵操作。
- 主窗口最小尺寸为 900×600，并支持完整键盘导航。

### 3.6 设置与诊断

- 设置页管理模型选择、请求超时、发送快捷键、缓存目录、数据目录和日志目录。
- 保存设置前验证目录可创建且可写；设置文件采用异步原子替换。
- 提供测试模型连接、打开 Agent 配置、打开数据/缓存/日志目录、复制诊断摘要和清理日志能力。
- 诊断摘要只包含应用版本、运行时、操作系统、路径、已选模型、注册模型数量和错误类型等最小信息。
- 应用不自动上传日志、诊断摘要、会话或任何用户数据。

## 4. 数据与迁移需求

- `AppSettings` 保存本地目录、请求超时、发送快捷键和 `SelectedModelSpecifier`。
- 旧 `ModelName` 只用于迁移到 `SelectedModelSpecifier`；旧 API 地址与 API Key 不再读取或写入。
- `ChatSession` 保存会话标识、标题、创建/更新时间和消息集合。
- `AgentLib.Model.CopilotChatMessage` 承载标准角色、正文和 reasoning；WPF 编辑状态由 `ChatMessageViewModel` 隔离。
- 会话持久化使用专用 DTO，不直接序列化 WPF 状态或 AgentLib 复杂对象图。
- 写入使用临时文件加替换；同一会话的保存和删除必须按操作顺序串行化，旧操作不得覆盖新状态。

## 5. 非功能需求

### 5.1 隐私与安全

- Key 只存在于用户维护的外部 Agent 配置中。
- 设置、会话、日志、导出文件和诊断摘要不得主动写入 Key、认证头或完整请求体。
- 默认不记录聊天正文；用户分享诊断资料前应检查并移除敏感路径信息。
- 所有诊断数据仅保存在本机，未经用户主动操作不得上传。

### 5.2 可靠性

- 启动、关闭、UI 线程、后台任务、网络和存储异常必须进入统一处理与日志链路。
- 用户取消不显示为失败；可恢复故障提供有限重试，不可恢复故障给出可操作提示。
- 设置和会话写入失败不得伪装成功；应用关闭时应取消活动请求并等待必要保存。
- 单个会话损坏、单次日志写入失败或模型连接失败不得导致无提示退出。
- 生产项目和发布产物不得包含 Mock、Fake、Demo 响应或测试语言模型实现；测试替身只能编译到独立测试项目。

### 5.3 性能

- 启动和文件操作不得同步阻塞 UI 线程。
- 流式输出、保存和自动滚动必须节流；长回复期间 UI 应保持可交互。
- 冷启动、首 token、典型/大量会话内存等指标必须按人工验收清单实测，未实测前不得标为通过。

### 5.4 可访问性与兼容性

- 控件提供可理解的名称、帮助文本、焦点顺序和键盘操作。
- 支持 Windows 10/11 x64，目标框架为 `net10.0-windows`。
- 发布包为 framework-dependent，运行机器需要安装 .NET 10 Desktop Runtime。
- DPI 100%/150%/200%、高对比度、900×600 窗口和 Windows 版本矩阵必须人工验收，未执行前保持“待人工实测”。

### 5.5 .NET 支持策略

- 使用仓库 `global.json` 固定的 .NET 10 SDK 构建。
- 运行时依赖 .NET 10 Desktop Runtime，并跟随 Microsoft 对 .NET 10 的支持生命周期获取安全和服务更新。
- 升级 SDK、WPF 或 AgentLib 时必须执行 Release 构建、自动化测试、发布验证和数据迁移回归。

## 6. 验收边界

- 自动化门禁包括 Release 构建、单元/集成测试和 win-x64 发布。
- 真实账号端到端、性能、DPI、高对比度、键盘完整性和 Windows 版本矩阵属于人工验收。
- 自动化成功不能替代人工验收，也不得据此声明人工性能或兼容性已通过。
