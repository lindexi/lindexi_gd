# DeepSeek Workspace 项目框架设计

## 1. 设计目标

以 WPF、MVVM、Generic Host 和 AgentLib 构建可配置、可诊断、可测试、可发布的个人开发者桌面 AI 工作区。设计重点是明确宿主生命周期、服务边界、异步与 UI 线程边界、外部凭据配置、可靠本地持久化和结构化错误处理。

## 2. 运行时分层

- `App`：应用组合根，创建并启动 Generic Host，注册全局异常处理，执行初始化与受控关闭。
- `Views`：WPF 展示和必要的界面事件桥接，例如输入快捷键、智能自动滚动和焦点恢复。
- `ViewModels`：页面状态、命令、交互流程和用户可见错误映射。
- `Models`：应用设置、会话、模型描述和流式响应块。
- `Services`：Agent 模型、聊天调用、设置、会话仓储、日志、诊断、用户交互、连接测试和导出。
- `Infrastructure`：通知、同步/异步命令和 Markdown 到 WPF 文档转换。

## 3. Generic Host 与依赖注入生命周期

`App.OnStartup` 是 WPF 必需的 `async void` 边界。其内部立即进入可等待流程：创建 `HostApplicationBuilder`、清理默认日志提供者、注册服务、构建 Host、初始化设置与文件日志、启动 Host、加载 Agent 配置、初始化会话，最后显示主窗口。

当前注册均为 Singleton：

- 基础服务：`ISettingsService`、`IAppLogger`、`ILoggerProvider`、`IDiagnosticsService`、`IChatRepository`。
- 产品服务：`IAgentApiEndpointManagerFactory`、`IAgentModelService`、`IAiChatService`、`IModelConnectionTestService`、`IChatExportService`、`IUserInteractionService`。
- UI：`ChatWorkspaceViewModel`、`SettingsViewModel`、`MainWindowViewModel`、`MainWindow`。

单例适合当前单窗口、单工作区进程模型。模型客户端按请求获取并释放，不注册为长生命周期对象。若未来增加多窗口或独立工作区，应先定义作用域所有权，再引入 Scoped 生命周期，不能直接复用当前单例状态。

关闭流程由窗口请求 `App.RequestShutdownAsync`：先让聊天工作区取消活动响应并保存，再停止 Host 和日志写入器，最后退出。全局处理覆盖 Dispatcher 未处理异常、未观察任务异常和 AppDomain 未处理异常。

## 4. 核心服务边界

### 4.1 Agent 模型与聊天

- `IAgentModelService`：解析配置路径、加载 `AgentApiEndpointManager`、暴露所有注册模型、选择模型并提供所选 `IChatClient`。
- `AgentAiChatService`：把会话历史映射为 `Microsoft.Extensions.AI.ChatMessage`，创建 Agent，注入 AgentLib 默认工作区工具，流式输出 reasoning/text，处理超时、取消、错误分类和重试。
- `IModelConnectionTestService`：对当前所选模型执行独立连接验证，不把凭据暴露给设置页。

### 4.2 设置与会话

- `ISettingsService`：异步加载、验证和原子保存设置；保存后发布不可变配置快照。
- `IChatRepository`：异步加载、保存和删除会话，支持取消、单文件故障隔离、版本迁移和同会话有序写入。
- `FileChatRepository`：每会话一个 JSON 文件，使用临时文件与替换提交；以操作版本和信号量防止旧保存覆盖新保存或删除。

### 4.3 日志、诊断、交互与导出

- `IAppLogger`：应用级异步日志入口；`FileAppLogger` 使用单读者 Channel 顺序落盘、按日文件、14 天保留和总量上限。
- `ILoggerProvider`：`AppLoggerProvider` 将 `Microsoft.Extensions.Logging` 统一桥接到应用文件日志。
- `IDiagnosticsService`：生成最小化本地诊断摘要并清理日志，不包含 Key 和聊天正文。
- `IUserInteractionService`：封装确认、文件选择、打开路径和剪贴板等 UI 交互，使 ViewModel 可测试。
- `IChatExportService`：将会话导出为 Markdown，保持持久化模型与导出格式解耦。

## 5. 配置来源、优先级与路径

### 5.1 Agent 端点配置

优先级从高到低：

1. 环境变量 `DEEPSEEKWPF_AGENT_CONFIG` 指定的文件。
2. `%LocalAppData%\DeepSeekWpf\AgentConfiguration.json`。

文件由 AgentLib 的 `AgentApiManagerConfiguration` 读取，管理 `PrimaryModel`、`OpenAIConfigurationList`、端点、Key 和模型定义。文件不存在时创建合法的空 JSON。WPF 设置不复制这些凭据字段。

### 5.2 应用设置与数据

- 设置文件：`%LocalAppData%\DeepSeekWpf\settings.json`。
- 默认缓存目录：`%LocalAppData%\DeepSeekWpf\Cache`。
- 默认数据目录：`%LocalAppData%\DeepSeekWpf\Data`。
- 默认日志目录：`%LocalAppData%\DeepSeekWpf\Logs`。
- 会话目录：当前数据目录下的 `Sessions` 子目录。

应用设置优先于默认值；旧 `ModelName` 在反序列化时迁移到 `SelectedModelSpecifier`。旧 API 地址和 API Key 已从设置模型移除，不再读取或写入。

## 6. 会话 SchemaVersion 与迁移

当前会话 DTO 使用 `SchemaVersion = 2`。加载时先读取 JSON 文档，再按版本迁移到当前 DTO：

- v2：按当前结构读取。
- v1 或缺少版本：按旧字段兼容读取并转换为 v2 内存模型。
- 高于当前支持版本：作为单文件加载问题报告，不影响其他会话。

持久化只写 v2。专用 DTO 隔离 WPF 编辑状态和 AgentLib 对象图，使磁盘格式可演进。每个损坏文件产生文件名、异常类型和恢复建议，界面与日志均可感知。

## 7. 异步与 UI 线程策略

- 网络、设置、日志和会话文件 I/O 全部使用异步 API。
- 服务层默认使用 `ConfigureAwait(false)`，不依赖 WPF 同步上下文。
- ViewModel 在 UI 命令上下文中更新可观察状态；后台服务不得直接修改 WPF 集合或控件。
- `async void` 只允许存在于 WPF 生命周期或事件边界，内部调用可等待方法并集中捕获异常。
- 流式响应通过 `IAsyncEnumerable<AiResponseChunk>` 传递；ViewModel 分别追加 reasoning 和 text。
- 流式会话保存按 500 ms 节流；界面滚动按 75 ms 节流，并仅在用户接近底部时跟随。
- 关闭时等待活动响应任务完成或取消，避免进程退出时遗留写入。

## 8. 错误分类与重试

`AiChatErrorCategory` 定义：配置、认证、限流、网络、超时、服务端、协议、空响应、存储、未知和取消。

- 认证与配置错误不可自动重试，提示用户修复外部配置。
- 限流、网络、超时、服务端和空响应可按规则重试。
- 单次请求最多三次尝试，使用有限递增等待；用户取消可中断等待。
- 已收到流式内容后禁止自动重试，避免重复内容写入同一助手消息。
- 用户主动取消不作为错误弹窗；失败请求保留可重试上下文。
- 每次生成使用关联标识记录 started、retrying、completed、failed 或 canceled，不记录请求正文和凭据。

## 9. 日志与隐私设计

- 日志用于记录生命周期、配置加载结果、会话文件问题、操作标识、错误类别和异常类型。
- 禁止主动记录 Key、Authorization Header、完整请求体和聊天正文。
- 诊断摘要只包含版本、运行时、操作系统、设置/配置/数据/日志路径、模型标识、模型数量及错误摘要。
- 日志默认保留 14 天，并限制总磁盘占用；用户可从设置页清理。
- 应用不提供自动上传逻辑。用户主动分享前应检查路径、用户名和其他环境信息。

## 10. 测试架构

- 测试项目与 WPF 产品项目分离，不依赖真实 Key、真实网络或用户目录。
- Agent 对话测试使用仅编译在测试项目中的聊天客户端替身，覆盖 reasoning/text、工具、取消、空响应和错误映射。
- 仓储测试使用隔离临时目录，覆盖 v1→v2 迁移、原子写入、并发有序保存、删除和损坏文件隔离。
- ViewModel 测试替换交互、导出、日志、设置和聊天服务，验证命令状态、停止、重试、删除确认撤销与编辑截断。
- 设置和诊断测试验证旧 `ModelName` 迁移、目录校验及敏感字段不进入输出。

## 11. CI 与发布

- CI 使用仓库指定的 .NET 10 SDK，执行还原、Release 构建和测试。
- 项目启用 Nullable、最新分析级别、代码样式构建检查和警告即错误。
- 发布脚本执行测试后，按 `win-x64` Profile 生成 framework-dependent、非单文件、非裁剪包。
- 发布前检查产品程序集与发布目录，禁止携带 Mock/Fake 类型、测试程序集、Demo 响应或设计时数据。
- 版本通过 `VersionPrefix` 和发布参数注入；发布产物必须可追踪到版本。
- 自动化发布成功只证明构建链路，不替代真实账号、性能、DPI、高对比度、键盘和 Windows 版本矩阵人工验收。
