# DeepSeekWpf 产品化改造计划

## 1. 文档目标

本文档用于指导 DeepSeekWpf 从可运行的 WPF 聊天 Demo 一次性改造为可配置、可诊断、可测试、可维护的 Windows 桌面产品。

本文档定义本次产品化改造的完整范围、实施要求和验收标准。所有任务应在同一次完整改造中落实，不拆分批次、阶段或里程碑，避免实现过程逐步偏离最终目标。

## 2. 当前实现基线

### 2.1 已具备能力

- 项目使用 `.NET 10`、WPF 和 MVVM 组织界面与业务状态。
- 已有主界面、设置界面和页面切换能力。
- 支持新建、选择、删除、刷新历史会话。
- 支持多轮消息展示、停止生成、思考内容与正文分区展示。
- AI 服务通过 `IAiChatService` 隔离，并支持异步流式增量输出。
- 会话按独立 JSON 文件保存到本地数据目录。
- 设置保存到 `%LocalAppData%/DeepSeekWpf`。
- 复用 `AgentLib.Model.CopilotChatMessage`，为后续工具调用、多模态和 Agent 能力保留扩展基础。
- 已有简单的本地日志和消息内联编辑能力。

### 2.2 仍属于 Demo 的主要表现

- 应用启动时固定注入 `MockAiChatService`，尚未接入真实 DeepSeek 服务。
- 服务依赖在 `App.xaml.cs` 中手工创建，缺少标准宿主、依赖注入、配置和生命周期管理。
- API Key 当前由 Demo 设置逻辑管理，尚未统一接入 `AgentApiEndpointManager`。
- 设置、日志和会话保存主要使用同步文件 I/O，可能阻塞 UI。
- 部分文件读写异常被直接吞掉，用户和日志都无法获知失败原因。
- 设置保存后通过丢弃任务的方式刷新会话，异常无法可靠传递。
- 缺少启动异常、UI 线程异常和未观察任务异常的统一处理。
- 缺少超时、重试、退避、限流、网络状态和服务错误的产品化映射。
- 缺少自动化测试项目、持续集成和正式发布配置。
- UI 仍保留“聊天客户端骨架”等 Demo 文案，缺少空状态、加载态、错误态和确认交互的系统设计。



### 2.3 当前主要风险

| 风险 | 影响 | 严重程度 |
|---|---|---|
| 模型端点配置仍由 Demo 逻辑管理 | 配置来源不统一 | 严重 |
| 真实模型未接入 | 无法形成可用产品 | 严重 |
| 异常被吞或异步任务失联 | 故障不可见、状态不一致 | 严重 |
| 缺少自动化测试 | 回归成本高、发布风险不可控 | 高 |
| 日志无分级、轮转和脱敏 | 难排障且可能泄露隐私 | 高 |
| 大量会话一次性加载 | 数据增长后启动和切换变慢 | 一般 |

## 3. 产品目标与范围

### 3.1 首个产品版本目标

首个可发布版本应满足以下核心场景：

1. 应用通过 AgentLib 的 `AgentApiEndpointManager` 读取 DeepSeek API 地址、模型和 API Key 配置。
2. 应用能够验证配置并发起真实的多轮流式对话。
3. 用户能够停止生成，并在网络或服务失败后理解原因和重试。
4. 会话能够可靠地自动保存，在应用重启后恢复。
5. 应用不主动将 API Key 写入设置文件、日志或会话文件。
6. 关键故障通过 AgentLib 内置日志方案记录本地诊断信息，且默认不记录敏感正文和凭据。
7. 核心服务和关键用户流程具有自动化测试保护。

### 3.2 关键质量属性

- **安全性**：不主动持久化或记录凭据和敏感正文，不增加超出产品实际需要的防御机制。
- **可靠性**：异常可恢复；取消和退出流程可控；保存失败能够被发现并反馈。
- **可用性**：加载、生成、停止、失败、重试和空状态均有明确反馈。
- **性能**：启动和会话切换不长时间阻塞 UI；流式更新不过度刷新界面；异步等待前后明确 UI 线程与后台线程边界，避免阻塞 UI 或在错误线程访问界面状态。
- **可维护性**：服务职责清晰，配置、网络、存储与 UI 状态保持必要边界，不为不明确的扩展场景增加抽象。
- **可测试性**：核心逻辑不依赖真实 UI 或真实网络，优先使用 AgentLib 内置 `FakeChatClient` 等测试机制验证关键路径。
- **可诊断性**：优先复用 AgentLib 内置日志方案，日志包含必要级别和故障上下文，但不记录凭据与敏感正文。
- **可发布性**：构建可重复、版本可追踪，产品化功能完整，不将安装包或 OTA 升级作为本次改造重点。

## 4. 实施原则

1. 一次性完成真实服务、Agent 能力、产品交互、异常处理、测试和发布配置，禁止拆分阶段实施。
2. 直接接入 AgentLib 已有的完整 Agent 能力，不重复建设协议层或延后集成。
3. 保持 WPF View 只负责展示和必要事件转发，业务逻辑放入 ViewModel 或服务。
4. 所有可能阻塞的网络和磁盘操作使用异步 API，并支持取消；每处异步流程都必须明确 `await` 前后的线程上下文，后台工作不得阻塞 UI，需要更新 UI 的逻辑必须回到 Dispatcher 线程。
5. 不通过吞异常维持表面可用；异常必须被分类、记录并转化为用户可理解的状态。
6. 数据格式变更必须带版本和迁移策略，不能直接破坏既有会话。
7. 完整改造完成后统一通过全部质量门禁，不设置里程碑或阶段性完成状态。
8. 优先复用 AgentLib 与 `Microsoft.Extensions.AI.DeepSeek` 已有能力，包括端点配置、日志和测试替身，避免在 WPF 项目中重复实现。
9. 删除原有 Mock 默认注入、Demo 配置、Demo 文案和仅为演示存在的分支逻辑；测试所需替身只能保留在测试或设计时场景中。

## 5. 完整改造清单

### 5.1 工程底座与真实可用闭环

目标：从“界面可演示”达到“真实服务可用，核心数据和凭据基本安全”。

#### 5.1.1 建立应用宿主和依赖注入

- 引入 Generic Host，统一管理依赖注入、配置、日志和应用生命周期。
- 将 `App.xaml.cs` 中的手工实例创建迁移到服务注册。
- 明确 Singleton、Scoped/会话级和 Transient 服务生命周期。
- 将窗口、ViewModel 和业务服务通过容器创建。
- 为启动初始化建立可等待、可失败、可展示错误的流程，避免继续扩大 `async void` 范围。
- 增加受控关闭流程，停止正在进行的请求并完成必要保存。

验收标准：

- 入口文件不再直接拼装全部业务依赖。
- 服务可在测试中替换为 Fake 或 Mock 实现。
- 启动初始化失败时能够显示可操作的错误信息，并写入诊断日志。

#### 5.1.2 接入真实 DeepSeek 服务

- 新增产品级 `IAiChatService` 实现，适配 `DeepSeekChatClient` 或 AgentLib 的模型提供者。
- 将当前会话转换为模型所需的聊天历史，同时保留 System、User、Assistant 角色。
- 将流式响应中的 reasoning 和 text 映射到现有 `AiResponseChunk` 或后续统一的增量消息模型。
- 正确处理取消、完成原因、服务端错误、无内容响应和协议异常。
- 为请求设置合理连接超时、整体超时和用户可取消令牌。
- 配置变更后安全重建客户端，避免旧凭据或旧端点继续被使用。
- 保留 Mock 实现，仅用于开发、设计时预览和测试，不作为生产默认值。

验收标准：

- 使用有效配置能够完成真实多轮流式对话。
- 点击停止后网络请求和 UI 增量更新均能及时结束。
- 401、403、429、超时、断网和 5xx 能映射为不同的用户提示。
- 日志中不出现 API Key、Authorization Header 或完整敏感请求体。

#### 5.1.3 统一模型端点配置

- 使用 AgentLib 的 `AgentApiEndpointManager` 统一读取 API 地址、模型和 API Key。
- 删除 WPF 项目中重复的 API Key 保存和端点配置逻辑。
- 设置页展示并编辑 AgentLib 支持的必要配置，不回显完整 API Key。
- 提供“测试连接”能力，在应用配置前验证地址、模型和凭据。
- 配置变更后重建聊天客户端，使新配置立即生效。

验收标准：

- 应用只通过 `AgentApiEndpointManager` 获取模型端点配置。
- WPF 自有设置、日志和会话文件不写入 API Key。
- 无效地址、空模型和认证失败能够给出明确提示。
- 配置更新后无需重启即可用于后续请求。

#### 5.1.4 提升会话数据可靠性

- 将仓储接口调整为完整异步 API，并贯穿取消令牌。
- 为会话 DTO 增加数据格式版本和迁移入口。
- 对无法读取的会话记录错误并允许用户恢复，不再静默忽略。
- 记录加载失败的文件名、异常类型和恢复建议。
- 明确自动保存触发点：用户消息入队、响应增量节流保存、响应完成、编辑、删除、退出。
- 设置切换数据目录时先验证目录可写，并定义复制、迁移或保留原位置的行为。
- 避免同一会话的保存任务并发执行，确保内存状态与落盘顺序一致。

验收标准：

- 会话加载或保存异常可被记录、反馈并恢复到可继续操作的状态。
- 单个会话读取失败不影响其他会话加载。
- 连续快速发送、停止和编辑不会造成状态错乱。
- 数据目录不可写时，用户会收到明确提示，应用不会假装保存成功。

### 5.2 产品体验、故障恢复与质量体系

目标：从“核心可用”达到“普通用户能够稳定使用，开发团队能够安全迭代”。

#### 5.2.1 建立统一错误处理

- 捕获并记录应用启动异常、Dispatcher 未处理异常和未观察任务异常。
- 定义领域错误类别：配置、认证、限流、网络、服务端、取消、存储、数据损坏和未知错误。
- 由服务返回结构化结果或抛出明确异常，由 ViewModel 统一映射用户文案。
- 为可恢复错误提供重试；重试必须可取消，并对 429/5xx 使用有限次数指数退避。
- 禁止空 `catch`；无法处理的异常至少进入诊断日志。
- 明确取消不作为错误弹窗，避免用户主动停止被显示为失败。

#### 5.2.2 完善聊天产品交互

- 移除“骨架”“模拟服务”等 Demo 文案，统一产品命名和术语。
- 增加首次启动引导、未配置状态、无会话状态、加载状态和错误状态。
- 输入框支持 Enter 发送、Shift+Enter 换行，并允许设置中调整行为。
- 生成期间明确控制可执行命令，避免重复发送和切换导致状态错乱。
- 会话删除增加确认和可选撤销机制。
- 支持会话重命名、按更新时间排序和基础搜索。
- 新消息和增量回复时按合理规则自动滚动，同时尊重用户主动向上阅读。
- 对长回复使用增量刷新节流，避免每个字符都触发昂贵的 UI 更新。
- 为 Markdown、代码块、复制按钮和链接打开制定安全展示方案。
- 明确编辑历史消息后的上下文行为：仅修改显示、截断后续重生成或创建分支。

验收标准：

- 所有核心页面均具备空、忙、成功和失败状态。
- 长回复生成过程中 UI 可交互且滚动稳定。
- 不允许重复提交造成并发响应写入同一助手消息。
- 删除、编辑和停止操作均有清晰且一致的反馈。

#### 5.2.3 建立可观测性与隐私规则

- 优先接入 AgentLib 内置日志方案，并与 `Microsoft.Extensions.Logging` 统一日志入口。
- 定义 Trace、Debug、Information、Warning、Error 的使用边界。
- 为每次生成创建请求关联标识，用于串联用户操作、网络调用和保存事件。
- 实现日志轮转、保留期限和最大磁盘占用限制。
- 默认不记录完整聊天正文、API Key 或认证请求头。
- 在设置页提供打开日志目录、复制诊断摘要和清理日志能力。
- 默认不上传用户数据。

#### 5.2.4 建立自动化测试体系

建议新增测试项目，至少覆盖：

- 模型端点配置：`AgentApiEndpointManager` 配置读取、无效配置和配置更新。
- `FileChatRepository`：读写往返、旧格式迁移、读取失败、保存顺序和取消。
- 真实 AI 服务适配器：流式文本、推理内容、取消、错误映射和空响应。
- `ChatWorkspaceViewModel`：发送、停止、失败、自动保存、命令状态和会话切换。
- `SettingsViewModel`：校验、测试连接、保存失败和恢复默认。
- 优先使用 AgentLib 内置 `FakeChatClient`，必要时使用 Fake `HttpMessageHandler`，避免单元测试访问真实服务。
- 为关键用户流程增加少量 UI 自动化或集成测试。

验收标准：

- 核心服务和 ViewModel 的关键分支有自动化测试。
- 测试不依赖真实 API Key、真实网络或用户本机目录。
- 每次提交能够自动完成还原、构建和测试。
- 修复线上或验收缺陷时优先补回归测试。

#### 5.2.5 建立持续集成

- 在 CI 中固定受支持的 .NET SDK 版本。
- 执行 Release 构建、测试和必要的格式/分析器检查。
- 启用 Nullable，并逐步将编译警告作为错误处理；第三方兼容警告需有明确豁免。
- 生成可追踪版本号和构建产物。
- 对依赖漏洞和过期包进行检查，但升级需通过兼容性验证。

### 5.3 性能、桌面体验与维护

目标：确保产品化功能完整、桌面交互稳定，并具备持续维护所需的基本工程质量。

#### 5.3.1 性能和资源控制

- 定义启动时间、首个会话显示时间、发送到首个 Token 时间和内存占用预算。
- 会话列表只加载摘要，需要时再加载完整消息。
- 对大量会话增加分页、虚拟化或增量加载。
- 对流式 UI 更新合并批次，降低属性通知和布局频率。
- 长会话进入模型前使用 AgentLib 的压缩或裁剪机制，并让用户理解上下文限制。
- 对日志、缓存、会话和临时文件设置容量与清理策略。
- 性能优化必须基于测量结果，不凭感觉重构。

#### 5.3.2 可访问性和桌面体验

- 检查键盘完整操作、焦点顺序、快捷键和默认按钮行为。
- 为交互控件设置可访问名称和合理的自动化属性。
- 验证 Windows 缩放、高 DPI、不同分辨率和长文本布局。
- 支持浅色/深色主题前，先集中管理颜色、间距和控件样式资源。
- 检查高对比度模式和文本可读性。
- 明确最小窗口尺寸，在较小屏幕上允许布局降级而不是裁切关键操作。

#### 5.3.3 维护与支持

- 定义受支持的 Windows 版本和 .NET 运行策略。
- 建立配置、会话和日志的支持手册。
- 建立崩溃、会话读取失败和认证失败的排障流程。
- 制定依赖升级节奏和安全修复响应流程。
- 为用户反馈建立最小诊断包，诊断包必须允许用户预览并排除聊天正文。

#### 5.3.4 删除 Demo 逻辑

- 删除生产启动路径中的 `MockAiChatService` 注入，真实 AgentLib 聊天能力作为唯一生产实现。
- 删除 WPF 项目内重复的端点配置、模拟响应和演示数据逻辑。
- 删除“骨架”“模拟服务”等 Demo 文案、占位状态和仅供演示的交互分支。
- Fake、Mock 和设计时数据只能存在于测试项目或明确的设计时入口中，不得进入生产默认流程。

验收标准：

- 生产代码中不存在可被误用的 Demo 服务入口或模拟响应分支。
- 应用启动后直接使用 AgentLib 配置和真实聊天能力。
- 自动化测试仍可通过 AgentLib 内置 `FakeChatClient` 独立运行。

## 6. 质量门禁

完整改造完成后必须一次性满足以下条件：

### 6.1 功能门禁

- 首次配置、测试连接、发送、流式显示、停止、重试、会话恢复均通过验收。
- 设置变更能够按预期应用，不需要重启的配置不应强制重启。
- 数据目录不可用、凭据失效和服务限流均有明确反馈。

### 6.2 配置与日志门禁

- 模型端点配置统一通过 `AgentApiEndpointManager` 读取。
- WPF 自有设置、日志、异常文本、会话文件和诊断包不主动写入 API Key。
- 默认不记录完整聊天正文或上传用户数据。
- 第三方依赖不存在未接受的高危漏洞。

### 6.3 可靠性门禁

- 无已知未处理异常导致的进程退出。
- 会话和设置经过磁盘不可写、无效 JSON、取消和连续操作测试。
- 单个会话读取失败不会阻止应用启动，用户能够获知并恢复。
- 应用关闭时正在运行的请求能够取消，必要数据能够完成受控保存。
- 所有异步 UI 流程均经过线程上下文检查，不在后台线程访问 WPF UI，也不以同步等待阻塞 UI 线程。

### 6.4 测试门禁

- Release 构建成功。
- 自动化测试全部通过。
- 核心 ViewModel 和服务关键分支有回归测试。
- 测试不依赖开发者个人环境和真实网络。
- AI 相关测试优先使用 AgentLib 内置 `FakeChatClient`。

### 6.5 性能门禁

至少测量：

- 冷启动到主界面可交互时间。
- 历史会话摘要显示时间。
- 发送请求到首个增量内容的时间。
- 长回复生成时 UI 线程响应情况。
- 典型会话量和大量会话量下的内存占用。

### 6.6 产品化完成门禁
