# AgentLib 消息 API 实验与待办（早期记录）

> 本文保留消息 API 实验时点的范围，后文“当前”及“未实现”不直接表示最新产品状态。Shell 和会话协议持久化随后已接通；架构与验收以 02、10、14 为准。信息对象现位于 Model/CopilotChatMessageResponseInfo.cs。早期撤回原生 XML 的记录不否定后续会话级原生 Items 存储。

## 当前范围

本轮是 API 写法实验，不是生产完成态。用 `AgentLib.Tests/ResponsesApiUsageTests.cs` 展示真实调用代码，评估写法、职责和改动范围。HTTP 使用内存处理器，请求和流式解析仍使用真实 SDK。

不扩展 Shell、执行器、持久化体系、克隆或会话分支。

## 当前 API

- `CopilotChatMessage` 不使用 partial；通过 `ResponseInfo` 属性延迟创建独立信息对象，普通 Chat 不访问便不分配协议状态。getter 不修改展示内容。
- 不提供 `GetOrCreateResponseInfo()`、消息级 Responses 转发方法或特殊创建入口。
- 信息对象持有所属消息，公开 `AppendResponse`、`AppendResponseUpdate`、`AppendToolResult`、`Responses`、`CurrentResponse`。
- 协议定位字典保持私有。原生响应列表只读，不提供未使用的集合通知；SDK 对象不进行 JSON 深拷贝，调用方不得修改已提交的响应对象。
- 文本和推理消息项的 internal 追加方法负责修改内容和产生增量事件；消息在原有内容项订阅生命周期中汇总事件。Chat 与 Responses 共用这套通知规则。
- 信息对象通过消息已有的 `AppendUsageDetails()` 提交用量，按响应去重，不另设业务用量累计，不提供赋值或补通知桥接方法。

## 已清理的提前建设

- 删除 `CopilotChatTextItem.Annotations`，解除普通文本项对 Responses SDK 的依赖，不再为每个文本项分配引用集合。
- 删除引用集合的克隆、XML 读写；恢复文本项原有克隆方式。
- 撤回此前实验增加的原生 Responses XML 保存恢复和 `RestoreResponses`。这也消除了保存普通 Chat 消息时访问延迟属性造成的额外分配。
- 原生引用仍留在 SDK 响应结果中，不提前建立第二份引用模型。
- 原生响应记录不再逐次 JSON 序列化再反序列化为快照，不再为查找响应复制整个列表。

注意：此前实验文件中的 Responses 扩展数据不再加载或写入；当前只保留原有展示消息的保存能力，不承诺协议续接恢复。

## API 用法测试

- 手动上下文获取模型客户端，完整请求和流式事件直接提交给信息对象。
- 工具结果使用同一个原生 Item 展示并提交下一轮请求。
- 交错输出定位到各自片段。
- 属性访问不改变内容，重复访问取得相同实例。
- 消息既有文本、推理增量事件可用。
- 用量更新原有消息属性，重复终态不重复累计。

## 已验证的原生 API 行为

- 本地工具：真实 HTTP 工具调用结果驱动 AIFunction 执行，再提交真实函数返回值；用量更新到消息当前值和累计值。
- 多轮：显式保留输入、原生 OutputItems 和后续输入，能继续上下文；不从展示文本拼接协议历史。
- 缓存：显式携带稳定历史前缀可以命中输入缓存。报告记录每轮 input、cached、命中率和累计加权比率，而不只记录测试通过。
- Web Search：在 Tools 中注册 SDK 内置工具，服务端完成搜索，响应中存在 WebSearchCallResponseItem。普通非流式用法已验证，完整流式及 UI 引用展示仍属待办。
- 真实服务实验生成 JSON 诊断报告，保留请求、响应、工具记录与用量；不记录密钥和鉴权头。新闻内容不写入静态产品结论。

## 审查后保留的必要状态

- `_activeResponseId`：隔离不同响应重新开始的输出索引，不等同于 PreviousResponseId。
- 片段、工具定位索引：处理交错流式更新，不是未来能力占位。
- 用量报告集合：避免重复终态造成重复累计。
- 首次内容标记：只在实际接收展示内容时清理原有占位符。

## 未解决问题与后续待办

以下是实验限制，不用新增通用框架或防御层提前填补：

- 消息克隆、协议状态恢复、btw、子智能体分支及生命周期复用均未实现。
- 清空消息后旧信息对象的继续使用、直接对公开 MessageItems 集合 Clear 时订阅释放需要明确生命周期契约。
- 当前只维护活动响应索引；跨轮重放旧响应可能重复投影，尚不提供历史重放能力。
- standalone error 事件当前通过 JSON 构造 ResponseError，并可能构造无 ID 的响应记录；这是类型表达绕行，应在明确错误 API 时调整，而不是视为完整支持。
- Web Search 当前借用工具输出字符串展示状态、将 action 序列化为文本；尚无专门状态/引用展示用法，不作为生产交互设计。
- 引用展示、完整 SDK Item 覆盖、取消中断、部分输出和非常规终态不在当前完成范围。
- 信息对象已独立，暂留于 `CopilotChatMessage.Responses.cs`；文件名整理后续处理。

审查并不意味着这些行为已经正确；本轮删除无消费者的提前建设，其他涉及语义调整的问题明确记录，避免在清理过程中再次扩展设计。
