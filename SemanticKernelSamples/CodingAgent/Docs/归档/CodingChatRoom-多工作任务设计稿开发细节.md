# CodingChatRoom 多工作任务设计稿开发细节

## 1. 文档定位

- 项目：`CodingChatRoom.AvaloniaShell`。
- 设计输入：`Docs/设计稿/多工作任务设计稿.png`。
- 需求依据：
  - [CodingChatRoom 多工作任务并行改造需求](CodingChatRoom-多工作任务并行改造需求.md)
  - [CodingChatRoom 多工作任务并行改造设计](CodingChatRoom-多工作任务并行改造设计.md)
- 本文范围：将设计稿转换为聊天首界面的可实施开发细节。
- 本轮只输出文档，不修改业务代码、样式、项目配置或测试。
- 历史会话页和设置页沿用现有独立页面及导航能力，本文只规定它们在首界面中的入口位置，不展开其页面视觉改造。
- 应用最小窗口尺寸按 `1280 × 720` 设计，不为更小窗口增加折叠式或移动端布局。

设计稿作为视觉方向和信息组织参考，不作为逐像素实现合同。最终界面以真实产品能力、现有数据契约、可访问性和 Avalonia 可维护性为准。

## 2. 设计目标

首界面应让用户在进入应用后立即完成以下判断与操作：

1. 当前正在查看哪个工作任务。
2. 哪些任务正在后台工作，哪些任务处于空闲状态。
3. 当前任务使用哪个工作目录、模型和思考强度。
4. 当前会话正在发生什么，工具执行到了什么阶段。
5. 从哪里继续输入、插话、停止或调整下一次执行选项。

界面视觉采用设计稿体现的“深色任务导航 + 明亮聊天工作区”结构。任务管理与聊天阅读形成清楚分区，多任务并行状态是首界面的核心视觉信息，聊天内容是主工作区域。

## 3. 设计稿取舍结论

### 3.1 直接吸收的设计方向

- 左侧使用深色常驻任务栏，右侧使用明亮聊天工作区。
- 左侧顶部放置产品标识和“新建工作任务”主按钮。
- 工作任务以纵向卡片或列表项呈现，直接显示名称、路径和状态。
- 当前任务使用明显的选中强调，后台任务仍持续显示活动状态。
- 全部历史会话与设置固定在左侧底部。
- 右侧顶部集中展示当前任务名称、状态、会话信息、工作路径、模型和思考强度。
- 消息区保留用户、助手、系统、思考过程、工具调用、审批工具和子代理等既有消息类型。
- 底部输入区保持固定，消息区独立滚动。
- 使用克制的圆角、边框、层级背景和统一线性图标增强完成度。

### 3.2 根据真实产品能力调整的内容

| 设计稿表达 | 开发采用方式 | 原因 |
| --- | --- | --- |
| 任务显示 `68%` 等百分比 | 使用状态文字、活动指示和阶段说明；仅在底层存在真实可测量进度时显示百分比 | 模型执行通常没有可靠总进度，虚构百分比会误导用户 |
| 当前任务“工作中”，其他任务“后台运行”使用不同业务状态 | 底层保持同一运行状态；界面根据任务是否活跃决定是否补充“后台”语义 | “后台运行”是显示上下文，不是独立执行状态 |
| 黄色表示普通后台运行 | 普通运行统一使用品牌蓝或运行色；黄色用于等待、警告或需要关注 | 避免正常运行与警告混淆 |
| 自定义窗口最小化、最大化、关闭按钮 | 保留系统原生窗口标题栏 | 当前应用已有原生标题栏，自定义标题栏会增加拖拽、DPI、系统菜单和可访问性成本 |
| Developer、PRO、个性签名等账号区域 | 左侧底部只保留真实存在的设置入口和必要应用信息 | 当前产品没有账户与订阅模型，不展示虚构身份和会员状态 |
| 品牌区外跳按钮 | 品牌区保持纯展示 | 当前没有对应且必要的首界面命令 |
| 顶部任务百分比进度条 | 工作中使用细型不定进度条或轻量活动动画 | 与真实异步状态一致 |
| 用户消息旁点赞、点踩 | 保留复制正文、复制整条等真实消息操作 | 当前没有反馈提交能力，避免无效控件 |
| 添加图片按钮、图片图标、拖放大区域同时存在 | 使用一个明确的“添加图片”入口，加待发送缩略图；拖放能力可在整个输入区生效 | 减少重复入口并节省垂直空间 |
| 顶部“重命名”语义不明确 | 任务重命名放任务菜单；会话标题编辑仍由会话能力明确承载 | 任务名和会话标题必须保持独立 |
| 代码 Diff、语法高亮和复制代码 | 作为消息富内容的后续增强；首阶段不从普通文本猜测代码结构 | 当前消息模型没有完整 Markdown AST 或结构化 Diff 契约 |
| 顶部高级配置图标 | 先不单独增加入口，现有模型、思考强度和运行选项直接展示 | 避免出现没有明确内容的按钮 |

### 3.3 保持现有语义的关键点

- 同一任务工作中再次发送消息时，按钮文案使用“插话”，调用现有消息注入语义。
- 新建会话保留任务工作路径和任务运行配置，清空输入草稿与待发送图片。
- 停止操作只作用于当前任务，不影响其他任务。
- 修改工作路径、模型和思考强度按任务隔离。
- 工作任务名称与会话标题分别展示和编辑。
- “工作中”覆盖模型运行、工具调用、循环迭代、压缩、停止和最终保存，直到完整收尾结束。

## 4. 整体布局

### 4.1 窗口与主网格

- 最小窗口：`1280 × 720`。
- 推荐设计基准：`1440 × 900`。
- 保留原生窗口标题栏和现有动态窗口标题。
- 主内容使用两列：
  - 左侧任务栏：建议固定 `296` 逻辑像素，可在 `288`～`312` 范围内依据实际字体调整。
  - 右侧工作区：占据剩余宽度。
- 左侧与右侧通过背景对比和一条低对比度边界分隔，不使用重阴影。

### 4.2 右侧工作区纵向结构

右侧聊天首界面分为四层：

1. **任务状态栏**：当前任务名、运行状态、状态详情和停止操作。
2. **会话与执行配置栏**：会话标题及会话操作、工作路径、模型、思考强度。
3. **消息阅读区**：可滚动展示完整消息和工具过程。
4. **输入与运行选项区**：图片附件、消息输入、发送、循环迭代、自动压缩、`dotnet run`、压缩对话和 LSP 操作。

任务状态栏与配置栏可以合并为一个双层顶部区域，但数据层级必须清楚。顶部总高度建议控制在 `120`～`148` 逻辑像素，避免压缩消息阅读区。

## 5. 左侧工作任务栏

### 5.1 品牌区域

顶部展示：

- 应用图标。
- 主标题 `CodingChatRoom`。
- 一行简短副标题，例如“AI 编程助手”。

品牌区域高度保持紧凑，不占用任务列表的主要空间。图标直接复用应用现有图标资源，首期不新增需要单独维护的品牌图形。

### 5.2 新建工作任务

- 使用左侧唯一的高强调主按钮。
- 文案为“新建工作任务”。
- 按钮横向填满内容区。
- 创建完成后，新任务成为活跃任务，右侧显示其空会话。
- 创建过程中按钮显示忙碌状态并阻止重复点击。

### 5.3 任务列表标题

任务列表上方显示“工作任务”和当前任务数量。数量来自 `WorkTasks.Count`，实时随创建和删除更新。

不需要折叠整个任务列表。工作任务是首界面的主要导航，持续可见比节省少量空间更重要。

### 5.4 任务项信息层级

每个任务项默认展示三层信息：

1. **任务名称**：主要文本，单行省略。
2. **工作路径**：次要文本，优先显示已应用路径；未设置时显示“未设置工作路径”。
3. **运行状态**：状态图标、主状态文字，可选辅助状态详情。

完整路径通过 Tooltip 展示。路径文本不换行，避免不同任务卡片高度失控。

任务项右上角放置“更多”菜单。菜单包含：

- 新建会话。
- 查看相关历史会话。
- 重命名任务。
- 删除任务。

工作中的任务可额外显示一个紧凑停止按钮。停止是运行时高频操作，可直接出现；其余管理动作收纳到更多菜单，避免当前实现中四个按钮并排造成的杂乱。

### 5.5 任务项视觉状态

#### 当前任务

- 使用蓝色左侧强调条或浅蓝描边。
- 背景比普通任务项略亮。
- 名称使用较高字重。
- 保留清晰键盘焦点框，选中态与焦点态能够同时辨认。

#### 非当前但正在工作

- 状态位置显示运行色圆点或活动图标。
- 状态文字显示“后台工作中”或“后台正在压缩”等界面文案。
- 底层仍绑定任务真实操作状态，不创建第二套状态值。

#### 空闲任务

- 状态使用中性图标和“空闲”文字。
- 任务项仍保持完整可点击区域。

#### 失败或中断提示

- 主状态回到可操作的空闲状态后，保留一行“上次执行失败”或“上次执行中断”提示。
- 提示与当前运行状态分离，避免把“空闲”等同于“上次成功”。

### 5.6 底部导航

左侧底部固定显示：

- 全部历史会话。
- 设置。

两个入口使用导航项样式，而不是大块灰色按钮。当前页面对应入口应有选中反馈。进入历史或设置后，任务列表仍可见且继续更新后台状态；点击任务直接返回该任务聊天页。

## 6. 右侧任务状态栏

### 6.1 基本内容

状态栏左侧展示：

- 当前任务名称。
- 当前任务主状态。
- 状态详情文本。

右侧展示：

- 工作中时的“停止”按钮。
- 空闲时不保留停止按钮占位。

任务名称来自 `WorkTaskItemViewModel.DisplayName`，不能使用会话标题代替。

### 6.2 状态详情

状态详情来自真实操作阶段，例如：

- 正在准备运行。
- 正在生成回复。
- 正在执行工具。
- 正在压缩对话。
- 正在等待下一轮循环。
- 正在停止。
- 正在保存会话。
- 上次执行失败：简短错误摘要。

现有实现目前主要提供 `IsRunActive`、`IsCompressionActive` 和 `IsChangingWorkspace`。视觉改造第一阶段可以先映射为“工作中”“正在压缩”“正在应用工作路径”“空闲”；更细状态需要先补齐统一任务状态机，不能由 View 层根据零散布尔值猜测。

### 6.3 运行进度表达

- 普通 Agent 执行使用不定进度条或轻量脉冲图标。
- 工具本身提供真实进度时，可在工具卡片内部显示具体进度。
- 状态栏不显示估算百分比。
- 运行耗时只有在宿主持有可靠开始时间后才显示；显示格式为“已运行 8 分钟”或“已运行 01:24:16”。

## 7. 会话与执行配置栏

### 7.1 会话信息组

展示：

- 小标签“当前会话”。
- 当前会话标题。
- 新建会话按钮。
- 会话历史按钮。

任务名称已在上一层展示，因此这里明确使用会话标题，避免两种名称混淆。

新建会话在当前任务工作中时禁用，并通过 Tooltip 说明当前任务完成或停止后可操作。会话历史保持可用。

### 7.2 工作路径组

包含：

- 标签“工作目录”。
- 可编辑路径输入框。
- 选择目录按钮。
- 应用按钮。
- 已应用路径状态。

输入框对应 `WorkspaceInput`，已应用状态对应 `NextRunWorkspacePath`。两者必须保持视觉区分：用户输入但尚未应用时，状态行仍显示旧的已应用路径。

建议状态文案：

- 未设置：`当前未设置工作目录`。
- 已生效：`已应用：D:\Projects\ShopAdmin`。
- 正在切换：`正在应用工作目录…`。
- 失败：显示精简错误，完整内容进入 Tooltip 或系统消息。

目录选择按钮使用系统目录选择器。选择目录只填入输入框，仍由用户点击“应用”提交，使行为与手动输入一致。

### 7.3 模型组

- 使用带明确标签的 ComboBox。
- 显示模型的稳定可读名称，继续复用 `LanguageModelOptionViewModel.DisplayName`。
- 工作中禁用模型切换，当前执行继续使用启动时配置。
- 模型列表较长时，下拉项允许展示提供商和模型名称两级文本。

### 7.4 思考强度组

- 使用带明确标签的 ComboBox。
- 继续使用“默认、低、中、高”等真实选项。
- 工作中禁用切换。
- Tooltip 解释“默认”表示使用模型服务默认值。

### 7.5 顶部配置栏的布局策略

在 `1280` 宽度下，右侧可用宽度约 `984`。配置栏采用 Grid 分组，不使用绝对坐标：

- 会话组：`Auto` 或约 `260`。
- 工作路径组：占主要剩余宽度，最小约 `340`。
- 模型组：约 `190`。
- 思考强度组：约 `140`。

当文字较长时优先压缩会话标题和模型显示文本，并通过 Tooltip 展示完整内容。工作路径输入框保留最大伸缩空间。

## 8. 消息阅读区

### 8.1 整体表现

- 消息区使用极浅冷色背景，与顶部和底部白色操作区形成轻微层次。
- 内容区域左右保留舒适边距。
- 助手消息可使用较宽内容列，用户消息保持右对齐且限制最大宽度。
- 系统消息居中显示为轻量提示条。
- 流式更新保持现有自动滚动规则：用户停留底部时跟随输出，用户主动上翻后不抢夺滚动位置。

### 8.2 消息身份

#### 用户消息

- 右对齐。
- 使用浅品牌色背景。
- 显示“你”和时间。
- 图片随消息内容展示。

当前没有真实用户资料，不引入 Developer 头像或姓名。可以使用简单的“你”标记或统一用户图标。

#### 助手消息

- 左对齐。
- 使用应用图标或简洁 AI 图标。
- 显示“Copilot”和时间。
- 正文保持可选择与可复制。

#### 系统消息

- 用于工作目录切换、压缩结果、错误、取消和服务状态。
- 使用中性提示条；错误状态切换为错误语义色。

### 8.3 工具调用

现有 `CopilotChatToolItem` 已支持显示名称、主要文本、次要文本、输入和输出，继续采用 Expander：

- 折叠头显示工具名、简短说明和当前结果摘要。
- 展开后显示输入参数和工具输出。
- 长路径单行省略并提供 Tooltip。
- 工具完成、失败和运行中的图标由工具真实状态决定。
- 普通完成状态不使用大面积绿色背景，只在图标和状态文字上表达。

### 8.4 审批工具与子代理

- 审批工具保留“同意”“拒绝”操作，并使用比普通工具更明显的边界和提示。
- 子代理内容继续允许展开，标题明确表明子任务名称。
- 多任务并行与单任务内部子代理是不同概念，视觉上不要复用左侧工作任务卡片样式。

### 8.5 思考过程

继续使用默认折叠的 Expander。样式采用低对比度背景和左侧细强调线，与正式回答区分。展开状态不持久化到任务文件。

### 8.6 代码内容

首阶段保持现有可选择文本能力，不从字符串中临时解析复杂 Markdown。后续若引入结构化 Markdown 或代码片段模型，再实现：

- 等宽字体代码块。
- 语言标记。
- 复制代码。
- 结构化 Diff。
- 大代码块内部滚动和折叠。

这部分应建立在消息模型提供结构化片段之后，避免 View 中加入不稳定的正则解析。

### 8.7 消息操作

首阶段采用现有右键菜单：

- 复制正文。
- 复制整条消息。

后续可增加鼠标悬停操作栏，但命令仍复用统一消息命令。消息评价按钮在具备真实反馈服务后再接入。

## 9. 底部输入区

### 9.1 输入框与发送

- 输入框支持多行。
- 默认高度约 `72`～`96`，允许内容增长到合理上限后内部滚动。
- 占位文案保持简短，例如“输入编程问题”。
- 辅助文案显示 `Ctrl+Enter 发送，Shift+Enter 换行`。
- 发送按钮位于输入框右侧，使用主要按钮样式。
- 空闲时按钮文案“发送”，运行时按钮文案“插话”。
- 运行中插话仍要求存在有效文本或附件，并调用当前任务的注入逻辑。

### 9.2 图片附件

- 使用一个“添加图片”按钮。
- 待发送图片以横向缩略图列表显示在输入框上方或下方。
- 每个缩略图显示文件名和移除按钮。
- 输入区域可作为图片文件拖放目标，但视觉上只在拖入文件时显示覆盖提示，不长期占用大块空间。
- 支持格式继续以 `ImageAttachmentViewModel` 当前定义为准：PNG、JPEG、GIF、WebP、BMP。

### 9.3 运行选项

使用紧凑复选框或 Switch，包含：

- 循环迭代。
- 自动压缩对话。
- 启用 `dotnet run`。

这些选项属于当前工作任务。切换任务后显示对应任务自己的值。

工作中：

- 当前执行使用启动时快照。
- 选项可以按产品策略禁用，或者允许修改但明确“下次执行生效”。
- 首期建议工作中禁用，避免用户误以为会改变正在进行的调用。

### 9.4 次要操作

- “压缩对话”作为次要按钮，只有会话可压缩且任务空闲时启用。
- “结束 LSP 服务”放入输入区次要工具菜单或右侧低强调按钮，不与发送、停止争夺视觉权重。
- 停止当前任务放在顶部任务状态栏，底部不重复显示。

## 10. 状态与 ViewModel 契约

### 10.1 统一操作状态

设计稿落地需要把当前零散布尔值收敛为统一显示状态。建议新增内部枚举：

```text
Idle
ChangingWorkspace
Starting
Running
Compressing
LoopWaiting
Stopping
Saving
Failed
Disposed
```

`Failed` 表示最近一次结果，可与当前是否空闲分开建模。更稳妥的数据模型是：

- `OperationState`：当前操作阶段。
- `LastOutcome`：None、Succeeded、Cancelled、Failed、Interrupted。
- `StatusDetail`：当前阶段的可显示摘要。
- `StartedTime`：当前执行开始时间，可空。

任务列表和顶部状态栏从同一状态源派生，避免分别判断 `IsRunActive`、`IsCompressionActive` 和 `IsChangingWorkspace` 后出现不一致。

### 10.2 WorkTaskItemViewModel 建议属性

在现有属性基础上补充或调整：

- `DisplayName`
- `WorkspaceDisplayText`
- `WorkspaceToolTip`
- `IsActive`
- `OperationState`
- `StatusText`
- `StatusDetail`
- `IsWorking`
- `IsBackgroundWorking`
- `HasLastFailure`
- `LastOutcomeText`
- `CanStop`
- `CanCreateSession`
- `CanDelete`
- `StopCommand`
- `OpenMenuCommand` 或供 View 绑定的任务菜单命令

任务项不直接读取多个 Service 属性拼文案，状态组合放在 ViewModel 中完成。

### 10.3 ChatViewModel 建议属性

现有聊天 ViewModel 已包含大部分功能。为新布局补充显示投影：

- `TaskDisplayName`，或由父 ViewModel 单独绑定。
- `OperationStatusText`
- `OperationStatusDetail`
- `IsOperationActive`
- `CanEditRunConfiguration`
- `AppliedWorkspaceText`
- `HasWorkspaceInputDifference`
- `SendShortcutText`
- `CanStop`

不建议让 `ChatViewModel` 持有工作任务集合；多任务导航仍由 `MainViewModel` 管理。

### 10.4 命令可用性

| 命令 | 空闲 | 工作中 |
| --- | --- | --- |
| 切换任务 | 可用 | 可用 |

| 应用工作路径 | 可用 | 禁用 |

命令层必须再次校验状态，按钮禁用不能作为唯一并发保护。

## 11. Avalonia 视图拆分

为避免 `MainView.axaml` 继续膨胀，建议按以下方式拆分：

- `Views/MainView.axaml`
  - 只负责左右主布局和聊天/历史/设置页面切换。
- `Views/WorkTaskSidebarView.axaml`
  - 品牌区、新建任务、任务列表、历史与设置入口。
- `Views/WorkTaskItemView.axaml`
  - 单个任务项、状态、更多菜单和任务级快捷操作。
- `Views/ChatView.axaml`
  - 继续负责聊天首界面，可进一步拆出顶部和输入区。
- `Views/ChatTaskHeaderView.axaml`
  - 当前任务状态和停止操作。
- `Views/ChatConfigurationBarView.axaml`
  - 会话、工作路径、模型、思考强度。
- `Views/ChatComposerView.axaml`
  - 附件、输入、发送和运行选项。

拆分以减少 XAML 复杂度为目的，不为每个视觉小块创建独立 ViewModel。子视图可继续绑定 `MainViewModel`、`WorkTaskItemViewModel` 或 `ChatViewModel`。

## 13. 交互细节

### 13.1 切换任务

- 点击任务卡片主体切换任务。
- 点击更多菜单不触发任务切换。
- 切换后右侧立即绑定目标任务现有 `ChatViewModel`。
- 后台运行任务的消息、状态、附件和草稿继续保留。
- ChatView 切换 DataContext 后继续复用现有解除旧订阅、订阅新 ViewModel 和重置滚动逻辑。

### 13.2 重命名任务

- 从任务更多菜单进入编辑。
- 任务名在原位置变成单行输入框。
- Enter 保存，Escape 取消。
- 空白名称不能保存。
- 保存失败保留编辑内容并显示错误，不静默恢复旧值。
- 重命名不修改会话标题。

### 13.3 删除任务

- 空闲任务显示确认对话框，确认文案明确历史会话和工作文件仍保留。
- 工作中任务使用“停止并删除”确认流程，等待停止、保存和资源释放完成后再从列表移除。
- 删除过程中任务项显示“正在删除”并禁止重复操作。

### 13.4 停止任务

- 顶部停止按钮作用于当前任务完整执行链。
- 左侧后台任务可通过任务项菜单或紧凑停止按钮停止。
- 点击后状态立即进入“正在停止”，按钮禁用，等待真实完成。
- 停止完成且保存结束后变为空闲，并保留“已取消”结果提示。

### 13.5 工作路径

- 用户编辑输入框不会立即改变已应用路径。
- 应用成功后同步任务项路径和窗口标题。
- 应用失败时保留输入文本，便于修正。
- 工作中不允许应用新路径。

### 13.6 键盘操作

- `Ctrl+Enter`：发送或插话。
- `Shift+Enter`：输入换行。
- `Escape`：取消任务名编辑或关闭当前弹出菜单。
- 左侧任务列表支持方向键移动和 Enter 激活。
- 所有仅图标按钮提供 Tooltip 和 AutomationProperties.Name。

## 14. 性能与生命周期

### 14.1 后台任务更新

- 每个任务状态变化由任务自身事件驱动。
- 所有 ObservableCollection 和界面属性更新进入 Avalonia UI 线程。
- 活动动画使用 UI 共享动画资源，不为每个任务创建高频计时器。
- 运行耗时若显示，由单个低频应用级计时器刷新可见文本，建议一分钟内按秒、之后按分钟更新，避免频繁重绘。

### 14.2 消息滚动

现有消息区使用动态高度内容。首阶段保持现有实现并回归长会话性能；若实测出现布局或内存问题，再评估虚拟化。流式消息更新时不得每个 Token 强制执行昂贵的完整测量或无条件滚到底部。

### 14.3 事件订阅

- `WorkTaskItemViewModel.Dispose` 必须解除 Application 和 WorkspaceController 订阅。
- ChatView 在 DataContext 切换时解除旧 ChatViewModel 订阅。
- 删除任务后不允许后台迟到事件更新已经移除的任务项。
- 设置页与历史页打开期间，任务状态订阅持续有效。

## 18. 完成标准

本次设计稿落地完成后，聊天首界面应达到以下结果：

- 左侧任务栏具备稳定、整洁且容易扫描的任务导航。
- 用户可以立即区分当前任务、后台工作任务和空闲任务。
- 任务管理动作完整，但不会以大量并排按钮破坏视觉秩序。
- 右侧顶部清楚表达任务、会话、路径和模型配置的层级。
- 消息区适合长时间阅读正文、工具输出和图片。
- 输入、发送、插话、停止和运行选项具有明确主次关系。
- 所有进度和状态来自真实运行数据，不展示虚构产品能力。
- 界面保留设计稿的现代感，同时与现有多任务架构、会话语义和 Avalonia 实现保持一致。
