# CodingChatRoom 能力选择与内置提示词设计

## 1. 文档定位

本文针对 `CodingChatRoom.AvaloniaShell` 输入区当前只有“添加图片”入口、缺少“代码审查”“按照指令进行压缩”“代码重构设计”等发送前能力入口的问题，给出完整设计边界。

总体采用：

> **能力目录 + 可选 XML 配置 + Markdown 提示词 + 程序内置动作分派。**

能力只是“发送前的提示词处理与动作选择”，不是技能、插件，也不是另一套聊天系统。

本文只做设计，不修改业务代码、测试、项目文件或界面。

审核已合入的边界：

- 约定文件名用帕斯卡命名，XML 固定为 `Ability.xml`，默认提示词为 `Prompt.md`。
- **“编程”和“按照指令进行压缩”都是程序内置特殊默认项**，不依赖磁盘文件即可出现和执行。
- 能力选择入口放在“添加图片”**左边**。

---

## 2. 明确要做与不做

### 2.1 要做

- 在输入区底部增加能力选择下拉入口，位置在“添加图片”左侧。
- 默认选择“编程”，输入原样发送。
- “按照指令进行压缩”始终作为内置项存在，进入真实会话压缩流程。
- 每个文件夹表示一个动态能力。
- 支持可选 XML 配置，配置仅包含：
  - 提示词 Markdown 文件
  - 多语言名称
  - 能力 ID
- 将 Markdown 中的 `{{input}}` 替换为输入框内容。
- 普通能力将展开后的完整提示词直接发送、直接展示。
- 启动时、打开能力菜单时异步刷新；不等待，刷新完成后更新列表。
- 发送请求被受理后，立即切回“编程”；键盘和按钮行为一致。
- 保持不同工作任务的输入与能力选择互相独立。

### 2.2 不做

- 不做文件监听。
- 不做斜杠命令，包括命令解析、补全、别名和转义规则。
- 不增加能力专用的聊天气泡、折叠展示或消息元数据。
- 不做提示词预览面板、内置 Markdown 编辑器。
- 不做能力市场、远程下载、自动同步。
- 不支持脚本、动态程序集或任意本地动作。
- 不支持模板继承、模板引用、表达式和递归替换。
- 不在 XML 中增加图标、排序、快捷键、动作类型、参数等字段。
- 不改变技能发现、工具权限或智能体执行机制。

## 3. 能力目录结构

根目录固定为：

`%LocalAppData%\CodingChatRoom\Abilities`

对应 `CodingChatRoomPaths` 新增 `AbilitiesDirectory`。

每个直接子目录表示一个动态能力，例如：

```text
Abilities/
├─ CodeReview/
│  ├─ Ability.xml
│  └─ Prompt.md
├─ Compress/
│  ├─ Ability.xml
│  └─ Prompt.md
└─ 我的检查清单/
   └─ 检查清单.md
```

约定：

- 只枚举根目录的直接子目录。
- 根目录下散落的 Markdown 文件不识别为能力。
- 不递归发现能力。
- XML 固定名称为 `Ability.xml`。
- 随应用提供的提示词文件固定为 `Prompt.md`。
- 用户自定义 Markdown 文件名可以不是 `Prompt.md`，但程序写入的默认文件必须用帕斯卡命名。
- Markdown 采用 UTF-8，兼容 BOM。
- 不要求目录名等于显示名称或 ID。
- 目录名对程序提供的默认能力使用帕斯卡命名：`CodeReview`、`Compress`。

### 3.1 没有 XML 时

能力目录中：

- **只有一个 `.md` 文件**：直接采用它。
- 没有 `.md` 文件：能力无效。
- 多个 `.md` 文件：能力无效，不猜测使用哪个。
- ID 使用目录名。
- 显示名称使用目录名。

无 XML 的能力，其目录名就是身份；重命名目录会被视为新能力。有 XML 并显式指定 ID 时，可以重命名目录而不改变身份。

### 3.2 有 XML 时

XML 明确指定要使用的 Markdown 文件；其他 Markdown 文件不参与选择。

XML 如果格式错误或目标文件不存在，**不回退到无 XML 规则**，避免配置错误被掩盖。

---

## 4. XML 配置约定

配置逻辑结构限定为：

| 内容 | XML 表达 | 规则 |
|---|---|---|
| 标识 | `Id` | 必填、非空、稳定 |
| 提示词文件 | `PromptFile` | 必填，指向当前能力目录中的 Markdown 文件 |
| 多语言名称 | `Names` 下的多个 `Name` | 可省略；通过 `Culture` 属性区分语言 |

例如：

- `Id`：`code-review`
- `PromptFile`：`Prompt.md`
- 中文名称 `zh-CN`：代码审查
- 英文名称 `en`：Code Review
- 默认名称：Code Review

默认名称使用不带 `Culture` 的 `Name` 表示。

程序提供的默认 `Ability.xml` 中，`PromptFile` 一律写 `Prompt.md`。

### 4.1 ID 规则

- 按去除首尾空白后的值读取。
- 使用不区分大小写的序号比较。
- 不允许空白字符、路径分隔符和控制字符。
- 普通 Unicode 名称允许作为 ID，兼容无配置的中文目录。
- ID 不随当前界面语言改变。
- 不依靠显示名称判断执行行为。

保留 ID：

- `programming`
- `compress`

这两个 ID 属于程序内置项，目录能力不得作为独立菜单项覆盖它们。

重复 ID 的处理：

- 同一次扫描中出现重复的**动态能力 ID**，所有冲突项均不加载。
- 不按目录枚举顺序选取“第一个”。
- 记录诊断信息，指出冲突目录。
- 若多个目录都声称 `compress`，则全部不能作为压缩模板来源，内置压缩回退到程序默认要求，并记录冲突。
- 目录声称 `programming` 时直接拒绝该目录，不影响内置“编程”。

显示名称相同但 ID 不同的动态能力可以同时存在，菜单中显示 ID 作为辅助信息以便区分。

### 4.2 多语言名称回退

按以下顺序取名称：

1. 当前 UI 语言精确匹配，例如 `zh-CN`。
2. 父级语言，例如 `zh`。
3. 无 `Culture` 的默认名称。
4. 能力目录名。

内置项的显示名称走现有资源文件，不从目录名推导。

语言标识按标准 Culture 名称校验，不区分大小写。重复语言项或无效语言项视为配置错误。

### 4.3 路径与解析安全

- `PromptFile` 仅允许文件名，不允许绝对路径、子目录路径或 `..`。
- 必须是 `.md` 文件。
- 不跟随能力目录或提示词文件上的符号链接、重解析点。
- XML 禁止 DTD、外部实体及外部资源解析。
- 不识别的配置节点、属性应报告配置错误，避免拼写错误被静默忽略。

配置永远只是数据，不提供代码执行能力。

## 5. “编程”、压缩与随应用提供的模板

### 5.1 “编程”

“编程”是程序内置的特殊默认项：

- ID 固定为 `programming`。
- 不需要磁盘文件。
- 始终出现在能力菜单中。
- 模板内容为空，但发送行为是**直接使用原始输入**，不是发送空字符串。
- 始终可用。
- 不允许目录能力覆盖这个 ID。
- 继续支持现有图片发送行为。

### 5.2 “按照指令进行压缩”

压缩同样是程序内置的特殊默认项，不是“磁盘上恰好存在的普通模板”：

- ID 固定为 `compress`。
- 不需要磁盘文件即可出现在菜单中并执行。
- 始终走内置压缩动作，不能被目录配置改成普通提示词发送。
- 不允许目录能力作为另一个独立菜单项覆盖这个 ID。
- 磁盘上的 `Compress` 目录只用于覆盖**额外压缩要求模板**，不决定动作类型，也不决定菜单项是否存在。

模板来源：

| 情况 | 额外压缩要求 |
|---|---|
| 未找到有效的 `compress` 目录模板 | 使用程序内置默认要求 |
| 找到且仅有一个有效的 `compress` 模板 | 使用该模板展开结果 |
| 模板无效、冲突、越界或无法读取 | 回退程序内置默认要求，并记诊断 |

因此：

- 用户删除 `Compress` 目录后，菜单仍显示“按照指令进行压缩”。
- 现有“压缩对话”按钮和自动压缩也不会因目录缺失而失效。

### 5.3 随应用提供的普通模板

默认提供一个普通磁盘能力：

| ID | 目录 | 中文名称 | 行为 |
|---|---|---|---|
| `code-review` | `CodeReview` | 代码审查 | 普通提示词发送 |

它使用与用户能力相同的文件夹、`Ability.xml`、`Prompt.md` 结构。  
该 ID **不是**内置保留项；用户删除后，菜单中不再出现，也不会在后续启动中被重建。

`Compress` 目录随应用一次性写入，只作为内置压缩的可编辑模板来源。

### 5.4 默认文件初始化

为避免删除文件后又被自动创建，明确采用一次性初始化：

- 在能力目录中使用独立初始化标记，不污染 Shell 设置。
- 未初始化时，将 `CodeReview`、`Compress` 写入能力目录。
- 已存在目录不覆盖、不补写，不假设其中内容仍属于程序默认文件。
- 初始化成功后保存标记。
- 初始化失败记录错误，允许下次启动重试。
- 后续启动和应用升级不覆盖用户文件，也不重建用户主动删除的能力。
- “编程”和内置压缩菜单项不受初始化结果影响。

不在能力选择器中增加恢复默认、编辑、导入等管理功能；用户直接管理文件。

## 6. 模板处理

普通能力的执行输入为：

> Markdown 正文中的全部 `{{input}}`，替换为用户当前输入。

具体规则：

- 区分大小写。
- 只识别 `{{input}}`。
- 替换全部匹配项。
- 保留用户输入的换行和空白。
- 不递归替换。
- 不解释其他双大括号文本。
- 不进行 XML、HTML 或 Markdown 转义。
- 不修改文件内容。

例如输入自身含有 `{{input}}`，该文本在替换后保持原样。

内置“编程”不走模板替换。

内置压缩：将当前压缩模板中的 `{{input}}` 替换为本次输入，得到**额外压缩要求**。若使用程序内置默认要求且其中不含 `{{input}}`，则忽略输入框文字，或按内置默认模板的既有占位规则处理；程序提供的 `Compress/Prompt.md` 必须包含 `{{input}}`。

### 6.1 模板有效性

对动态磁盘能力，除内置项外：

- Markdown 为空或只有空白：无效。
- 没有 `{{input}}`：无效。
- 文件无法读取或解码：无效。
- 单个模板最大 1 MiB；XML 最大 64 KiB，超过限制不加载。

无效动态能力不出现在可选列表中，错误写入诊断日志，不弹出打断操作的对话框。

内置压缩的磁盘模板若无效，菜单项仍在，只是回退程序默认要求。

### 6.2 空输入和图片

| 场景 | 行为 |
|---|---|
| 编程，无文字、无图片 | 不发送 |
| 编程，有图片、无文字 | 保持现有图片发送行为 |
| 普通模板，无文字、无图片 | 不发送 |
| 普通模板，有图片、无文字 | 将 `{{input}}` 替换为空，连同图片发送 |
| 普通模板，有文字及图片 | 展开文字，原样附带图片 |
| 压缩，无文字 | 允许，表示没有额外压缩要求 |
| 压缩，存在待发送图片 | 阻止执行，提示先移除图片 |

能力不会改变模型支持图片与否的既有校验。

## 7. 界面与发送行为

### 7.1 入口

在输入区域底部，能力选择器放在“添加图片”左侧：

**[ 编程 ▾ ]　[ 添加图片 ]　　　　　　　　　[ 发送 ]**

对应现有 `ChatView.axaml` 输入区底部行：能力选择器、添加图片、快捷提示/停止、发送。

菜单顺序：

1. 编程。始终第一项。
2. 按照指令进行压缩。始终第二项。
3. 其他动态能力，按当前语言显示名称排序，ID 用于稳定决胜。

不增加自定义排序配置。

选择普通能力或编程后，发送按钮仍为“发送”；选择压缩后改为“压缩”。提示文本放入现有资源体系。

### 7.2 发送后重置

所有发送入口必须进入同一个提交方法，不能分别在鼠标事件、键盘事件中实现重置。

顺序固定为：

1. 捕获当前工作任务、会话、能力、输入、图片及运行选项。
2. 完成有效性与可执行状态检查。
3. 生成最终提示词和不可变请求快照。
4. 应用层受理请求。
5. **立即切换回“编程”。**
6. 执行请求并沿用现有结果展示。

“受理”指已通过检查并取得该任务的执行权，尚不要求模型调用成功。

因此：

- 成功受理后，即使网络失败、模型失败或用户取消，也不恢复旧能力。
- 检查失败、当前不能发送、没有可压缩历史等情况，不算发送成功，保留能力和草稿。
- 切回“编程”不影响已经捕获的执行快照。
- 用户可以在请求执行期间准备下一条输入，能力选择遵循现有输入区可用状态。
- 不因能力机制改变既有草稿清空、发送失败提示等通用行为。

## 8. 异步刷新：不等待、不监听

### 8.1 触发时机

只在以下时机发起刷新：

- 应用启动。
- 用户打开能力下拉菜单。

不做文件监听、定时刷新或手动刷新按钮。

默认文件初始化也放在后台初始化流程中，不阻塞界面。

### 8.2 展示行为

- 立即显示当前已有快照。
- 没有已加载动态能力时，动态能力区域保持空白。
- 不显示加载占位项，不等待扫描完成再弹出菜单。
- “编程”和“按照指令进行压缩”是固定项，仍然存在，不属于异步加载结果。
- 刷新成功后在 UI 线程整体更新列表。
- 菜单已经打开时，直接更新菜单内容，不关闭重开。
- 刷新可能更新压缩项所绑定的模板正文和显示名称覆盖，但不把压缩项移出菜单。

### 8.3 并发与一致性

- 应用共享一个能力目录快照。
- 同一时刻只执行一个扫描。
- 扫描期间再次打开菜单，复用当前扫描，不追加重复任务。
- XML、名称和 Markdown 正文作为一个能力快照一起发布。
- 发送使用当前已加载快照，**不在发送时等待磁盘重读**。
- 文件修改只有在后续刷新完成后生效，不影响已受理请求。

刷新后：

- 当前 ID 仍存在：更新对应定义和名称。
- 当前选中的是动态能力，且该 ID 已消失或变为无效：恢复“编程”，不清空输入。
- 当前选中的是 `programming` 或 `compress`：保持选中；若压缩模板变化，仅更新后续尚未受理的请求所使用的模板。
- 正在执行的请求继续使用原有快照。

错误边界：

- 单个动态能力错误：跳过该能力，其他能力正常加载。
- 根目录不存在：发布空的动态能力列表；内置两项仍在。
- 根目录因权限、I/O 等原因无法扫描：保留上次成功快照并记录错误；首次扫描失败则动态区域保持空白。
- 错误不弹窗，也不阻止发送“编程”消息或执行内置压缩。

## 9. 压缩动作的完整定义

### 9.1 不作为普通编程请求发送

选择 `compress` 后：

- 展开的 Markdown 是**本次压缩要求**。
- 不调用普通编程智能体让它“自行总结”。
- 进入现有真实压缩链路，更新实际会话上下文。

当前已有：

`CodingChatApplication` → `CopilotChatManager.ReduceSessionAsync(...)` → `IChatReducer`

应复用此链路。

### 9.2 自定义范围

最终压缩提示词分为：

1. **程序固定协议**：输出结构、必要字段、工具消息合法性、会话更新约束。
2. **模板展开结果**：用户可编辑的压缩重点和要求。
3. **待压缩历史**：由程序提供，不增加历史占位符。

模板不能替代固定协议，也不能声明执行其他本地动作。

磁盘 `Compress` 模板只能提供第 2 部分。

### 9.3 三个入口统一

| 入口 | 压缩要求来源 |
|---|---|
| 按照指令进行压缩能力 | 当前压缩模板 + 当前输入 |
| 现有“压缩对话”按钮 | 当前压缩模板，输入为空 |
| 自动压缩 | 当前压缩模板，输入为空 |

“当前压缩模板”指：有效磁盘 `compress` 模板，否则程序内置默认要求。

磁盘模板被删除或无效时：

- 能力菜单仍显示“按照指令进行压缩”。
- 现有手动压缩和自动压缩仍使用程序内置默认要求，不失去原有功能。

本次输入的额外要求仅用于本次能力调用，不写回模板、不影响后续自动压缩。

### 9.4 执行边界

- 没有可压缩历史或会话忙碌时不能执行。
- 显式压缩能力不进入循环迭代，也不启动新的编程运行。
- 压缩成功后不再重复触发一次自动压缩。
- 取消令牌贯穿模型请求和压缩过程。
- 验证结果前不替换原始上下文。
- 失败、取消或结果无效时保留原历史。
- 成功后沿用现有会话保存与摘要更新机制。

### 9.5 聊天展示

不新增压缩专用气泡。

- 沿用现有压缩记录和结果展示。
- 显式能力调用时，将现有“总结对话”请求记录的文字替换为**本次展开后的完整要求**。
- 保留该记录原有的压缩/预置信息语义，避免再次作为普通用户请求执行。
- 不额外插入一条普通消息，不产生双重请求。

现有手动按钮和自动压缩的可见记录保持原来的展示方式。

---

## 10. 普通消息展示与历史

普通能力完全沿用现有消息结构：

- 展开后的完整提示词就是用户消息。
- 聊天界面直接铺开展示。
- 历史保存的也是完整提示词。
- 不另存原始输入、能力名称、模板版本等能力专用字段。
- 不新增气泡标签、折叠内容或实际提示词查看器。
- 不同时写入原始输入和展开内容。

历史恢复、模型上下文和现有重试功能都使用已保存的消息内容，不重新读取能力模板。

因此模板以后修改，不会改变过去已发送的消息。

## 11. 代码职责与改动边界

| 位置 | 责任 |
|---|---|
| `CodingChatRoomPaths` | 提供 `AbilitiesDirectory` |
| 能力默认文件安装器 | 默认能力一次性初始化及独立标记 |
| 能力定义数据类型 | 保存 ID、名称映射、模板正文、来源目录、是否内置 |
| 能力目录服务 | 异步扫描、XML 校验、去重、快照发布；把有效 `compress` 模板绑定到内置压缩项 |
| 提示词处理组件 | 字面量替换与请求快照构造 |
| `ChatViewModel` | 菜单列表、当前选择、刷新触发、统一提交与重置 |
| `ChatView.axaml` | 能力选择器放在添加图片左侧，以及必要状态绑定 |
| `CodingChatApplication` | 根据 ID 分派普通发送或压缩 |
| 现有压缩实现 | 接收自定义要求、传递取消、保持压缩协议与提交一致性 |
| 现有资源文件 | 内置界面名称、提示及错误文本 |

不新增通用动作插件框架，不让 XML 决定任意执行类型。

能力目录服务为应用级共享服务；当前选择属于各自 `ChatViewModel`，不持久化。新工作任务、新会话及重启后默认“编程”。

内置两项的显示名称来自资源文件；若磁盘 `compress` 模板提供了多语言名称，可用于覆盖压缩项显示名称，但不能把它从菜单中移除。

## 12. 验收清单

### 12.1 文件与配置

- 无 XML、单 Markdown 能正确加载。
- 多 Markdown 且无 XML 时不加载。
- XML 指定 `Prompt.md`、多语言回退及显式 ID 正常。
- 程序写入的默认文件名为 `Ability.xml` 和 `Prompt.md`。
- 重复 ID、无效 XML、越界路径、外部实体、超限文件均正确拒绝。
- 用户文件不被初始化和升级覆盖。
- 删除 `CodeReview` 后不会在后续启动中被重新创建。
- 删除 `Compress` 后，内置压缩菜单项仍在，并回退程序默认要求。
- 目录声称 `programming` 时不出现第二个“编程”。

### 12.2 刷新

- 启动和菜单打开均不阻塞 UI。
- 首次扫描未完成时，动态区域为空，内置两项仍可见。
- 刷新结果能更新已经打开的菜单。
- 快速反复打开不会并发堆积扫描。
- 不创建任何文件监听器。
- 当前动态能力失效后回到“编程”，输入不丢失。

### 12.3 发送

- 能力选择器在添加图片左侧。
- 键盘和按钮共享提交逻辑。
- 受理后立即恢复“编程”，不等待运行结束。
- 校验失败不重置。
- `{{input}}` 全量、单次、字面替换。
- 普通能力直接展示并保存完整展开内容。
- 图片行为符合上述矩阵。
- 多任务选择、输入和请求不串用。

### 12.4 压缩

- 压缩是内置项，不因目录缺失从菜单消失。
- 自定义要求进入真实压缩器。
- 固定输出协议不被模板替换。
- 空输入允许，图片阻止。
- 失败和取消不破坏历史。
- 不启动普通编程或循环迭代。
- 临时要求不影响后续自动压缩。
- 磁盘 `compress` 模板缺失时，既有压缩功能仍然可用。

**最终边界：能力系统只负责本地文件发现、发送前模板替换和已知内置动作分派；“编程”与“压缩”均为程序内置项；聊天展示保持原样；刷新不等待、不监听；斜杠入口明确不做。**
