# 配置、安全与可观测性

## 配置边界

本方案禁止修改设置界面、设置文件格式和设置读写逻辑。

Responses 分支直接复用当前选中语言模型的既有配置：

- Endpoint；
- API Key；
- 模型名称与模型定义；
- 现有代理和客户端连接选项。

不增加 `Responses.Enabled`、能力集合、store、background、parallel tools 或 hosted tools 配置。所有现有 OpenAI 协议模型均可由入口尝试使用 Responses；端点不支持时显示真实错误，不自动回退 CodingAgent。

## 客户端创建

Responses 客户端创建集中在一个工厂或 `AgentLib` 的新增只读能力中，避免 Shell 重复拼接地址或读取凭据。

- 使用现有 `ApiEndpoint` 语义创建 SDK 客户端；
- 不修改用户已经可用的配置值；
- 不为 Responses 单独规范化、迁移或重写配置文件；
- 无法从当前模型取得 Responses 客户端信息时，入口明确说明该模型实现不支持 Responses 客户端创建。

## 必要安全边界

只保留不会妨碍正常使用的基本安全要求：

- 不在新增日志中输出 API Key 或 Authorization；
- 不把密钥写入会话文件；
- Web Search 结果不自动写入工作区；
- 本地函数工具继续使用现有路径、权限和沙箱语义；
- 取消令牌贯穿网络流和本地工具调用。

不新增审批系统、权限配置页、额外密钥库、数据保留工作流、请求正文审计器或复杂脱敏管线。

## 错误处理

直接保留有助于用户解决问题的信息：

- HTTP 状态与服务端错误消息；
- response status、code、param 和 response id；
- 工具名称与工具执行错误；
- 会话读取或保存错误。

UI 使用简洁可理解的错误文本；诊断日志记录现有日志体系能够承载的上下文。无需为每种错误创建独立异常类型，也不做自动重试、能力探测或协议回退。

## 可观测性

沿用现有 `FileCopilotChatLogger`，增加少量 Responses 运行信息：

- engine=`Responses`；
- provider/model；
- response/conversation id（存在时）；
- 完成状态；
- 工具名称、耗时与结果状态；
- token usage。

不记录 streaming delta 全文，不建立新的遥测管线或高频 sequence 日志。

## 用量映射

把 SDK 已返回的用量映射到现有 `UsageDetails`：

- InputTokenCount；
- OutputTokenCount；
- TotalTokenCount；
- CachedTokenCount；
- ReasoningTokenCount。

若现有类型缺少字段，只在 `AgentLib` 中增加可选成员，并保持旧 XML 可读。
