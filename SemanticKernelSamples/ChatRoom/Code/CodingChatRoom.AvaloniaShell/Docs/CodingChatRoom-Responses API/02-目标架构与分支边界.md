# 架构与分支边界（当前实现）

## 入口与装配

`ChatViewModel` 在发送、循环或手动压缩入口读取模式选择，取得 runner 后显式交给 `CodingWorkTaskController`。不实现模式锁定、切换检测、跨协议历史对齐或自动回退。

`CodingWorkTaskRuntime` 持有具体类型的 CodingAgentChatRunner 和按需创建的 ResponsesCodingChatRunner；组合根提供模型配置、附加工具源及提示词路径。Controller 不构造 Responses Agent，不接收创建工厂委托。

```text
ChatViewModel
  → CodingWorkTaskController
      → CodingAgentChatRunner → CodingAgent
      → ResponsesCodingChatRunner → ResponsesCodingAgent
                                     → ResponsesCodingAgentRunner
```

## 资源与历史归属

- CodingAgent 继续拥有 CodingWorkspaceCache 和工作区工具资源。
- Responses Agent 直接使用 CodingAgent 既有工作区工具获取方法，不复制工具。
- CodingWorkspaceRuntime、CodingWorkspaceRunLease 已否决并删除，不恢复，不把原有工作区上下文称为租约。
- CopilotChatManager 和 CopilotChatSession 是唯一业务会话体系。
- CopilotChatSession 延迟持有 CopilotResponsesSession。Shell runner 不维护按会话 ID 索引的第二套历史字典。
- 消息的 CopilotChatMessageResponseInfo 负责展示和用量，不能成为运行期间重建历史的数据源。

任务释放仍沿用现有运行对象逻辑；新建会话的重启逃生机制另行暂缓，不宣称已完成旧操作隔离。

## Runner 与运行结果

ICodingChatRunner 的当前操作：

- RunAsync：执行入口给定的输入、工作区及 CodingChatRunOptions。
- InjectMessageAsync：向活动运行提交插话。
- TryCompactConversationAsync：内部决定是否有可压缩历史；无历史 false，失败和取消传播。

CodingChatRunOptions 位于 AgentLib.Coding，只承载执行配置，不承载协议选择。

运行结果使用 ICodingAgentRunResult。ChatClientCodingAgentRunResult 和 ResponsesCodingAgentRunResult 是普通类，分别实现协议操作；公共契约不包含具体 runner 或协议特判。CompletedCodingAgentRunResult 仅承载消息及收尾任务。

## 插话

Responses 使用 ConcurrentQueue<ResponseItem>，当前请求继续执行。在工具批次结束后，或无工具终态准备退出时，追加插话并继续下一请求。多条插话按队列顺序处理，不取消重发，不增设极端时序防御。

Shell runner 向活动会话追加可见用户消息和日志，协议队列不从展示内容重建。

## 状态与取消

Controller 使用一个 CodingWorkTaskOperationState 枚举表达 Idle、Running、Compressing、Finalizing 及相应循环状态、循环重试等待。全部变更通过统一入口通知。

最外层发送、循环、手动压缩拥有操作生命周期及取消源；内部步骤只推进状态。清理取消源并完成收尾后才发布 Idle。循环继续开关是用户输入，不等同于循环活动状态。

已复现并修复第二轮取消循环后按钮通知停留在插话状态的问题，测试同时验证实际属性和最终通知值。

## 压缩边界

Responses 完全使用服务端 /responses/compact，无任何回退。手动入口和自动工具边界调用已接通，但真实压缩续聊未通过，不能标记产品能力完成。阈值与 CodingAgent 对齐，插话优先；详情见 14。

循环关闭自动压缩时残留的 Chat 专用历史裁剪职责仍需核查，不宣称已完全协议无关。
