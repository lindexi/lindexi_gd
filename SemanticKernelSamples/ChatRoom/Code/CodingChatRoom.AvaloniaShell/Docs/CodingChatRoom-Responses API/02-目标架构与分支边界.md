# 目标架构与分支边界

## 分支原则

ToggleButton 只决定新运行入口使用哪个 runner。`ChatViewModel.SendAsync` 开始时读取一次并保存到局部变量，之后不再观察 Toggle 状态。

```text
ICodingChatRunner runner = IsResponsesApiEnabled
    ? ResponsesRunner
    : CodingAgentRunner;

await Application.SendMessageAsync(runner, contents, options);
```

循环迭代同样在循环入口捕获一次 runner。运行中不设计切换、回切、迁移、锁定、警告或自动回退。

## 每任务对象图

```text
CodingChatRuntime
├─ CopilotChatManager                  唯一的可见会话与消息所有者
├─ CodingWorkspaceController           唯一的下一次运行工作路径
├─ CodingWorkspaceRuntime              唯一的工具资源所有者
├─ CodingAgent                         现有协议引擎
├─ CodingAgentChatRunner               现有执行分支，完整保留
├─ ResponsesCodingAgent                Responses 协议引擎
├─ ResponsesCodingChatRunner           Responses 执行分支
├─ CodingChatApplication               唯一的会话与运行协调器
├─ CodingChatSessionStore               同一格式保存可见历史及对应协议状态
└─ SettingsService
```

`CodingChatApplication` 继续独占：

- 会话列表、新建、打开、删除、重命名；
- 运行门、取消源、循环、最终保存和状态通知；
- 工作区快照与诊断日志；
- 手动和自动压缩的协调入口。

runner 只负责协议执行，不维护第二份会话列表或应用状态。

## Runner 契约

调整现有 Shell 内部契约，使其表达协议无关能力。`AgentLib.Coding` 允许同步修改 `CodingAgent` API，但 CodingAgent 分支及其能力必须保留：

```text
ICodingChatRunner
- RunAsync(contents, workspacePath, options, ct)
- InjectMessageAsync(contents, ct)
- CompactConversationAsync(session, ct)
- SupportsMessageInjection
- CanCompact(session)
```

具体签名以实现时最小需求为准。现有 `CodingAgentChatRunner` 保持原运行链，并将压缩委托给现有 `CopilotChatManager.ReduceSessionAsync`。Responses runner 使用 Responses compact/状态策略。

`CodingChatApplication.SendMessageAsync` 接收入口已选定的 runner。分支判断只存在于 `ChatViewModel` 的发送、循环和压缩入口，不散布到应用协调过程。仓库内原调用方同步迁移，不为 Shell 内部契约保留重复重载。

## 活动运行

Application 在运行开始时保存 `_activeRunner`，只用于本次运行的既有操作：

- 判断是否支持插话；
- 将插话交给本次 runner；
- 自动压缩调用本次 runner；
- 日志记录实际引擎。

`_activeRunner` 不是切换防御，不与 Toggle 比较，也不触发迁移。运行完成后清空。

现有 CodingAgent 分支继续支持消息注入。Responses 若没有等价的原生安全语义，则 `SupportsMessageInjection=false`，运行时发送入口不可用；不得用取消重发伪造“插话”。这不改变现有 CodingAgent 行为。

## 运行与资源所有权

- `CodingWorkspaceRuntime` 独占工作区缓存、Roslyn LSP 和工具对象。
- 每次运行获取不可变 `CodingWorkspaceRunLease`，包含工具注册和展示注册表。
- 两个 Agent 均通过 lease 使用工具；lease 结束前资源不能替换或释放。
- `CodingChatRuntime.DisposeAsync` 先取消并等待唯一 Application 的活动操作，再释放两个 Agent，最后释放共享 runtime。

业务不会让两个 runner 同时执行，但资源所有权仍由 lease 证明，而不是依赖 UI 偶然串行。

## 自然演进证明

- 新 Responses Item 或托管工具：增加独立注册与 projector handler，不改本地工具内核。
- 新协议：新增 runner/Agent，继续复用唯一 Application 和 workspace lease。
- Conversations 与无存储加密状态：替换 Responses runner 内部状态策略，不改 UI、会话管理和工具。
- 新消息 Item：增加 projector handler，不修改 Application。

后续目标是增加局部协议实现，不需要重做首个结构。
