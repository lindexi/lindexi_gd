# 测试与产品验收

## AgentLib 兼容测试

必须持续验证：

1. `AgentLib` 公开 API 基线无删除、改签名或语义破坏。
2. 旧 `AgentApiManagerConfiguration` JSON 继续反序列化。
3. 旧会话 XML 继续加载。
4. AgentLib 现有测试全量通过。

`AgentLib.Coding` 不做公开 API 兼容基线；其仓库内调用方和测试随架构同步迁移。必须通过行为回归证明 CodingAgent 分支仍具有原工具、提示词、压缩、取消和释放能力。

## Responses 单元测试

使用可注入 transport/client seam，覆盖：

- 文本与图片 Items 顺序；
- Instructions 单一来源；
- reasoning effort 与 summary 映射；
- 文本和思考摘要 delta；
- function call 参数、结果和多轮循环；
- 同批并行工具调用与稳定结果顺序；
- Web Search 请求注册、状态、annotations 和 citations；
- completed、incomplete、failed、error 和 canceled；
- usage 映射；
- conversation、previous response 与 store=false 状态续接；
- 旧会话格式和新增 Responses 状态读写。

测试不得调用真实网络，也不 mock 解决方案内的工具实现。

## 工具共享测试

- 两个 Agent 获得等价的工具名称、描述和 JSON Schema；
- `dotnet run` 只影响本次 run lease；
- 展示摘要一致；
- 同名工具冲突仍按现有规则处理；
- LSP 停止由共享 runtime 生效；
- 共享资源只释放一次。

## Shell 测试

- Toggle 关闭只调用 CodingAgent runner；
- Toggle 开启只调用 Responses runner；
- 发送或循环开始后改变 Toggle 不影响当前运行；
- Responses 失败不自动回退；
- 两套协议状态写入各自槽位；
- 停止、保存和释放作用于实际分支；
- 设置 View、设置 ViewModel、设置文件模型和设置读写行为没有 Responses 相关改动；
- 既有 Shell 测试全量通过。

## UI 验收

- Toggle 紧邻“启用 dotnet run”右侧；
- 聊天页只新增这一个控件；
- 文本、ToolTip、键盘操作和焦点可见性正确；
- 窄窗口及 100% 到 200% 缩放下不覆盖发送区和右侧操作区；
- 设置页面视觉树和交互保持不变。

## 真实端点验收

产品发布前使用真实 Responses 端点验证：

1. 文本流与图片输入。
2. reasoning summary。
3. 本地文件工具调用。
4. 同一 response 的多工具调用。
5. Web Search 及答案引用。
6. 多轮上下文，应用重启后继续。
7. 用户取消。
8. cached/reasoning token 记录。
9. 不支持 `/responses` 的端点显示真实错误且不回退。

## 发布门禁

- `AgentLib` API 基线通过；
- CodingAgent 与 Responses 两条路径均可独立完成编程任务；
- Responses Items、工具循环、Web Search、状态、流、取消和用量已验证；
- 旧配置与旧历史继续可用；
- 设置界面和设置逻辑无改动；
- UI 可用性验收通过；
- 不存在自动回退或未实现却宣称支持的能力。
