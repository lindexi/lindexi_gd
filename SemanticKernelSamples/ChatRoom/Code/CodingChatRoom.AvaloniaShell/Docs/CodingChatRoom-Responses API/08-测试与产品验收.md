# 测试与产品验收

## AgentLib 兼容测试

必须持续验证：

1. `AgentLib` 公开 API 原则上兼容；已确认的 `IManualSendMessageContext.LanguageModel` 接口扩展例外按 03 执行。
2. 旧 `AgentApiManagerConfiguration` JSON 继续反序列化。
3. 旧会话 XML 继续加载。
4. AgentLib 现有测试全量通过。

`AgentLib.Coding` 不做公开 API 兼容基线；其仓库内调用方和测试随架构同步迁移。必须通过行为回归证明 CodingAgent 分支仍具有原工具、提示词、压缩、取消和释放能力。

## Responses 单元测试

使用可注入 transport/client seam，覆盖：

- 文本与图片 Items 顺序；
- Instructions 单一来源；
- reasoning effort 与 summary 映射；
- 文本和思考摘要 delta；
- function call 参数、结果和多轮循环；
- 同批并行工具调用与稳定结果顺序；
- Web Search 请求注册、状态、annotations 和 citations；
- completed、incomplete、failed、error 和 canceled；
- usage 映射；
- 显式历史续接；store、previous response 与响应读取分别验证，不假定参数发送即能力生效；
- 旧会话格式和新增 Responses 状态读写。

离线单元测试不访问网络，不 mock 解决方案内工具实现。另设 `LiveApi` 分类的可选真实服务实验：密钥文件不存在则正常返回，存在才运行；只在内存中构造含密钥的 JSON 配置，不记录配置或鉴权头。

## 当前 API 实验的判断规则

- 测试首先展示调用写法，不以尚未完成的产品目标扩大改动范围。
- 历史续接用每次新生成的无认证含义随机标签，检查后续实际请求没有夹带标签或旧输入；查看完整回答是否包含标签，不用回答长度或严格格式判断记忆是否成功。
- 请求是否发送 store、响应如何报告 store、按 ID 读取是否成功、仅凭 ID 是否能续接分别判断，不相互替代；显式历史对照单独命名，不作为失败后的自动兜底。
- 本地工具由真实 AIFunction 执行；检查名称、参数、调用次数、结果、call_id、后续请求内容、最终回答及当前/累计用量。
- Web Search 检查发送的 tools 含 web_search，响应存在原生 WebSearchCallResponseItem，不能用模型自述搜索过作为证据。
- 缓存实验采用稳定长前缀和多轮新增内容，记录每轮 input tokens、cached tokens、命中率及累计加权比率，核验消息用量映射。缓存命中与服务端对话存储分开验证。
- 诊断文件记录时间、请求正文、HTTP 状态、完整响应、响应 ID、输出项类型、工具 action/状态、回答和用量，引用保留在原生响应中；取消或断言失败也保留已取得的诊断信息。
- 不记录密钥或鉴权头；真实测试只使用合成输入和公开检索内容。成功摘要未展示详细输出时，读取诊断文件再报告结论。

以下工具共享、Shell、UI 和发布门禁为后续产品验收，不代表当前实验已完成。

## 工具共享测试

- 两个 Agent 获得等价的工具名称、描述和 JSON Schema；
- `dotnet run` 只影响本次 run lease；
- 展示摘要一致；
- 同名工具冲突仍按现有规则处理；
- LSP 停止由共享 runtime 生效；
- 共享资源只释放一次。

## Shell 测试

- Toggle 关闭只调用 CodingAgent runner；
- Toggle 开启只调用 Responses runner；
- 发送或循环开始后改变 Toggle 不影响当前运行；
- Responses 失败不自动回退；
- 两套协议状态写入各自槽位；
- 停止、保存和释放作用于实际分支；
- 设置 View、设置 ViewModel、设置文件模型和设置读写行为没有 Responses 相关改动；
- 既有 Shell 测试全量通过。

## UI 验收

- Toggle 紧邻“启用 dotnet run”右侧；
- 聊天页只新增这一个控件；
- 文本、ToolTip、键盘操作和焦点可见性正确；
- 窄窗口及 100% 到 200% 缩放下不覆盖发送区和右侧操作区；
- 设置页面视觉树和交互保持不变。

## 真实端点验收

产品发布前使用真实 Responses 端点验证：

1. 文本流与图片输入。
2. reasoning summary。
3. 本地文件工具调用。
4. 同一 response 的多工具调用。
5. Web Search 及答案引用。
6. 多轮上下文，应用重启后继续。
7. 用户取消。
8. cached/reasoning token 记录。
9. 不支持 `/responses` 的端点显示真实错误且不回退。

## 发布门禁

- `AgentLib` API 基线通过；
- CodingAgent 与 Responses 两条路径均可独立完成编程任务；
- Responses Items、工具循环、Web Search、状态、流、取消和用量已验证；
- 旧配置与旧历史继续可用；
- 设置界面和设置逻辑无改动；
- UI 可用性验收通过；
- 不存在自动回退或未实现却宣称支持的能力。
