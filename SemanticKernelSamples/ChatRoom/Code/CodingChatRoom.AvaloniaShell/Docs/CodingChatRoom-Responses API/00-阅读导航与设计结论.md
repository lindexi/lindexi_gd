# CodingChatRoom Responses API 设计文档

## 文档目标

本文档集定义 `CodingChatRoom.AvaloniaShell` 对 OpenAI Responses API 的产品级支持方案。Responses 是独立的一等执行路径，不适配成 Chat Completions，也不替换现有 `CodingAgent`。

本文档集只有一套目标实现，不按阶段或版本拆分。

## 权威约束

1. `AgentLib` 公开 API 只允许增加，不允许删除、改名、改变参数语义或破坏二进制兼容。
2. `AgentLib.Coding` 允许为本次架构调整进行破坏性变更，但现有 `CodingAgent` 执行能力和 CodingAgent 分支必须完整保留。
3. 用户只在新运行入口处通过 ToggleButton 选择执行引擎；运行开始后不支持也不防御来回切换。
4. Responses 路径直接使用 `OpenAI.Responses` 的 Items、流式事件和有状态语义，不经过 `IChatClient` 适配。
5. 两条路径共享提示词、工作区工具、展示模型和应用协调层，但不共享协议状态机。
6. 唯一界面变化是在“启用 dotnet run”右侧增加一个经过布局设计的 ToggleButton。
7. 禁止修改设置界面、设置文件格式及其读写逻辑；现有模型配置均可进入 Responses 分支，真实端点不支持时按服务返回错误处理。
8. SDK 托管工具中，本方案要求第一等支持的只有 Web Search。

## 总体结构

```text
ChatViewModel
  └─ 在运行入口读取一次 IsResponsesApiEnabled
       ├─ false → CodingChatApplication → CodingAgentChatRunner → CodingAgent
       └─ true  → CodingChatApplication → ResponsesCodingChatRunner → ResponsesCodingAgent

AgentLib.Coding
  ├─ CodingAgent
  ├─ ResponsesCodingAgent
  └─ CodingWorkspaceRuntime
```

`CodingWorkspaceRuntime` 使两个 Agent 复用同一套 Roslyn、文件、.NET CLI、图片和沙箱工具。未来扩展 Responses Item、状态策略或新执行协议时，只扩展对应执行引擎，不重做工具基础设施、会话协调和 UI。
