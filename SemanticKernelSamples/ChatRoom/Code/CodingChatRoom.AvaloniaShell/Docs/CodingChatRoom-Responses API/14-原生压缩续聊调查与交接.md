# 原生压缩续聊调查与交接

## 当前结论

服务端 Compact 调用及原生结果保存已接通，但压缩后语义续聊尚未验收通过。根因未确认，不能宣称问题一定属于客户端、SDK、模型或服务端。

本文件是调查交接快照。旧文档、阶段性报告中的“通过”需区分能力验收与仅完成诊断请求。

## 当前实现

- `ResponsesCodingAgent.TryCompactConversationAsync` 使用模型提供的 ResponsesClient 调用 `/responses/compact`。无历史返回 false；请求错误、取消、解析错误传播，无回退。
- Compact 请求包含 model、完整原生 input 和 instructions。完整解析 output 后检查取消，再调用 `CopilotResponsesSession.ApplyCompaction` 替换历史。
- 下一次请求使用完整压缩输出，再追加新用户输入；自动压缩时在本地工具批次完成之后判断，没有待处理插话且达到阈值才执行，然后追加插话。
- CodingAgent 和 Responses 的条件/强制阈值为 200000/300000；条件分支要求本轮助手输出至少 10000。真实用量优先，缺失时字符数估算，不伪造统计用量。
- 可见消息不删除、不参与协议历史重建。存储初始化才允许恢复原生历史。
- 当前使用 OpenAI NuGet 2.13.0；工作区 `openai-dotnet` 源码版本标为 2.14.0，不应混同。

## 已确认的证据

1. 未压缩的真实多轮对话能回答随机项目标识和代码审查事实。
2. Compact 返回 HTTP 成功、response.compaction 和 output；实验中一般只有一个 compaction Item，encrypted_content 是可读摘要。
3. 原生压缩结果包含所需事实，但部分摘要存在事实改写或额外扩展，不能假设摘要绝对忠实。
4. SDK 将 compaction 读取为 InternalUnknownItemResource。源码显示 type/id 被保留，其余字段存入 Patch，再正常写出；完整请求测试未发现内容丢失。
5. 完全绕过 SDK 的 HttpClient + System.Text.Json 实验仍未成功续聊，SDK 类型转换不是失败的必要条件。
6. 离线审计真实请求链：所有 Compact output Items 在下一请求前缀完整保留，字段、值、顺序一致；其后仅追加新问题。
7. 多组中英文提示词、实际三轮代码审查、默认/显式 Compact instructions、结构化/简写用户消息、流式/非流式、字符转义、Accept 请求头、系统代理/直连，均未建立成功基线。
8. 原生 compaction、空上下文、无效 compaction 的输入用量曾相同；文本正向对照用量增加且能利用事实。这是有效输入行为线索，不证明服务内部实现。
9. 未知类型、缺 encrypted_content、数字 encrypted_content 曾返回 HTTP 200，与真实压缩 Item 用量相同。不能把 HTTP 成功等同于内容被模型使用。
10. 保留用户消息的诊断不能恢复仅存在于助手历史中的事实；不能将补回用户消息作为已验证修复。
11. 响应 GET 和 input_items 查询路径返回 404，未得到服务保存输入的额外证据。
12. M2.7 普通多轮基线通过，Compact 成功，续聊未通过；不能泛化所有模型能力。
