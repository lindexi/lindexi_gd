# 会话状态与持久化

## 状态模型

会话文件继续保存现有字段，并增加可选 Responses 协议状态：

```text
ChatCompletionsState
- 现有 AgentSessionState

ResponsesState
- ModelId
- ConversationId（使用 Conversations 时）
- PreviousResponseId
- StoredOutputEnabled
- 必要的本地 Responses Items（store=false 时）
```

可见消息用于展示历史；协议状态用于继续 Responses 上下文。两者职责不同。

## 续接策略

- SDK 和服务支持 Conversations 时，每个本地会话使用独立 conversation；
- 否则使用 `PreviousResponseId` 链；
- `store=false` 时保存继续上下文所需的 Responses Items 和 encrypted reasoning content；
- 不能从 UI 纯文本反推完整工具与 reasoning 上下文。

具体策略由 Responses runner 内部根据 SDK 返回与所用 API 形态确定，不增加设置项或设置文件字段。

## 分支状态边界

- CodingAgent 分支只读写现有 `AgentSessionState`；
- Responses 分支只读写 `ResponsesState`；
- 两种状态使用不同节点和编解码器；
- 不实现协议迁移、运行中切换、回切检测或自动回退。

Responses 分支首次运行时只以本轮文本和图片建立 Responses 上下文，不迁移已有 CodingAgent 协议状态。

## XML 兼容扩展

保持现有根元素、消息节点和 `AgentSessionState`，新增可选节点：

```xml
<ProtocolStates>
  <ResponsesState>...</ResponsesState>
</ProtocolStates>
```

规则：

- 旧文件无该节点时正常加载；
- 新文件保留现有节点语义；
- 格式版本递增，读取器继续支持旧版本；
- response/conversation id 可以保存；
- API key、Authorization 和完整原始请求不得保存。

`CopilotChatSessionPersistenceData` 通过可选协议状态承载 Responses 数据，原属性和公开 API 保留。

## 保存时机

复用现有会话保存流程，不新增原子替换、写前日志、双文件提交或高频运行检查点：

- 一轮 Responses 运行完成、失败或取消后，内存状态与可见消息一起进入现有保存流程；
- 完成本地工具批次后先更新内存状态，不对每个文本 delta 或 streaming event 写磁盘；
- 用户执行现有的新建、切换、关闭等会触发保存的操作时，按现有机制保存最新状态；
- 如果现有文件存储本身已采用临时文件替换，可继续复用，但本方案不要求为 Responses 新增该机制。

该设计保持状态一致性和代码可读性，不为极低概率异常退出恢复引入额外持久化状态机。

## 删除

删除会话沿用现有本地删除语义。本方案不增加远端 conversation/response 清理流程；服务端数据保留遵循所使用 API 与账号策略，不让本地删除依赖额外网络操作。
