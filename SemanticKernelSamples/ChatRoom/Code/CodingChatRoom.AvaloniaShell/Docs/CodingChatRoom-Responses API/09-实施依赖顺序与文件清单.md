# 实施依赖顺序与文件清单

## 说明

以下是同一产品级实现的依赖顺序，不是分阶段或分版本计划。

## 实施顺序

1. 固化 `AgentLib` 公开 API、旧配置和旧 XML 的兼容基线。
2. 在不修改设置模型的前提下，让现有 OpenAI 模型对象提供 Responses 客户端创建信息。
3. 提取 `CodingPromptProvider`，供两个 Agent 共享提示词。
4. 在 `AgentLib.Coding` 提取 `CodingWorkspaceRuntime` 和 run lease，并迁移现有 CodingAgent。
5. 实现 `AIFunction` 与 Responses function tool 的桥接。
6. 实现 Responses 请求、流式 Items、本地工具循环、Web Search、状态、取消和用量。
7. 扩展会话协议状态与 XML 读写，复用现有保存流程。
8. 调整 `CodingChatApplication` 接收入口已选定的 runner，并实现 Responses runner。
9. 在每任务 runtime 中装配两个 runner 和共享工作区 runtime。
10. 在发送与循环入口读取 Toggle 一次并选择分支。
11. 完成唯一 UI 变化：`dotnet run` 右侧 ToggleButton、必要的响应式布局和本地化资源。
12. 完成单元、兼容、UI 和真实端点验收。

## 代码审查门禁

- 不复制 CodingAgent 后改协议；
- 不在 Application 内散布 `if (useResponses)`；
- 不改设置界面、设置 ViewModel、设置文件或设置读写逻辑；
- 不把 response state 存入 UI ViewModel；
- 不为异常退出恢复引入原子检查点或额外事务状态机；
- 不为运行中来回切换增加锁、警告或迁移状态；
- SDK 托管工具只承诺 Web Search；
- 不接受超出 ToggleButton 所需范围的界面改版；
- 不接受未通过真实端点验收却标记产品级完成。
