# 界面与交互设计

## 唯一新增控件

在聊天页底部选项行中，将新的 `ToggleButton` 放在“启用 dotnet run”右侧：

```text
循环迭代 | 自动压缩对话 | 启用 dotnet run | Responses API [开关]
```

不增加新的卡片、标题栏、说明区、状态徽章或弹窗。禁止为 Responses 修改设置页、设置 ViewModel、设置文件及其读写逻辑。

## 控件语义

使用带可见文本的紧凑 ToggleButton，而不是无标签 Switch：

- 文本：`Responses API`
- 关闭：下一次运行使用现有 CodingAgent
- 开启：下一次运行使用 Responses API
- ToolTip：`下一次运行使用 OpenAI Responses API；关闭时使用现有 CodingAgent`
- AccessibleName 与可见文本一致

采用 ToggleButton 是因为它表示两种运行模式中的选中状态；不得使用普通 Button 模拟状态，也不得只用颜色表达状态。

## 布局

现有底部区域是 `Grid ColumnDefinitions="*,Auto"`，左侧横向 StackPanel 已有三个 CheckBox。增加控件后需保证窄窗口不挤压右侧操作区：

- 左侧选项容器改为可换行的 `WrapPanel`；
- 项间水平距离维持现有视觉节奏，行间距不小于 8；
- ToggleButton 高度与 CheckBox 命中区域一致；
- 文本不得缩写为无意义的 `Response` 或只放图标；
- 最小窗口宽度下允许选项换到第二行，不允许覆盖、裁切或水平滚动。

该变化只服务于新增控件后的响应式布局，不改变聊天页信息层级。

## 视觉样式

增加专用 `ToggleButton.ApiMode` 样式：

- 未选中：透明或中性背景，使用标准边框；
- 选中：使用现有 accent 资源的浅色背景和清晰边框；
- hover、pressed、focus、disabled 均有可辨识状态；
- 焦点轮廓不能被背景吞没；
- 不使用危险色、渐变、发光或自定义品牌图标。

用户面对的是执行方式选择，不是警告或实验功能，因此文案中不使用“测试版”“实验性”。

## ViewModel 行为

新增：

```text
IsResponsesApiEnabled
```

属性仅表示下一次入口选择，不持久化为会话状态，也不在运行期间被 Application 订阅。`SendAsync` 在清空输入前读取一次，选择对应 runner，并交给同一个 `CodingChatApplication` 完成运行协调。

当前模型或远端端点无法使用 Responses 时：

- Toggle 仍可见；
- 用户发送后显示客户端创建错误或服务端真实错误；
- 不自动退回现有 CodingAgent；
- 不偷偷修改 Toggle 状态。

自动回退会让用户误判实际使用的 API，违反模式选择的可见性原则。

## 现有功能语义

- 模型与思考强度对两条分支均生效；
- 图片对两条分支均保持顺序；
- `dotnet run` 只决定本地工具集合；
- 停止按钮作用于本次入口选择产生的活动分支；
- LSP 停止作用于共享 `CodingWorkspaceRuntime`；
- 自动压缩在 Responses 分支映射为 Responses 原生上下文管理/compact 策略，不显示成“已完成”但实际无效；
- 循环迭代每轮继续使用开始循环时捕获的分支，不在循环中重读 Toggle。

## 可用性验收

必须覆盖：

- 100%、125%、150%、200% 缩放；
- 中文和英文较长本地化文本；
- 最小窗口宽度；
- 键盘 Tab 顺序、Space 切换和焦点可见性；
- 高对比度下的选中与未选中区分；
- 开关右侧操作区不抖动、不被挤出。
