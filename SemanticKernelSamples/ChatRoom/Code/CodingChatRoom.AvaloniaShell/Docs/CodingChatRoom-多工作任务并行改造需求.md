# CodingChatRoom 多工作任务并行改造需求

## 1. 文档定位

项目：`CodingChatRoom.AvaloniaShell`。

本文是多工作任务功能的权威需求边界。未列入本文的旧需求、旧建议和旧待办均不属于该功能，不实施，也不存在“暂缓后再做”的含义。

实现必须复用现有结构，保持逻辑通顺、直接、可读。禁止补丁式修复、过度防御、过度设计和无必要抽象。

## 2. 必须实现

### 2.1 工作任务持久化

使用应用本地数据根目录下的 `WorkTasks.json` 保存工作任务元数据。

每个任务保存以下全部信息：

- ID；
- 名称；
- 已应用的工作目录；
- 采用的模型；
- 思考强度。

模型只保存能够从现有模型列表中重新选择模型的信息，不保存 API Key、模型客户端或其他凭据。

应用启动时恢复任务列表及上述配置。恢复任务不得自动发送消息、执行模型请求或启动工具。

只预期单个桌面应用进程中的正常交互，不考虑多个进程同时写入 `WorkTasks.json`。

### 2.2 历史恢复路径同步

从历史记录恢复会话后，目标工作任务的已应用工作目录必须同步为历史会话保存的工作路径。

## 3. 必须核查

以下事项先阅读现有代码和测试。现有逻辑正确时不修改；发现真实设计或行为问题时，修复根因。

### 3.1 任务独立性

每个工作任务必须拥有独立的：

- `CodingChatRuntime`；
- `AgentApiEndpointManager` 和模型选择；
- `CopilotChatManager` 与当前会话；
- `CodingAgent` 与工作区资源；
- `CodingAgentChatRunner`；
- `CodingChatApplication`；
- `CodingWorkspaceController`；
- `ChatViewModel`、输入、附件、运行状态和思考强度；
- 与任务上下文相关的图片、沙盒和 LSP 工具状态。

任务切换只改变界面投影，不停止或改写其他任务。

### 3.2 停止、删除、退出和释放

必须核查：

- 停止操作只影响对应任务；
- 停止覆盖循环等待、压缩和最终收尾；
- 任务运行期间删除操作安全；
- 任务运行期间退出窗口安全；
- Runtime 不泄漏；
- 删除任务后事件订阅完整解除，不保留对已删除任务的引用；
- 删除失败时原任务仍保留；
- 异步异常向用户提供可读提示。

不得为了假设性异常增加复杂状态机、额外协调层或重复释放逻辑。

### 3.3 设置与并行验证

必须核查和测试：

- 全局设置传播行为；
- 任务 A、任务 B 能够同时执行；
- 后台输出始终归属发起执行的任务；
- 停止一个任务不影响另一个任务；
- 模型客户端真实并行能力；
- 文件存储真实并行能力；
- 沙盒真实并行能力；
- LSP 真实并行能力。

上述并行验证以每个工作任务状态和 Runtime 依赖完全独立为前提。

## 4. 界面验收

必须先阅读界面代码和现有测试，再验收以下行为：

- 长任务名显示；
- 长路径显示；
- 原位重命名；
- 确认重命名后关闭编辑状态；
- 任务重命名不影响会话标题；
- 最小宽度下运行选项与底部按钮不冲突；
- 历史图标与思考强度选择框底部对齐；
- 任务菜单与任务名垂直居中；
- 控件 Hover 状态；
- 控件 Pressed 状态；
- 控件 Disabled 状态；
- 键盘焦点状态；
- 图标颜色继承；
- 普通按钮不受 Danger 配色污染；
- Mica 系统合成效果；
- 窗口非激活状态；
- 不支持 Mica 时使用浅色不透明回退；
- 设置页全部展开时的信息密度；
- 设置页保持单层功能分区。

Headless 测试可以验证声明、资源和布局，但不能代替 Windows 实机材质验收。

## 5. 永久非目标

以下事项明确不做，不属于该功能的后续阶段：

- 全局历史目录重构；
- 会话挂载注册表、同一会话单一可写挂载、加载预留和迟到事件协调；
- 后台历史索引增量同步体系；
- 持久化任务顺序；
- 持久化活跃任务；
- 持久化当前会话引用；
- 持久化自动压缩、DotNet Run、循环执行等运行选项；
- 持久化输入草稿、附件、运行状态或中断状态；
- 崩溃后自动续跑；
- 多进程并发写入协调、跨进程锁或跨进程隔离；
- 自动创建 Git worktree；
- 多 Agent 自动协作、任务依赖图或自动任务调度；
- 多窗口或远程多用户管理；
- 为以上非目标预留抽象、接口、字段或兼容逻辑。

现有已经工作的历史、导航和界面功能保持原样，不借此需求扩大重构范围。

## 6. 验证要求

- 为任务元数据保存和启动恢复添加自动化测试；
- 为历史恢复路径同步添加自动化测试；
- 复用并补充任务独立、停止隔离、设置传播和界面专项测试；
- 运行相关专项测试；
- 运行最新全量测试；
- 对必须依赖 Windows 实机或外部服务的项目，明确记录实际验证结果，不能用编译成功代替运行验收。
