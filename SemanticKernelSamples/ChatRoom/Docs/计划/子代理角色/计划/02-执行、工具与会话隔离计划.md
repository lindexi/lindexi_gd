# ChatRoom 执行、工具与会话隔离实施计划

## 1. 目标

本阶段完成当前 `ChatRoomManager` 执行链的两种子代理调用：

- 非 preset 消息在索引 0 Mention SubAgent，安排目标角色后续公开执行。
- Standard 角色通过 `InvokeChatRoomSubAgent` 同步取得目标结果，并继续当前模型轮次。

两条路径复用现有 `ChatRoomRole`、执行器、模型、技能、工作区、流式消息和 AgentSession 序列化能力，不创建第二套子代理 runtime。

固定语义：

- 子代理只接收本次任务文本。
- 每次逻辑调用使用新会话；同次 Standard 提醒复用该会话。
- Standard 必须通过 `ReturnOutputToCaller` 提交正式结果；未提交时只提醒一次。
- Coding 不注入 Standard 返回工具，使用现有 completion content。
- 每次真实模型输出仍是普通 Assistant 消息，并将外层和底层 `IsPresetInfo` 设为 true。
- preset 输出可见、可保存，但不会进入后续上下文或 Mention 调度。

## 2. 当前代码事实

### 2.1 Step 是必须复用的执行入口

`ChatRoomManager.ChatRoomAutoLoopRunner.StepAsync` 当前负责：

1. 构建增量输入。
2. 注入聊天室管理和工作区工具。
3. 调用 `ChatRoomRole.SpeakAsync`。
4. 创建并展示流式 `ChatRoomMessage`。
5. 完成静态文本并保存角色 AgentSession。
6. 处理取消、失败和 `CurrentSpeaker`。

子代理执行必须扩展这条链，而不是绕过它直接调用底层模型，否则会重复消息展示、持久化、错误处理和审批逻辑。

### 2.2 Standard executor 只有三个执行参数

`ChatRoomRoleExecutionContext` 当前只有：

```text
ChatManager
SystemPrompt
AdditionalTools
```

`StandardChatRoomRoleExecutor` 使用 `SelectedSession`，开启历史，追加全部 AgentLib 默认工具。它无法表达本次固定会话或排除默认 `InvokeSubAgent`。

### 2.3 AgentLib 已在一次 SendMessage 内捕获会话

`CopilotChatManager.SendMessage` 在启动时把 `SelectedSession` 捕获为局部 `currentSession`，本次消息、AgentSession 和日志随后都使用该对象。因此单次发送不需要会话栈。

真正缺少的是：

- 创建并取得一个确定的新会话。
- 第二次提醒发送时仍指定同一个会话。
- 序列化时明确使用本次会话，而不是当时的 `SelectedSession`。

### 2.4 默认工具只能全部开或全部关

`SendMessageRequest.AppendDefaultTools=false` 会同时关闭工作区默认工具和审批包装。ChatRoom 只需要排除 AgentLib 默认 `InvokeSubAgent`，不能用这个开关实现。

## 3. 最小执行契约

### 3.1 Step 调用选项

新增一个 internal 选项类型，名称按项目风格确定，例如 `ChatRoomRoleStepOptions`：

```text
TriggerMessage
TriggerMention
DirectTaskText
AdditionalUserMessages
AdditionalTools
UseFreshSession
MarkOutputAsPresetInfo
ReturnOutputCollector
```

约束：

- 普通 Participant 继续构建聊天室增量输入。
- SubAgent 必须有非空 `DirectTaskText`，不读取聊天室增量历史。
- SubAgent 强制 `UseFreshSession=true`、`MarkOutputAsPresetInfo=true`。
- Standard SubAgent 必须有 collector；Coding SubAgent 不需要 collector。
- 公开 `StepAsync(role, ct)` 保持不变，内部创建普通默认选项。

字段只用于现有 Step 链，不提升为跨程序集公共框架。

### 3.2 一次执行 core

将现有 Step 主体收敛为“一次模型运行”的内部 core。它负责：

- 选择普通会话或调用会话。
- 构造输入和工具。
- 调用 `SpeakAsync`。
- 创建、更新和完成一条普通 Assistant 消息。
- 在加入房间消息集合前设置 preset。
- 保存明确会话的 AgentSession。
- 返回消息、completion content 和实际会话。

core 不负责重试，也不递归调用自己。

### 3.3 Standard 最多两次运行

Standard SubAgent 外层编排固定为：

1. 创建本次 collector。
2. 创建本次新会话。
3. 使用任务文本运行一次 core。
4. collector 有结果则成功。
5. 否则在同一会话中发送固定提醒，再运行一次 core。
6. 仍未提交则失败，不执行第三次。

普通自然语言文本不是正式返回值。若 collector 已提交但公开文本为空，可用 collector output 填充本次已有消息；不得额外创建“工具结果”消息。

### 3.4 Coding 结果

Coding 目标继续走现有执行器：

- 不修改 `CodingChatRoomRoleExecutor.cs`。
- 不注入 `ReturnOutputToCaller`。
- AITool 路径使用现有 completion content 作为同步结果。
- Mention 路径只需要正常展示其 preset Assistant 输出。

若固定新会话无法在完全不修改 Coding executor 的前提下实现，优先在 `ChatRoomRole` 调用边界短暂选择新会话，让 executor 创建 manual context 后捕获它；不要扩展 Coding 工具和执行协议。

## 4. 最小 AgentLib 接缝

### 4.1 默认工具按名称排除

在 `SendMessageRequest` 增加只作用于默认工具的名称集合，例如：

```text
IReadOnlyCollection<string> ExcludedDefaultToolNames
```

`CopilotChatManager.ResolveTools` 在包装前过滤 `_toolManager.CreateDefaultTools` 的结果。ChatRoom Standard 固定排除：

```text
InvokeSubAgent
```

要求：

- 比较使用 `StringComparer.Ordinal`。
- request 自带工具不受排除集合影响。
- 空集合保持现有行为。
- AgentLib 不引用 ChatRoom 类型或工具名常量。

本功能只要求防止过滤后仍出现同名默认工具的直接冲突。不要借此建设通用工具策略、按类型过滤或复杂覆盖优先级。若现有底层对最终同名工具没有明确错误，可添加一个小型重复名称校验；不要把它扩展成独立框架。

### 4.2 创建并指定会话

实现以下能力即可，API 形状在编码时选择最贴近现有代码的一种：

- 创建并返回一个全新的 `CopilotChatSession`，不得复用空欢迎会话。
- `SendMessage` 可以明确使用调用方给定的 Session，或由一个重载接收 Session。
- `CreateManualSendMessageContextAsync` 在确有需要时可以明确使用给定 Session。
- `ChatRoomRole.SerializeAgentSessionStateAsync` 可以序列化给定 Session。

默认调用不传 Session 时保持现有行为。

不在首期实现：

- SelectedSession 栈。
- 通用 invocation scope 框架。
- 会话引用计数。
- 自动清理所有调用会话。
- 因猜测自嵌套而改写 `IsChatting`。

只有新增的自调用/嵌套测试证明 `IsChatting` 或 CTS 状态实际错误时，才在 AgentLib 做通用根因修复。

### 4.3 会话级 SystemPrompt

`ChatRoomRole` 当前用全局 `_hasSpoken` 决定是否注入角色提示词。新调用会话必须再次获得角色 SystemPrompt，同次提醒不能重复注入。

最小修正是把“是否已开始”绑定到本次 Session，例如依据 Session 的 AgentSession/消息状态判断，或维护会话 ID 集合。不得通过进入调用前清空 `_hasSpoken`、结束后恢复的方式模拟状态栈。

## 5. ChatRoom 返回协议和工具

### 5.1 collector

新增 internal collector，每次逻辑调用创建一个：

- 只接受一次非空正式输出。
- 第一次提交成功，第二次明确失败。
- 保留非空正文原文，不自动 Trim。
- 工具回调和执行完成读取之间保证可见性。

无需设计通用 result bus、channel 或多值聚合器。

### 5.2 `ReturnOutputToCaller`

工具固定名称：

```text
ReturnOutputToCaller
```

工具描述明确：

- Standard 子代理必须调用它提交正式结果。
- 普通文本不会自动成为调用结果。
- output 必须非空。

固定提醒文本由同一个协议类型提供，避免 Mention 和 AITool 路径漂移。

### 5.3 `InvokeChatRoomSubAgent`

新增 ChatRoom 自有工具 provider，参数保持最小：

```text
targetRoleId
prompt
```

调用时验证：

- RoleId 和 prompt 非空。
- 目标存在。
- 目标 `InvocationMode == SubAgent`。

不增加 Human、Manager、ParticipationMode、自调用、环路或最大深度限制。工具调用现有 Step 内部入口，并同步返回 Standard collector output 或 Coding completion content。

所有普通 Standard 非 Human 角色都可获得该工具；Standard SubAgent 本次运行额外获得 `ReturnOutputToCaller`。

## 6. 消息、speaker、取消和保存

### 6.1 preset 双层传播

子代理输出在加入 `Session.Messages` 前设置：

- `ChatRoomMessage.IsPresetInfo = true`。
- `CopilotChatMessage.IsPresetInfo = true`。

失败系统消息是否 preset 沿用现有错误展示语义，但必须保证不会继续触发 Mention。

### 6.2 `CurrentSpeaker` 恢复

AITool 内部调用会同步嵌套 Step。Step 开始保存 `previousSpeaker`，结束恢复它，而不是无条件设置 null。局部变量即可，不新增公开 speaker stack 类型。

### 6.3 取消

内层调用、一次提醒和保存沿用父工具调用的 CancellationToken。不新增父子 CTS 树。取消时移除未完成流式消息、恢复 previous speaker，不伪造 collector output。

### 6.4 AgentSession 保存

普通 Participant 保持现有保存语义。SubAgent 保存本次明确调用会话的状态；下次调用仍新建会话，不恢复该状态作为调用起点。

## 7. 按序实施任务

### 02-01 扩展 AgentLib 默认工具过滤

修改 `SendMessageRequest` 和 `CopilotChatManager.ResolveTools`，增加默认工具名称排除，并用现有 `SendMessageResult.ToolList` 测试过滤结果。

### 02-02 增加最小固定会话能力

让 Manager 可以创建并返回全新 Session，让 SendMessage/ManualContext/序列化在需要时使用指定 Session。保持所有默认重载行为。

### 02-03 将角色首次提示改为会话级判断

移除全局 `_hasSpoken` 对多会话的错误影响，保证新调用会话注入 SystemPrompt、同次提醒不重复注入。

### 02-04 新增返回 collector 和工具

实现 `ReturnOutputToCaller`、一次提醒常量和协议测试。不得修改 AgentLib 现有 `SubAgentToolProvider`。

### 02-05 扩展 Step 选项

在现有 AutoLoopRunner 内增加 internal 选项和一次执行 core，普通入口保持兼容。

### 02-06 实现 fresh-session 子代理执行

SubAgent 使用 direct task、新会话、preset 双层标记和明确会话保存；Participant 行为保持。

### 02-07 实现 Standard 一次提醒

首次未提交时，在同一 Session 和 collector 上执行一次提醒；第二次仍未提交则失败。

### 02-08 新增 `InvokeChatRoomSubAgent`

动态列出当前 SubAgent，调用 Manager 内部 Step，返回正式结果；注入所有普通 Standard 角色。

### 02-09 修复嵌套 speaker 与取消收尾

Step 使用 previous speaker 恢复；取消和失败移除流式消息，不污染 collector。

### 02-10 更新提示词

区分开头 Mention 的后续公开执行和 AITool 的同步结果；列出可调用 SubAgent 的 RoleId、RoleName、ExecutionKind 和简介。

## 8. 关键测试

### AgentLib 接缝

- 空排除集合保持默认工具基线。
- 排除 `InvokeSubAgent` 后仍保留工作区默认工具。
- 自定义同名工具与被排除默认工具可共存为单个工具。
- 新建两次调用 Session 得到不同 SessionId。
- 指定 Session 的消息和 AgentSession 不写入其他 Session。
- 默认 API 行为不变。

### Standard 返回协议

- 第一次提交成功。
- 空白和重复提交失败。
- 首次未提交、提醒后提交成功。
- 两次均未提交时失败且不执行第三次。
- 普通文本不替代正式 output。

### ChatRoom 调用

- Mention 和 AITool 都只传本次任务。
- 连续两次调用同一 SubAgent 不共享历史。
- 同次提醒能读取首次运行上下文。
- Standard AITool 返回后父角色继续当前轮。
- Coding 使用 completion content，Coding 执行器无差异。
- 子代理消息双层 preset，且不会触发后续 Mention。
- A 调 B 后 `CurrentSpeaker` 恢复为 A。

自调用和 A→B→A 只需要硬超时 smoke test，证明没有新增专用拒绝和明显会话串写；不要求首期证明任意深度调用框架。

## 9. 完成门禁

- Mention 与 AITool 两条调用链可用。
- Standard 正式返回协议严格执行一次提醒。
- 调用间无记忆、同次提醒有上下文。
- AgentLib 仅增加通用过滤和会话接缝，不引用 ChatRoom。
- 不修改 `AgentLib/Tools/SubAgentToolProvider.cs`、`AgentLib/Model/CopilotChatSubAgentItem.cs`、`AgentLib.ChatRoom/CodingChatRoomRoleExecutor.cs` 和 `AgentLib.Coding/**`。
- 未增加 invocation stack、环路检测、最大深度、父子取消树或第二套执行框架。
