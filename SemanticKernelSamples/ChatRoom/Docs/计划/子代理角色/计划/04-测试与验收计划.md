# ChatRoom 子代理角色测试与验收计划

## 1. 目标

本册只组织验证顺序、回归边界、提交建议和最终完成定义。具体业务契约以前三册为准，不在这里复制全部设计。

测试原则：

- 每个阶段先补最小失败测试，再改生产代码。
- 每个阶段结束运行目标测试和相关项目构建。
- 异步模型/工具/自动循环测试必须有硬超时。
- 使用项目现有 MSTest 与中文 `DisplayName` 约定。
- 不把依赖真实网络、模型或本机配置的测试作为稳定 CI 门禁。

## 2. 建议实施与提交顺序

### 批次 A：模型和解析

范围：

- legacy/Domain InvocationMode。
- 结构化 Mention。
- 消息 IsPresetInfo/Mentions。
- 唯一 MentionParser。
- 深复制和映射编译迁移。

门禁：

- Mention 现有语法回归通过。
- span、来源 MessageId 和集合不变量通过。
- 解决方案中不再有生产用 `MentionedRoleIds`。

推荐单独提交，便于后续调度问题定位。

### 批次 B：调度和可见性

范围：

- legacy trigger 队列项。
- Participant/SubAgent/preset 调度表。
- 默认队列和管理者排除。
- 任务文本提取。
- legacy/Coordinator 顶层输入过滤。
- 仅 InvocationMode 更新不替换 Coordinator runtime。

门禁：

- 普通 Participant 行为无回归。
- Human/Assistant 开头 Mention SubAgent 调度。
- 中段、前导空白和 preset 不调度。
- Coordinator 顶层语义测试通过。

### 批次 C：AgentLib 最小接缝

范围：

- 默认工具按名称排除。
- 创建/指定 Session。
- 明确 Session 的 manual context 和序列化（按实现需要）。

门禁：

- AgentLib 默认 API 行为不变。
- 排除 InvokeSubAgent 后仍保留工作区默认工具。
- 指定 Session 不串写。
- AgentLib 不引用 ChatRoom。

该批次应能独立构建和测试。

### 批次 D：legacy 子代理执行

范围：

- Step options 和一次执行 core。
- fresh invocation session。
- 会话级 SystemPrompt。
- ReturnOutputToCaller 和一次提醒。
- InvokeChatRoomSubAgent。
- preset 双层传播。
- CurrentSpeaker 恢复。

门禁：

- Mention 与 AITool 两条链可用。
- 连续调用无记忆，同次提醒有上下文。
- 父 Standard 得到工具结果后继续当前轮。
- Coding executor 和 AgentLib.Coding 无改动。

### 批次 E：持久化和 Avalonia

范围：

- 三套格式版本切换。
- 新字段往返和旧版拒绝。
- 模板复制路径。
- 角色编辑/列表/Mention 插入/发送文本。
- README。

门禁：

- 新格式往返通过。
- UI 能创建、编辑和触发 SubAgent。
- 前导空白不被发送流程改写。
- 消息模板没有分叉。

## 3. 分层测试矩阵

### 3.1 纯模型和纯函数

优先放在 `AgentLib.ChatRoom.Tests`：

- `ChatRoomMention` 构造不变量。
- `ChatRoomMessage` Mentions 来源、顺序、重复和 span。
- MentionParser 普通/方括号、大小写、边界、顺序和首次去重。
- SubAgent 任务文本提取。
- collector 非空、一次提交和并发可见性。

这些测试不需要 fake model，执行应快速稳定。

### 3.2 legacy Manager 集成

使用现有 fake executor/fake provider 测试：

- 默认队列与管理者组合。
- Human/Assistant 的 Participant/SubAgent Mention 调度表。
- preset 上下文和调度过滤。
- Step direct task 与普通增量输入分流。
- Standard 一次提醒。
- Coding completion result。
- CurrentSpeaker 嵌套恢复。
- 取消时流式消息清理。

不要为了测试创建第二套生产 invoker；通过 internal 可见性测试现有 Step 接缝。

### 3.3 AgentLib

在 `AgentLib.Tests` 中覆盖：

- 默认工具过滤。
- request 自定义工具不被排除。
- 新会话唯一性。
- 指定 Session 的消息、AgentSession 和日志目标。
- 默认重载保持 SelectedSession 行为。

多目标项目至少运行仓库当前支持并用于 CI 的目标框架。若本机缺少某个预览 SDK，应明确记录环境限制，不通过修改项目降级规避。

### 3.4 Coordinator 架构测试

首期只验证：

- Domain 模型新字段和深复制。
- Coordinator 使用共享 Mention 语法。
- 默认队列和管理者排除 SubAgent。
- preset 不进入 runtime InputMessages，但输入上界可跨过它。
- 开头 Mention SubAgent 顶层执行只获得任务文本和 null checkpoint。
- 仅 InvocationMode 更新不 Replace runtime、不清 checkpoint/水位。

明确不要求：

- Coordinator Standard AITool 内部角色调用。
- execution host 或内部调用命令。
- 同角色嵌套 revision 重基线。
- 多 public output candidate。

### 3.5 持久化

沿用现有测试类扩展，不新建大型格式测试框架：

- `ChatRoomPersistenceTests`：legacy version、新字段和拒绝场景。
- `RoleTemplateServiceTests`：version、复制路径和坏文件隔离。
- `ChatRoomSnapshotMapperTests`：schema 3、Stored Mention 和 transient state。
- `ChatRoomManagerTests/IntegrationTests`：恢复 preset 与 AgentSession 行为。

### 3.6 Avalonia

优先测试 ViewModel，不做脆弱的像素/视觉测试：

- RoleEdit 调用模式映射。
- RoleItem 显示文本。
- Participant/SubAgent Mention 插入。
- SendAsync 保留前导空白。
- 子代理消息仍投影到现有 MessageItemViewModel。

## 4. 必须覆盖的端到端场景

### 场景 1：Human 开头 Mention Standard SubAgent

输入：

```text
@审查员 检查当前改动
```

断言：

- Mention StartIndex 为 0。
- 目标被调度，只收到“检查当前改动”。
- 使用新会话。
- 正式 output 提交成功。
- 公开 Assistant 消息 preset=true。
- 后续 Participant 上下文不包含该消息。

### 场景 2：Standard AI 同步调用 Standard SubAgent

断言：

- 父角色工具列表不含 AgentLib 默认 InvokeSubAgent。
- 存在 InvokeChatRoomSubAgent。
- 子代理存在 ReturnOutputToCaller。
- 工具结果返回父角色，父角色继续同一轮。
- 子代理公开消息仍在聊天室时间线。

### 场景 3：首次未提交，提醒后提交

断言：

- 只提醒一次。
- 两次运行使用同一 SessionId 和 collector。
- 提醒时可读取首次运行上下文。
- 下一次新任务使用不同 SessionId。

### 场景 4：Coding SubAgent

断言：

- 不注入 ReturnOutputToCaller。
- AITool 返回现有 completion content。
- Mention 输出正常展示为 preset。
- `CodingChatRoomRoleExecutor.cs` 与 `AgentLib.Coding/**` 无差异。

### 场景 5：位置和 preset 边界

参数化覆盖：

- Human/Assistant。
- 普通/方括号 Mention。
- StartIndex 0、中段、前导空白。
- preset true/false。
- Participant/SubAgent。

断言严格遵循 `01` 的调度表。

### 场景 6：保存、关闭和恢复

断言：

- 新格式保存 InvocationMode、preset 和 Mentions。
- 恢复后消息仍可见且不进入上下文。
- SubAgent 下一次调用不使用恢复会话。
- Participant 仍可延续恢复的 AgentSession。

## 5. 自调用与嵌套的测试边界

需求不增加自调用或环路拒绝，因此至少添加有硬超时的 smoke test：

- A 调 A 不因 ChatRoom 专用校验被拒绝。
- A 调 B 后父 speaker 恢复。
- A→B→A 不发生明显 Session 串写。

若测试暴露 `CopilotChatManager.IsChatting`、CTS 或 SelectedSession 的通用错误，先记录失败证据，再做最小通用修复。不得在没有失败证据时预先实现：

- 活动发送引用计数。
- invocation stack。
- 深度限制。
- 环路检测。
- 每角色 Semaphore。

首期不把“任意深度环路最终一定终止”作为完成条件；没有深度限制的系统本来也不能提供该保证。

## 6. 构建和测试命令层级

实现时按以下层级逐步扩大范围：

1. 修改文件的编译错误检查。
2. 相关测试类。
3. 相关测试项目。
4. `AgentLib.ChatRoom` 与 Avalonia 项目构建。
5. `ChatRoom.slnx` 完整构建。
6. 最终相关测试集合。

优先使用 Test Explorer 的类/方法过滤运行测试。完整构建失败时区分：

- 本次修改引入的编译或测试回归。
- 既有预览 SDK、真实模型配置、网络或本机环境问题。

只有后者可以作为已知环境限制记录；不得把本次回归归为环境问题。

## 7. Git 差异审查

最终必须确认以下文件无差异：

- `SemanticKernelSamples/AgentLib/AgentLib/Tools/SubAgentToolProvider.cs`
- `SemanticKernelSamples/AgentLib/AgentLib/Model/CopilotChatSubAgentItem.cs`
- `SemanticKernelSamples/AgentLib/AgentLib.ChatRoom/CodingChatRoomRoleExecutor.cs`
- `SemanticKernelSamples/AgentLib/AgentLib.Coding/**`

同时检查：

- 没有长期 `MentionedRoleIds` 双写。
- 没有子代理专用 runtime/invoker/命令/UI 消息类型。
- 没有 invocation stack、环路检测、最大深度或父子取消树。
- 没有通用 JSON shape validator。
- 没有把 Coordinator 内部 AITool 嵌套偷偷带入首期。

## 8. 最终完成定义

只有同时满足以下条件才算完成：

- InvocationMode 与其他角色字段正交。
- legacy 和 Coordinator 的基础 Mention/preset/顶层调度语义一致。
- legacy Mention 和 Standard AITool 均可调用 SubAgent。
- Standard 严格使用 ReturnOutputToCaller，并只提醒一次。
- Coding 保持现有执行链。
- 子代理调用内有状态、调用间无记忆。
- 子代理输出正常展示、保存、恢复，但不污染上下文和调度。
- 三套格式只接受当前版本。
- Avalonia 可编辑、展示并正确插入 SubAgent Mention。
- README 已说明使用方式和限制。
- 禁止修改范围无差异。
- 相关测试和构建通过，或仅剩已明确记录且与本次无关的环境限制。
