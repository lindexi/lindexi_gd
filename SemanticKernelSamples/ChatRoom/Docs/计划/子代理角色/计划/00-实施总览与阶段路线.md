# ChatRoom 子代理角色实施总览与阶段路线

## 文档状态

- 状态：待实施
- 交付类型：多分册实施计划总览
- 推荐方案：[方案一：独立 InvocationMode](../候选方案/方案一-独立InvocationMode.md)
- 产品入口：legacy `ChatRoomManager`
- 一致性入口：`Domain` + `ChatRoomCoordinator` + `Runtime`
- 适用解决方案：`SemanticKernelSamples/ChatRoom/ChatRoom.slnx`
- 本轮数据策略：直接升级当前开发格式，不实现旧会话、旧模板或旧 snapshot 迁移

## 1. 文档目的

本目录把“独立 `InvocationMode`”方案拆成可以逐批实施、逐批验证的计划。每个分册只覆盖一个相对稳定的改造面，避免实现者一次加载候选方案全文，也避免在同一个提交中同时修改模型、调度、工具、持久化和 UI。

本总览负责：

1. 固定需求与设计解释的优先级。
2. 记录开始实施前的真实代码和测试基线。
3. 定义分册依赖关系、推荐提交边界和阶段门禁。
4. 标出候选方案与当前代码之间必须先处理的架构差异。
5. 明确禁止顺手修改的范围。

### 2.2 已确认的文档差异

推荐方案是后续修订版本，以下内容以推荐方案为准：

- 任意**非 preset** 的 Human 或 Assistant 消息，只要子代理 Mention 的 `StartIndex == 0`，都可触发子代理；不再按发送者类型区别处理。
- 子代理调用复用角色配置和现有执行链，但调用会话每次新建；不继承上一次子代理调用的会话历史。
- 子代理本次调用可以正常生成并保存 `AgentSession` / checkpoint；下一次调用只是**不恢复**该 checkpoint，而不是禁止写入 checkpoint。

候选方案“测试计划 15.7 第 5 条”中“子代理调用不创建或更新 RoleCheckpoint”与该方案其他章节冲突，应视为笔误。正式验收采用“允许提交最近一次调用 checkpoint，但后续子代理调用忽略它”的语义。

## 3. 当前代码基线

### 3.1 生产与目标架构

当前桌面应用仍使用：

```text
ChatRoomService
  -> ChatRoomManager
      -> ChatRoomAutoLoopRunner
          -> ChatRoomRole
              -> StandardChatRoomRoleExecutor / CodingChatRoomRoleExecutor
```

以下新架构已经存在并有架构测试，但尚未接入 `ChatRoomService` 或 Avalonia 生产链：

```text
ChatRoomCoordinator
  -> ChatRoomState
  -> ChatRoomRoleRuntimeRegistry
  -> IChatRoomRoleRuntime
  -> IsolatedChatRoomRoleRuntime
```

因此，本功能分两条轨道交付：

- **生产轨道**：先完成 legacy 行为，使桌面应用真正获得子代理能力。
- **一致性轨道**：随后更新 Domain/Coordinator/Runtime，使同一角色和消息数据在未来切换到 Coordinator 后保持相同解释。

不得为了实现本功能提前把 Avalonia 全量迁移到 Coordinator，也不得撤销正在进行的状态架构重构。

### 3.2 当前实现事实

- legacy 与 Domain 都只有 `AlwaysParticipate` / `MentionOnly`，尚无 `InvocationMode`。
- legacy `MentionParser` 使用正则，支持 `@角色名` 和 `@[角色名]`，按首次出现去重，但只返回 RoleId。
- Coordinator 有独立的私有 Mention 解析逻辑，语法与 legacy 不完全一致。
- legacy 与 Domain 消息都只有 `MentionedRoleIds`，没有匹配位置和 `IsPresetInfo`。
- legacy 默认队列、Mention 优先队列和管理者兜底都尚未排除子代理。
- `BuildIncrementalUserMessages` 与 `IsolatedChatRoomRoleRuntime.BuildIncrementalMessages` 尚未过滤 preset 消息。
- `StandardChatRoomRoleExecutor` 会把 `AdditionalTools` 交给 `SendMessageRequest`，但 AgentLib 默认工具仍会追加 `InvokeSubAgent`。
- `SendMessageRequest` 只有全开/全关的 `AppendDefaultTools`，没有按函数名排除默认工具的能力。
- legacy `ChatRoomRole` 长期持有一个 `CopilotChatManager`，普通发言延续其当前 `SelectedSession`。
- Coordinator 的 `IsolatedChatRoomRoleRuntime` 每次执行都会创建并释放一个 legacy `ChatRoomRole`，Participant 通过 checkpoint 恢复上下文；它并不长期持有 UI 型 `ChatRoomRole`。
- Coordinator 当前只允许一个顶层 `CurrentExecution`，活动父执行期间会拒绝第二个 `StartRoleExecutionCommand`。
- legacy `room.config.json` 与单文件角色模板没有显式格式版本；snapshot 当前 `SchemaVersion == 2`。
- `ChatViewModel.SendAsync` 会执行 `InputText.Trim()`，会破坏子代理 Mention 的原始起始位置。
- 角色列表插入 Mention 时总是追加到输入末尾，无法保证子代理 Mention 位于索引 0。

## 4. 目标行为摘要

### 4.1 角色四个正交维度

```text
ParticipationMode : 普通参与者何时进入默认队列
ExecutionKind     : Standard 或 Coding 引擎
IsManagerRole     : 普通自动循环中的管理者身份
InvocationMode    : Participant 或 SubAgent 的触发语义
```

只修改 `InvocationMode`：

- legacy 保留原角色实例、执行器和当前资源。
- Domain 不递增 `RuntimeVersion`，不替换 runtime，不删除 checkpoint，不重置消费水位。

### 4.2 调度规则

| 来源消息 | 目标模式 | Mention 位置 | 结果 |
|---|---|---|---|
| 非 preset | Participant | 任意有效位置 | 保持现有 Mention 调度 |
| 非 preset | SubAgent | `StartIndex == 0` | 调度目标角色 |
| 非 preset | SubAgent | 非消息开头 | 只保留解析结果，不调度 |
| preset | 任意 | 任意位置 | 不参与 Mention 调度 |

默认参与队列和管理者兜底都必须排除 `SubAgent`。

### 4.3 调用与输出

- Mention 路径和 AITool 路径最终都复用普通角色执行能力。
- 子代理只接收本次任务文本，不读取聊天室历史、调用者会话或旧子代理调用会话。
- 同一次 Standard 子代理调用中的首次运行和一次协议提醒共享同一个新会话。
- Standard 子代理必须通过 `ReturnOutputToCaller` 提交非空结果；第一次未提交时提醒一次，第二次仍未提交则失败。
- Coding 子代理不注入返回工具，使用既有 Coding 完成文本作为等价结果。
- 子代理的真实模型输出仍作为普通 Assistant 消息显示和持久化，并设置 `IsPresetInfo = true`。
- 父 Standard AI 的 AITool 得到正式结果后在原模型轮次继续推理。

## 5. 关键架构校正

### 5.1 legacy 会话不能只靠改写 `SelectedSession`

父 Standard 角色通过工具同步调用子代理时，子代理可能再次调用其他子代理，甚至调用自身。若简单在共享 `CopilotChatManager` 上执行 `CreateNewSession()` 并永久改变 `SelectedSession`，返回父模型后其 checkpoint、消息和后续工具调用可能落到错误会话。

实施必须先建立通用的“指定调用会话”接缝，使一次执行捕获固定的 `CopilotChatSession`，同次协议提醒继续使用该会话，执行结束后不依赖全局当前选择来完成父调用。具体方案见 [04-Legacy执行与调用会话隔离计划](04-Legacy执行与调用会话隔离计划.md)。

### 5.2 Coordinator 不能重入顶层 `StartRoleExecutionCommand`

Coordinator 当前活动父执行期间会拒绝第二个顶层 execution。AITool 同步调用不能直接复用公开 `StartRoleExecutionCommand`，否则父执行会死等或立即失败。

一致性轨道采用以下边界：

- `CurrentExecution` 仍只描述顶层房间执行。
- runtime 通过内部、通用的“执行角色调用并等待结果”接缝请求目标角色。
- 目标角色调用不发布第二个顶层 execution 状态，不引入可持久化 execution stack。
- 目标公开消息、消费水位和 checkpoint 的最终提交仍回到 Coordinator 单写者命令循环完成。
- 停止和关闭继续取消顶层 token；嵌套调用沿用该 token，不增加独立父子取消树。

具体方案见 [05-Coordinator与Runtime一致性计划](05-Coordinator与Runtime一致性计划.md)。

### 5.3 Coordinator runtime 保持隔离创建模型

当前 `IsolatedChatRoomRoleRuntime` 每次执行创建隔离的 legacy `ChatRoomRole`。实施不应为了逐字模拟 legacy 的“长期角色对象”而把 UI 型角色对象长期放入 runtime。

- Participant：继续从 committed checkpoint 恢复。
- SubAgent：不向本次调用传入旧 committed checkpoint，天然获得新 `CopilotChatSession` / `AgentSession`。
- 两者都可在成功后生成 candidate checkpoint。

这既满足调用间无记忆，也保持当前目标架构的资源所有权边界。

## 7. 推荐实施批次

### 批次 A：数据语义

目标：让两套模型可以无歧义表达角色调用模式、preset 消息和结构化 Mention。

包含：

- `ChatRoomRoleInvocationMode`。
- legacy/Domain `ChatRoomMention`。
- legacy/Domain `ChatRoomMessage.IsPresetInfo` 与 `Mentions`。
- 统一解析器输入与输出。
- 深复制、构造校验和源生成上下文准备。

门禁：模型和 Mention 单元测试全部通过；生产调度尚未切换时也必须可编译。

### 批次 B：legacy 调度

目标：先让生产自动循环正确识别 SubAgent，但暂不开放 Standard AITool。

包含：

- Human/Assistant 开头 Mention 规则。
- 默认队列和管理者兜底排除 SubAgent。
- preset 消息不触发 Mention。
- 普通角色增量输入跳过 preset。
- 子代理任务文本提取。

门禁：现有 MentionOnly、管理者和链式 Mention 回归全部通过；新增调度场景通过。

### 批次 C：AgentLib 通用工具接缝

目标：只增加通用、与 ChatRoom 解耦的默认工具过滤能力。

包含：

- `SendMessageRequest.ExcludedDefaultToolNames` 或等价只读集合。
- `ResolveTools` 按名称过滤默认工具。
- 额外工具与默认工具合并后的函数名重复校验。
- net6.0 与 net10.0 AgentLib 测试。

门禁：不修改 `SubAgentToolProvider`；AgentLib 默认工具行为和 `AppendDefaultTools=false` 回归通过。

### 批次 D：legacy 子代理执行

目标：打通生产中的 Mention 和 AITool 两条完整调用链。

包含：

- 通用 Step/execution 选项。
- 固定调用会话。
- `ChatRoomSubAgentToolProvider`。
- `ReturnOutputToCaller` collector 与一次提醒。
- Standard 工具注入；Coding 完成结果复用。
- preset 输出传播到外层和底层消息。
- 会话保存与下一次调用不恢复。

门禁：两次调用隔离、一次提醒、AI 工具继续父回复、Coding 不被修改等场景通过。

### 批次 E：Coordinator/Runtime 一致性

目标：在不接入 UI 的前提下，让目标架构具备相同业务语义。

包含：

- Domain 调用模式和消息语义传播。
- 可见输入与消费水位解耦。
- 通用调用请求与 runtime host 接缝。
- 顶层 execution 内的同步目标角色调用。
- 子调用结果经命令循环原子提交。
- SubAgent 忽略旧 checkpoint、成功后可提交新 checkpoint。

门禁：Coordinator 单写者、顶层单 execution、stale 校验和 runtime lease 原有测试继续通过；新增嵌套调用测试无死锁。

### 批次 F：持久化切换

目标：在模型与行为稳定后一次性切换所有格式版本。

包含：

- legacy 会话 `FormatVersion`。
- 角色模板 `FormatVersion`。
- snapshot schema 提升。
- 新字段和 Mention 数组往返。
- 缺失/旧/未来版本拒绝。
- legacy 恢复时 preset 传播到底层 `CopilotChatMessage`。

门禁：三套格式的正向往返和拒绝测试通过后，才允许继续 UI。

### 批次 G：Avalonia

目标：让用户可配置、辨认和正确触发子代理，不改变消息模板。

包含：

- 角色调用方式编辑。
- 角色卡类型标签。
- 子代理隐藏压缩与清空记忆菜单。
- 子代理 Mention 插到输入开头。
- 发送时保留前导空白。
- 模板大厅传播调用模式。

门禁：Shell ViewModel 测试通过；无需新增子代理消息模板或卡片。

### 批次 H：收尾验收

目标：完成全量测试、README 和变更审查。

包含：

- 分层测试矩阵。
- 基线失败区分。
- README 使用说明。
- Git diff 检查禁止修改范围。
- 完整构建。

## 8. 阶段通用门禁

每个批次必须满足：

1. 先添加或更新对应测试，再删除旧断言或字段。
2. 不得把 RoleId-only Mention 和结构化 Mention 长期双写；过渡仅限同一提交内编译迁移。
3. 不得以 `Trim()`、默认 enum 值或 JSON 缺省值掩盖输入/格式错误。
4. 不得因 `InvocationMode` 改变 `ExecutionKind`、`ParticipationMode` 或 `IsManagerRole`。
5. 不得通过关闭所有 AgentLib 默认工具来绕过 `InvokeSubAgent` 冲突。
6. 不得把普通文本当作 Standard 子代理的隐式正式结果。
7. 不得为子代理新增特殊消息 kind、UI 卡片或父消息内嵌 `CopilotChatSubAgentItem`。
8. 不得在 Coordinator 命令循环内同步等待会回投同一命令循环的任务。
9. 所有新增异步 MSTest 使用硬超时；核心和 Shell 新测试使用中文 `DisplayName`。
10. 每个批次结束运行目标项目测试和解决方案构建。

## 10. 完成定义

全部满足后才视为功能完成：

- 生产 legacy 链路可通过开头 Mention 和 Standard AITool 调用 SubAgent。
- legacy 与 Domain/Coordinator 对角色、Mention、preset 和 checkpoint 语义一致。
- Standard 返回协议、一次提醒和失败路径明确。
- 每次子代理调用使用新会话，同次提醒复用该会话，后续调用不恢复旧状态。
- 子代理输出正常显示和持久化，但不会进入其他角色上下文或 Mention 调度。
- 三套持久化格式仅接受当前版本。
- UI 可编辑和正确插入子代理 Mention，消息模板无分叉。
- 禁止修改文件无差异。
- 相关新增测试和既有回归通过；仅保留已记录、与本功能无关的基线失败。
