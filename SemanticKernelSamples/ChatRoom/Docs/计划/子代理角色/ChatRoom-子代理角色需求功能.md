# ChatRoom 子代理角色需求功能

## 1. 文档目的

本文档只定义 ChatRoom 子代理角色需要实现的产品行为和审核边界，供人类确认需求是否正确、实现路径是否偏离。

具体实现路线见[实施总览与阶段路线](计划/00-实施总览与阶段路线.md)。本文档不规定具体数据模型、类型名称或代码改造方式。

## 2. 背景

当前聊天室可以区分人类与非人类角色、自动参与与仅 mention 参与、管理者身份，以及 Standard 与 Coding 执行引擎，但仍缺少“子代理”这一触发语义。

子代理仍然是普通的 `ChatRoomRole`：继续使用现有角色配置、执行引擎、`AgentSession`、checkpoint、`StepAsync` 和公开消息展示链路。它与普通角色的主要差别只在于触发时机，以及其输出是否进入其他角色的后续上下文。

## 3. 核心需求

1. 角色可以被定义为普通聊天室参与者或子代理。
2. 子代理不能进入普通自动发言队列。
3. 继续使用现有 Mention 语法和解析流程，不为子代理新建独立解析协议。
4. Mention 解析结果需要保留来源消息、匹配位置以及是否位于消息开头等结构化信息。
5. 用户消息只有在针对子代理的 Mention 位于消息索引 0 时，调度器才把它当作对子代理的直接调用。
6. 用户消息中段的 `@子代理角色名` 仍可被解析和显示，但不能触发子代理。
7. 非人类角色消息中的普通 `@子代理角色名` 不能触发子代理；Standard 角色通过聊天室专用 `InvokeChatRoomSubAgent` AITool 调用子代理。
8. 子代理继续通过现有 `StepAsync` 和普通角色执行链路运行，不增加独立 invoker、临时角色或临时会话。
9. 子代理继续使用并保存自己的 `AgentSession`、checkpoint 和角色运行状态，按现有角色机制延续上下文。
10. Standard 子代理被触发后必须通过 `ReturnOutputToCaller` 提交正式结果；普通文本不代替完成结果。第一次未提交时提醒并重试一次，第二次仍未提交则明确失败。子代理每次模型运行的原始输出都按普通角色消息显示，但工具返回值不额外生成结果气泡。
11. AI 调用 Standard 子代理时，`ReturnOutputToCaller` 的值作为 AITool 返回值交还父 AI；调用 Coding 子代理时使用现有 Coding/AgentLib 完成结果。父 AI 获得结果后继续完成自己的回复。
12. 子代理执行期间产生的角色消息与普通角色消息一样进入聊天室并使用相同 UI 模板展示，但设置 `IsPresetInfo = true`。
13. 普通角色构建后续上下文时必须跳过 `IsPresetInfo = true` 的子代理消息；父 AI 已获得的工具结果不受该过滤影响。
14. 不对子代理增加 `IsHuman`、`ParticipationMode`、`IsManagerRole`、执行引擎组合、嵌套深度或调用环路等额外硬约束。
15. 本轮只改 Standard 执行引擎的通用工具接缝；Coding 子代理继续使用现有 Coding/AgentLib 完成结果，并将该结果视为等价提交，不注入 `ReturnOutputToCaller`，也不修改 `AgentLib.Coding`。
16. ChatRoom 只维护当前 `ChatRoomManager` 实现；角色定义、Mention 信息、自动调度、上下文过滤和持久化都以这套实现为唯一事实来源。
17. 当前产品尚未发布，持久化结构可直接调整为新格式，不实现旧角色、旧模板或旧消息的兼容迁移；会话配置和角色模板都使用显式格式版本，缺失或旧版本数据直接拒绝。

## 4. Mention 触发规则

假设存在名为“代码审查子代理”的子代理角色。

| 输入 | 是否触发子代理 | 原因 |
|------|----------------|------|
| `@代码审查子代理 检查当前改动` | 是 | Mention 位于消息索引 0 |
| `Xxxx。@代码审查子代理 检查当前改动` | 否 | 不在消息开头 |
| `Xxxx。 @代码审查子代理 检查当前改动` | 否 | 不在消息开头 |
| ` @代码审查子代理 检查当前改动` | 否 | 存在前导空白 |
| `@代码审查子代理\t检查当前改动` | 按现有 Mention 规则 | 不额外收紧空白字符语法 |
| `@[代码审查子代理] 检查当前改动` | 按现有 Mention 规则 | 不为子代理移除现有方括号语法 |
| `@普通助手 检查当前改动` | 否 | 目标不是子代理，继续按普通角色规则调度 |

解析器只负责识别 Mention 并返回结构化位置；是否触发子代理由调度器结合来源消息发送者、目标角色的调用模式和 `IsAtMessageStart` 判断。

## 5. 上下文与可见性

### 5.1 用户直接调用

- 用户输入继续作为现有的人类聊天室消息显示和持久化。
- 调度器从该消息的结构化 Mention 中识别位于开头的子代理目标，并通过现有 `StepAsync` 执行角色。
- 子代理回复使用普通角色消息的同一套流式展示、模型信息和持久化机制。
- 子代理回复设置 `IsPresetInfo = true`，不进入其他普通角色的后续模型输入，也不再次触发 Mention 调度。

### 5.2 AI 角色调用

- Standard 角色通过聊天室自己的 `InvokeChatRoomSubAgent` AITool 发起调用，不使用或修改 `AgentLib.Tools.SubAgentToolProvider`。
- 工具在现有角色执行机制中调用目标角色，不创建第二套子代理运行时。
- 子代理的普通角色消息会显示在聊天室中，并设置 `IsPresetInfo = true`。
- Standard 子代理由 `ReturnOutputToCaller` 提交正式结果；Coding 子代理使用现有 Coding/AgentLib 完成结果。两者都作为工具结果返回当前调用者。
- 其他角色可以在 UI 中看到子代理消息，但构建模型上下文时会跳过该消息。

### 5.3 子代理执行

- 子代理是正常角色，继续复用自身现有的 `CopilotChatManager`、`AgentSession` 和 checkpoint。
- 用户 Mention 调用时，按现有增量消息机制获得当前上下文。
- AI 工具调用时，在现有增量上下文基础上加入调用任务，不清空旧会话。
- Standard 子代理的正式完成结果必须由 `ReturnOutputToCaller` 提交；未提交时不能使用最后一段普通文本代替。
- 用户 Mention 调用也要求提交该结果；UI 显示每次模型运行本身的普通角色输出，不再根据返回值创建额外结果消息。
- Coding 子代理沿用当前 Coding/AgentLib 的结果机制，该结果视为等价完成，不注入或检查 `ReturnOutputToCaller`。
- 提醒重试仍属于同一次逻辑调用，不为 UI 额外创建一条“结果消息”或专用调用卡片。

## 6. 非目标

本轮不包含以下能力：

- 让子代理自动参与聊天室讨论。
- 通过角色名称、提示词、模板名称或工具集合推断子代理身份。
- 规定子代理身份必须合并到现有参与模式或执行引擎。
- 为子代理创建独立调用入口、独立 runtime、临时 `AgentSession` 或专用 UI 消息类型。
- 修改 `AgentLib.Tools.SubAgentToolProvider` 或复用其实现。
- 修改 Coding 执行引擎、`AgentLib.Coding` 接口或其内部子代理机制。
- 增加自调用、调用环路、最大嵌套深度等专用限制。
- 兼容迁移当前开发阶段产生的旧持久化数据。

## 7. 验收检查表

- [ ] 普通自动调度不会执行子代理。
- [ ] 消息中段的普通 `@子代理名` 不会执行子代理。
- [ ] Mention 解析结果包含来源消息、匹配位置和是否位于消息开头。
- [ ] 位于开头的用户 Mention 能通过现有 `StepAsync` 调用目标子代理。
- [ ] AI 普通文本中的 `@子代理名` 不会触发子代理。
- [ ] Standard AI 可以通过聊天室专用 AITool 调用子代理。
- [ ] 子代理继续复用并保存现有角色会话和 checkpoint。
- [ ] Standard 子代理未通过返回工具提交时，工具调用在一次提醒后明确失败。
- [ ] 子代理消息使用普通角色 UI 展示，并设置 `IsPresetInfo = true`。
- [ ] 子代理消息可见、可持久化，但不会进入其他普通角色的后续上下文或 Mention 调度。
- [ ] AI 调用时，Standard 返回工具值或 Coding 现有完成结果会交还父 AI，父 AI 可以继续完成回复。
- [ ] Coding 执行链路保持不变，其现有结果被视为等价完成。
- [ ] 项目只保留一套聊天室实现，不存在平行的角色模型、调度器或持久化链路。
- [ ] 持久化只覆盖当前新结构，不包含旧格式迁移分支；缺失或旧格式版本会被明确拒绝。

## 8. 已知实现约束

- `MentionParser` 当前只返回 RoleId，需要扩展为包含来源与位置的结构化结果，但不改变现有 Mention 语法。
- `StepAsync` 已经负责角色流式消息、会话保存和 UI 展示，子代理应复用该链路。
- Standard 执行器可以接收本轮附加 `AITool`。发送请求增加通用的“按函数名排除默认工具”能力；ChatRoom Standard 只排除 AgentLib 默认 `InvokeSubAgent`，保留其他默认工具，并追加聊天室工具和按需返回工具。
- Coding 执行器走独立接口且当前不消费 Standard 的附加工具，本轮不修改；其现有完成结果直接作为 Coding 子代理调用结果。
- `IsPresetInfo` 当前不能单独完成聊天室上下文隔离；实现必须在上下文构造、Mention 调度和持久化中传播并执行过滤。
- AgentLib 中现有 `SubAgentToolProvider` 与本需求无关，保持不动；ChatRoom 新增独立命名的 `ChatRoomSubAgentToolProvider`。
