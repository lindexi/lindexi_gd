# CodingChatRoom 多工作任务并行改造设计

## 1. 设计边界

本文只描述实现权威需求所需的设计。未列入本文的旧设计建议永久废止，不作为预留方向。

设计原则：

- 一个桌面进程管理多个相互独立的工作任务；
- 每个任务拥有自己的运行时对象，不通过共享可变状态模拟隔离；
- 持久化只保存任务 ID、名称、工作目录、模型和思考强度；
- 恢复历史会话时同步目标任务工作路径；
- 正确的现有逻辑不修改；
- 不增加跨进程协调、通用宿主层、会话注册表、复杂状态机或未被当前需求使用的抽象。

## 2. 当前结构

项目使用 .NET 10、Avalonia 12.1.0、编译绑定和 MSTest。

当前多任务组合关系为：

`App` → 每任务一个 `CodingChatRuntime` → 独立的 `AgentApiEndpointManager`、`CopilotChatManager`、`CodingAgent`、`CodingAgentChatRunner`、`CodingChatApplication`、`CodingWorkspaceController`、`ChatViewModel` 和 `SessionListViewModel`。

`MainViewModel` 管理任务集合并将活跃任务的聊天和历史对象投影给界面。任务切换不得销毁后台任务。

实施前必须以当前源码为准核查该关系，不能依据旧文档假定已经正确或错误。

## 3. WorkTasks.json

文件位置：`CodingChatRoomPaths.RootDirectory/WorkTasks.json`。

根对象包含任务记录集合。每条记录包含：

| 字段 | 含义 |
| --- | --- |
| `Id` | 稳定任务 ID |
| `DisplayName` | 任务名称，与会话标题独立 |
| `WorkspacePath` | 已应用工作目录，可空 |
| `ModelReference` | 从当前 Runtime 的可用模型中重新定位模型的信息 |
| `ReasoningEffort` | 思考强度，可空 |

不添加版本迁移框架、任务排序字段、活跃任务字段、当前会话字段、运行选项字段、草稿字段、附件字段或运行状态字段。

模型引用应直接复用现有 `LanguageModelOptionViewModel` 和底层模型定义中足以稳定匹配的信息。不得保存显示对象、客户端实例或密钥。

## 4. 存储职责

增加一个职责单一的任务元数据存储类型：

- `LoadAsync`：文件不存在时返回空集合；存在时反序列化记录；
- `SaveAsync`：将当前任务记录写入 `WorkTasks.json`；
- 使用项目现有 JSON 约定和异步文件 API；
- 只支持应用内正常交互，不增加跨进程锁；
- I/O 异常不得吞掉，应由调用层转为可读错误。

不为存储增加接口，除非现有测试确实需要替换外部文件依赖且没有更直接的测试方式。

## 5. 启动恢复

启动流程：

1. 创建应用路径并读取任务记录；
2. 没有记录时，按现有流程创建默认任务；
3. 有记录时，为每条记录创建独立 `CodingChatRuntime`；
4. 使用记录中的 ID 和名称创建任务项；
5. 将工作目录应用到该任务的 `CodingWorkspaceController`；
6. 在该 Runtime 的可用模型中匹配并选择模型；
7. 在思考强度选项中匹配并选择强度；
8. 恢复完成后显示任务列表，不发送消息、不运行模型、不启动工具调用。

模型或思考强度无法匹配时沿用该 Runtime 的现有默认值，并通过已有错误展示机制给出可读信息；不得增加新的模型注册体系。

任务新增、重命名、工作目录应用、模型变化、思考强度变化和任务删除后保存当前任务集合。保存失败时界面必须可见，且删除失败不得先从集合移除任务。

## 6. 历史恢复路径同步

`CodingChatApplication.OpenSessionAsync` 成功选择或加载历史会话后，将 `targetSession.WorkspacePath` 同步到本任务的 `CodingWorkspaceController`。

同步应属于打开会话成功提交的一部分：

- 成功后会话与工作路径一致；
- 加载或路径应用失败时保留原会话和原工作路径；
- 不改变任务模型和思考强度；
- 不增加跨任务会话挂载协调。

工作路径规范化和校验复用 `CodingWorkspaceController` 的现有方法。

## 7. 生命周期与独立性核查

核查现有实现是否满足：

- 每个任务拥有完全独立的 Runtime 及可变依赖；
- Stop 只取消本任务执行，并阻止本任务循环继续；
- 压缩、等待和最终保存处于任务完整工作周期内；
- 运行任务不能在未完成收尾时被删除；
- 窗口退出释放全部任务 Runtime；
- 删除任务先完成可能失败的释放，再从集合删除；
- `ChatViewModel`、`SessionListViewModel` 和 `WorkTaskItemViewModel` 的事件订阅可解除；
- 异步命令异常通过现有错误状态显示。

只修复核查中确认存在的真实问题，不增加与当前控制流无关的兜底逻辑。

## 8. 设置与并行核查

每个任务的模型选择是任务状态，不得修改其他任务。全局设置通过现有设置存储传播到已有任务和新任务时，必须按当前产品语义测试。

并行验证必须证明：

- A、B 的执行链同时处于活动状态；
- 输出、工具结果和错误写回各自 ChatManager 和会话；
- 停止 A 后 B 继续运行；
- 两个 Runtime 的模型客户端、会话文件、沙盒工具和 LSP 工作区资源不会因共享可变实例而串扰。

若外部环境无法完成某项实机验证，应明确记录未验证，不以静态检查替代。

## 9. 界面核查

保留当前 Windows 11 Fluent 浅色布局、原生标题栏、Mica 请求和不支持时的浅色不透明回退。

验收长任务名、长路径、原位重命名、按钮最小宽度布局、对齐、交互状态、焦点、图标继承、Danger 配色隔离、设置页密度和单层分区。已有行为正确时不修改样式。

禁止重新查看视觉设计稿，禁止恢复已经删除的标题栏或深色侧栏。

## 10. 永久禁止扩展

不得实现或预留：

- 全局历史目录重构；
- 会话挂载注册表或同一会话写入协调；
- 任务顺序、活跃任务、当前会话或运行选项持久化；
- 草稿、附件、运行状态或中断状态持久化；
- 多进程文件协调；
- 自动续跑、自动 worktree、多 Agent 调度、多窗口或远程管理；
- 为这些事项添加接口、字段、服务或兼容分支。
